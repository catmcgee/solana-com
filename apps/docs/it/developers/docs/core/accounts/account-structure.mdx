<Info>
  **Riepilogo**

  Gli account hanno 5 campi: lamport, data, owner, executable e rent_epoch. Ogni
  account è identificato da un indirizzo univoco di 32 byte. Gli account devono
  mantenere un saldo minimo di lamport proporzionale alla dimensione dei loro
  dati per rimanere on-chain.
</Info>

## Indirizzo dell'account

Ogni indirizzo di account è un valore di 32 byte, visualizzato come stringa
codificata in base58. Un indirizzo può essere di due tipi:

1. **Chiave pubblica**: corrisponde a una [Ed25519](https://ed25519.cr.yp.to/)
   keypair (ha una chiave privata)
2. **Program derived address (PDA)**: derivato deterministicamente da un ID
   programma e seed (nessuna chiave privata)

### Chiave pubblica

Una `Keypair` consiste in una chiave pubblica (usata come indirizzo
dell'account) e una chiave privata (usata per firmare le transazioni). L'esempio
seguente genera una keypair usando l'SDK Solana.

<CodeGroup>

```ts Kit
import { generateKeyPairSigner } from "@solana/kit";

// Kit does not enable extractable private keys
const keypairSigner = await generateKeyPairSigner();
console.log(keypairSigner);
```

```ts Legacy
import { Keypair } from "@solana/web3.js";

const keypair = Keypair.generate();
console.log(`Public Key: ${keypair.publicKey}`);
console.log(`Secret Key: ${keypair.secretKey}`);
```

```rs Rust
use solana_sdk::signer::{keypair::Keypair, Signer};

#[tokio::main]
async fn main() {
    let keypair = Keypair::new();
    println!("Public Key: {}", keypair.pubkey());
    println!("Secret Key: {:?}", keypair.to_bytes());
}
```

</CodeGroup>

### Program derived address

Un [program derived address](/developers/docs/core/pda) (PDA) è derivato
deterministicamente da un ID programma e uno o più seed opzionali. I PDA non
hanno una chiave privata corrispondente. L'esempio seguente deriva un PDA usando
l'SDK Solana.

<CodeGroup>

```ts Kit
import { Address, getProgramDerivedAddress } from "@solana/kit";

const programAddress = "11111111111111111111111111111111" as Address;

const seeds = ["helloWorld"];
const [pda, bump] = await getProgramDerivedAddress({
  programAddress,
  seeds
});

console.log(`PDA: ${pda}`);
console.log(`Bump: ${bump}`);
```

```ts Legacy
import { PublicKey } from "@solana/web3.js";

const programAddress = new PublicKey("11111111111111111111111111111111");

const seeds = [Buffer.from("helloWorld")];
const [pda, bump] = await PublicKey.findProgramAddressSync(
  seeds,
  programAddress
);

console.log(`PDA: ${pda}`);
console.log(`Bump: ${bump}`);
```

```rs Rust
use solana_sdk::pubkey; // macro
use solana_sdk::pubkey::Pubkey;

#[tokio::main]
async fn main() {
    let program_address = pubkey!("11111111111111111111111111111111");
    let seeds = [b"helloWorld".as_ref()];
    let (pda, bump) = Pubkey::find_program_address(&seeds, &program_address);
    println!("PDA: {}", pda);
    println!("Bump: {}", bump);
}
```

</CodeGroup>

## Campi dell'account

Ogni
[`Account`](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/account/src/lib.rs#L32-L56)
ha una dimensione massima di
[`MAX_ACCOUNT_DATA_LEN`](https://github.com/anza-xyz/agave/blob/v3.1.8/transaction-context/src/lib.rs#L34)
(10 MiB, equivalente a `MAX_PERMITTED_DATA_LENGTH`) e contiene cinque campi:

| Campo        | Tipo      | Descrizione                                                                                |
| ------------ | --------- | ------------------------------------------------------------------------------------------ |
| `lamports`   | `u64`     | Saldo in lamport. Il proprietario può addebitare; qualsiasi programma può accreditare.     |
| `data`       | `Vec<u8>` | Stato dell'account o bytecode del programma. Max 10 MiB. Scrivibile solo dal proprietario. |
| `owner`      | `Pubkey`  | Programma con accesso in scrittura. Riassegnabile solo quando i dati sono azzerati.        |
| `executable` | `bool`    | True = program account.                                                                    |
| `rent_epoch` | `Epoch`   | Deprecato. Impostato su `u64::MAX` per gli account esenti da rent.                         |

```rust Account
pub struct Account {
    /// lamports in the account
    pub lamports: u64,
    /// data held in this account
    #[cfg_attr(feature = "serde", serde(with = "serde_bytes"))]
    pub data: Vec<u8>,
    /// the program that owns this account. If executable, the program that loads this account.
    pub owner: Pubkey,
    /// if true, this account's data contains a program (and is now read-only)
    pub executable: bool,
    /// deprecated
    pub rent_epoch: Epoch,
}
```

<Steps>
  <Step title="Lamport">
    Il campo `lamports` contiene il saldo dell'account in
    [lamport](/developers/docs/references/terminology#lamport) (1 SOL = 1.000.000.000 lamport).

    Ogni account deve mantenere un saldo minimo in lamport per conservare i propri dati onchain. Questo saldo di archiviazione rimborsabile è proporzionale alla dimensione dei dati dell'account.

    <Info>
      Il runtime e i nomi dei metodi RPC chiamano questo valore "rent-exempt minimum", ma la raccolta continuativa del rent è disabilitata. Considera il saldo come un deposito rimborsabile per l'archiviazione dell'account: l'intero saldo può essere recuperato quando l'account viene chiuso.
    </Info>

    Vedi
    [`minimum_balance()`](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/rent/src/lib.rs#L93)
    e le
    [costanti](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/rent/src/lib.rs#L47-L80)
    di rent.

    ```rust title="Account Examples" focus={3,13}
    // Example Token Mint Account
    Account {
        lamports: 1461600,
        data.len: 82,
        owner: TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb,
        executable: false,
        rent_epoch: 0,
        data: 010000001e213c90625a7e643d9555bb01b6c3fe6416d7afd523ce8c7ddd9b923ceafb9d00000000000000000901010000001e213c90625a7e643d9555bb01b6,
    }

    // Example Token Program Account
    Account {
        lamports: 4513200894,
        data.len: 134080,
        owner: BPFLoader2111111111111111111111111111111111,
        executable: true,
        rent_epoch: 18446744073709551615,
        data: 7f454c460201010000000000000000000300f70001000000d8f90000000000004000000000000000800902000000000000000000400038000400400009000800,
    }
    ```
  </Step>

  <Step title="Data">
    Il campo `data` memorizza un array di byte arbitrario. Il suo contenuto dipende
    dal tipo di account:

    - **Program account**: Contiene bytecode eseguibile o l'indirizzo di un
      [program data account](/developers/docs/core/accounts/account-types#program-data-accounts)
      che memorizza il bytecode.
    - **Data account**: Contiene dati di stato definiti dal programma. Il programma
      proprietario definisce il formato di serializzazione.

    La lettura dei dati dell'account richiede due passaggi:

    1. Recuperare l'account tramite il suo [indirizzo](#indirizzo-dell’account).
    2. Deserializzare il campo `data` da byte grezzi nella struttura dati definita
       dal programma.

    ```rust title="Account Examples" focus={4,8,14,18}
    // Example Token Mint Account
    Account {
        lamports: 1461600,
        data.len: 82,
        owner: TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb,
        executable: false,
        rent_epoch: 0,
        data: 010000001e213c90625a7e643d9555bb01b6c3fe6416d7afd523ce8c7ddd9b923ceafb9d00000000000000000901010000001e213c90625a7e643d9555bb01b6,
    }

    // Example Token Program Account
    Account {
        lamports: 4513200894,
        data.len: 134080,
        owner: BPFLoader2111111111111111111111111111111111,
        executable: true,
        rent_epoch: 18446744073709551615,
        data: 7f454c460201010000000000000000000300f70001000000d8f90000000000004000000000000000800902000000000000000000400038000400400009000800,
    }
    ```
  </Step>

  <Step title="Proprietario">
    Il campo `owner` contiene l'ID del programma (chiave pubblica) del programma che
    possiede questo account.

    Il programma proprietario è l'unico programma che può:

    - Modificare il campo `data` dell'account
    - Dedurre lamport dal campo `lamports` dell'account

    Qualsiasi programma può aggiungere lamport a un altro account, ma solo il
    proprietario può dedurre lamport da esso.

    Per i program account, il proprietario è il
    [programma loader](/developers/docs/core/programs/builtin-programs#loader-programs)
    dell'account.

    ```rust title="Account Examples" focus={5,15}
    // Example Token Mint Account
    Account {
        lamports: 1461600,
        data.len: 82,
        owner: TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb,
        executable: false,
        rent_epoch: 0,
        data: 010000001e213c90625a7e643d9555bb01b6c3fe6416d7afd523ce8c7ddd9b923ceafb9d00000000000000000901010000001e213c90625a7e643d9555bb01b6,
    }

    // Example Token Program Account

        lamports: 4513200894,

        rent_epoch: 18446744073709551615,
        data: 7f454c460201010000000000000000000300f70001000000d8f90000000000004000000000000000800902000000000000000000400038000400400009000800,
    }
    ```
  </Step>

  <Step title="Eseguibile">

  <Step title="Epoch di rent">
    **Il campo `rent_epoch` è deprecato.**

    In precedenza veniva tracciato quando un account avrebbe avuto automaticamente dei lamport detratti per il mantenimento dei propri dati onchain. Poiché la raccolta continuativa del rent è disabilitata, `rent_epoch` è impostato su `u64::MAX` per tutti i nuovi account che soddisfano il saldo minimo di archiviazione.

    ```rust title="Account Examples" focus={7,17}

    Account {
    ```
