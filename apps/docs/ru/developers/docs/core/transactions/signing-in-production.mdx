Транзакция выполняется только при наличии действительной
[подписи](/developers/docs/core/transactions/transaction-structure#signatures) от каждого
обязательного подписанта. В процессе локальной разработки вы обычно храните ключ как
[`Keypair`](/developers/cookbook/wallets/create-keypair) и подписываете напрямую. В
продакшене вопрос стоит иначе: **где хранится приватный ключ
и кто вправе авторизовать подпись с его помощью?**

<Warning>
  Никогда не встраивайте приватные ключи в клиентский код, не включайте их во фронтенд-сборку и
  не фиксируйте в системе контроля версий. Любой, кто получит ключ, получит полный контроль над
  средствами этого аккаунта.
</Warning>

## Подходы к подписанию

| Подход                  | Где хранится ключ                                     | Кто подписывает                                          | Лучше всего подходит для                                                      |
| ------------------------- | ------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------- |
| **Локальный keypair**         | Файл или переменная окружения на машине           | Ваш код, напрямую                                | Локальная разработка, тесты, CI                                  |
| **Браузерный кошелёк**        | Кошелёк конечного пользователя (например, Phantom, Solflare)          | Конечный пользователь, для каждой транзакции                      | Фронтенд-dApps, где пользователи сами подписывают транзакции        |
| **Облачный KMS / HSM**       | Аппаратно защищённый сервис управления ключами (AWS KMS, GCP KMS, Vault) | Ваш бэкенд запрашивает подпись у сервиса | Бэкенд-сервисы, операции с казначейством, регулируемые среды |
| **Управляемые / MPC-кошельки** | Распределены или переданы на хранение в инфраструктуру провайдера   | Провайдер совместно подписывает в соответствии с вашей политикой     | Встроенные кошельки, процессы согласования, институциональное хранение   |

Локальный keypair — единственный подход, при котором необработанный ключевой материал находится внутри
вашего приложения. В каждом продакшен-подходе ключ хранится в специализированной инфраструктуре,
которая подписывает от вашего имени.

## Подписание на бэкенде

Когда серверу необходимо подписывать транзакции — для оплаты комиссий, отправки программных транзакций или
управления казначейством — используйте специализированный бэкенд управления ключами вместо обычного
keypair. Фонд Solana поддерживает [Keychain](/developers/docs/tools/keychain) —
унифицированную библиотеку подписания (Rust и TypeScript), предоставляющую единый интерфейс `SolanaSigner`
для всех бэкендов из таблицы выше: Memory, HashiCorp Vault, AWS
KMS, GCP KMS, Fireblocks, Privy, Turnkey, CDP, Crossmint, Dfns, Para, Openfort
и Utila.

Поскольку интерфейс одинаков для всех бэкендов, вы можете вести разработку локально с
ключом в памяти и переключиться на продакшен-бэкенд через конфигурацию,
не переписывая код приложения. Keychain совместим с
[`@solana/kit`](/developers/docs/clients/official/javascript) и
[Rust SDK](/developers/docs/clients/official/rust).
