  "How EVM concepts map onto Solana: accounts vs contract storage, programs vs
  contracts, fees and finality."

Most of what you know from Ethereum carries over, but one idea changes how you
design everything: on Solana, **programs are stateless**. A smart contract on
Ethereum stores its own state. A Solana program keeps its state in separate
<span className="sol-chip" data-concept="account"><Tooltip headline="Accounts" tip="Everything on Solana (balances, tokens, programs, app data) lives in accounts: records at an address, each with an owner that is allowed to change it." cta="Learn more" href="/docs/core/accounts">accounts</Tooltip><span className="nojs-only"> ([Accounts](/docs/core/accounts): Everything on Solana (balances, tokens, programs, app data) lives in accounts: records at an address, each with an owner that is allowed to change it.)</span></span> that it owns,
and every transaction lists the accounts it will read and write up front. That
is what lets the network run transactions that touch different accounts in
parallel.

## Concept map

| On Ethereum                          | On Solana                                                                                                     | Read more                                                         |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| Smart contract                       | Program: stateless code, usually written in Rust, upgradeable by its upgrade authority unless that is removed | [Programs](/docs/core/programs)                                   |
| Contract storage                     | Accounts owned by the program, passed into each instruction                                                   | [Accounts](/docs/core/accounts)                                   |
| `mapping` keys, `CREATE2` addresses  | Program-derived addresses (PDAs): addresses derived from seeds that only the program can sign for             | [PDAs](/docs/core/pda)                                            |
| `call` to another contract           | Cross-program invocation (CPI)                                                                                | [CPI](/docs/core/cpi)                                             |
| EOA and secp256k1 key                | Ed25519 keypair; the address is the base58 public key                                                         | [Wallets & signatures](/docs/core/wallets)                        |
| `msg.sender`                         | The signers listed in the transaction                                                                         | [Transactions](/docs/core/transactions)                           |
| ERC-20 contract per token            | One shared Token program; each token is a mint account, and balances live in token accounts                   | [Tokens](/docs/tokens)                                            |
| ERC-721                              | Metaplex Token Metadata, on top of the Token program                                                          | [Metaplex](/docs/tokens/metaplex)                                 |
| Gas and gas price                    | A base fee per signature, plus an optional priority fee per compute unit                                      | [Fees](/docs/core/fees)                                           |
| ERC-4337 paymasters                  | A separate fee payer is built in: any account can sign as fee payer                                           | [Fee sponsorship](/docs/core/fees/fee-sponsorship)                |
| Storage gas                          | A refundable deposit per account, proportional to its size                                                    | [Rent](/docs/core/rent)                                           |
| Account nonce                        | A recent blockhash that expires after about 60 to 90 seconds, or a durable nonce                              | [Confirmation & finality](/docs/core/transactions/confirmation)   |
| Block confirmations                  | Commitment levels: processed, confirmed, finalized                                                            | [Confirmation & finality](/docs/core/transactions/confirmation)   |
| ethers.js or viem                    | `@solana/kit` for TypeScript; Rust and Python SDKs                                                            | [SDKs](/docs/clients)                                             |
| Hardhat or Foundry                   | Anchor for programs; LiteSVM and Surfpool for testing                                                          | [Write onchain programs](/docs/programs)                          |
| Sepolia                              | Devnet                                                                                                        | [Clusters](/docs/references/clusters)                             |
