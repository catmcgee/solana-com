## What the code does

`createAsset(issuer)` builds one transaction with these instructions, in order:

1. **Create the mint account** (`getCreateAccountInstruction`). It is funded
   for the final size including metadata, but allocated without the metadata,
   which is written after the mint is initialized.
2. **Configure the extensions** that must be set before the mint is initialized
   (`getPreInitializeInstructionsForMintExtensions`).
3. **Initialize the mint** (`getInitializeMintInstruction`) with 6 decimals. The
   issuer is both the mint authority, who can issue more LSF, and the freeze
   authority, who approves and freezes holders.
4. **Write the metadata** (`getPostInitializeInstructionsForMintExtensions`).

Each extension sets one rule:

- `MetadataPointer` and `TokenMetadata`: the name (Lisbon Solar Fund), symbol
  (LSF), a URI for offchain details and an extra `isin` field, stored on the
  mint itself. See [Metadata](/docs/tokens/extensions/metadata).
- `PausableConfig`: the issuer can pause and resume every transfer, mint and
  burn. See [Pausable](/docs/tokens/extensions/pausable).
- `PermanentDelegate`: the issuer can move or burn tokens in any account
  without the holder's signature. See
  [Permanent delegate](/docs/tokens/extensions/permanent-delegate).
- `DefaultAccountState` set to `Frozen`: every new token account starts
  frozen, so nobody can receive LSF until the issuer approves them. See
  [Default account state](/docs/tokens/extensions/default-state).

The `send` helper it imports from `./config` builds, signs, sends and confirms
the transaction. You'll see it in the next step.

**Same mint in web3.js or Rust:** the cookbook recipe
[Create a mint with extensions](/developers/cookbook/tokens/create-mint-with-extensions)
creates a mint with the same five extensions in Kit, legacy web3.js and Rust.
