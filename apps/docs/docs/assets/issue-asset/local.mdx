<Stepper />

This step puts the code from the first two steps into a project of your own.
It has five files: a connection helper, the asset, holder approval, the
transfers that test the rules, and a script that runs them in order. The output under each block is what the same code
printed on a local Surfpool network.

## 1. Create the project and install the packages

You need Node.js 20 or later. The scripts use top-level `await` and
`import.meta.url`, so the project must be an ES module project: set
`"type": "module"` in `package.json`, as the second command does. Without it,
`tsx` runs the files as CommonJS and fails on the first `await`.

The examples are tested with `@solana/kit` 8.4, `@solana-program/token-2022`
0.19 and `@solana-program/system` 0.15. `tsx` runs the TypeScript files
directly.

```bash Terminal
mkdir issue-asset && cd issue-asset
npm init -y && npm pkg set type=module
npm install @solana/kit @solana-program/token-2022 @solana-program/system
npm install --save-dev tsx
```

## 2. Pick a network

The code reads the network from two environment variables and uses devnet when
they are unset.

- **Local:** install the [Surfpool CLI](/docs/tools/surfpool/toolchain/getting-started)
  and run `surfpool start`. Then set `RPC_URL=http://127.0.0.1:8899` and
  `RPC_SUBSCRIPTIONS_URL=ws://127.0.0.1:8900`. This is where the recorded output
  comes from.
- **Devnet:** leave both unset. Fund your issuer wallet (step 7 creates its key
  file) with free devnet SOL from the [Solana Faucet](https://faucet.solana.com/)
  to pay fees and account deposits.

<Rpc />

## 3. Add the connection helper

`send` builds a transaction from a list of instructions, signs it, sends it and
waits until it is confirmed. When a transaction fails it keeps the signature and
the message on the error, so you can look up a failed transaction and decode its
program error.

<Config />

## 4. Create the asset

Save this as `create-asset.ts`. It is the code from the
[previous step](/docs/assets/issue-asset/browser).

<Create />

Creating the mint costs the network fee plus a refundable deposit for the mint
account's storage. The recorded run paid a 10000-lamport fee, one signature for
the issuer and one for the new mint account.

<Rent />

## 5. Approve holders

Save this as `approve-holder.ts`. `openAccount` creates a holder's token
account, which starts frozen. `approveHolder` thaws it with the freeze authority
and, when you pass an amount, mints LSF to it in the same transaction. Amounts
are in base units: with 6 decimals, `1_000_000_000n` is 1000 LSF.

<Approve />

Call `approveHolder` only after your KYC check passes. To approve addresses from
an allowlist automatically instead of one by one, use
[Token ACL](/docs/tokenization/token-acl). To withdraw an approval, freeze the
account again with the freeze authority (see
[Freeze an account](/docs/tokens/basics/freeze-account)).

## 6. Test the rules

Save this as `blocked-transfer.ts`. It holds the transfers and controls from
step 1:

- `transfer` sends LSF between holders with `TransferChecked`.
- `sendToUnapproved` sends to a frozen account with `skipPreflight`, so the
  failed transaction lands and you can read its error, log and fee with
  `failure`.
- `sendToUnapprovedWithPreflight` sends the same transfer normally and decodes
  the rejection with `isToken2022Error(…, TOKEN_2022_ERROR__ACCOUNT_FROZEN)`.
- `pause` and `resume` switch every transfer of the asset off and on.
- `clawBack` uses the permanent delegate to move tokens out of a holder's account
  into the issuer's.

<Blocked />

## 7. Run it

Save this as `run.ts`. It calls the functions above in order: create the asset,
give a new holder a little SOL for fees, approve two investors and the issuer's
own account (so `clawBack` has somewhere to send tokens), then send to an
approved and an unapproved account, pause, try a transfer, resume, and claw
back 50 LSF.

<RunScript />

`run.ts` signs as the issuer with a key file: the path in `ISSUER_KEYPAIR`, or
the Solana CLI default `~/.config/solana/id.json`. If you already have one
(for example from `solana-keygen new`), skip to the run. Otherwise save this as
`keygen.ts`. It writes a new key file in the same format, a JSON array of 64
bytes, and prints the issuer's address:

```ts keygen.ts
import { generateKeyPairSync } from "node:crypto";
import { existsSync, mkdirSync, writeFileSync } from "node:fs";
import { homedir } from "node:os";
import { dirname, join } from "node:path";
import { createKeyPairSignerFromBytes } from "@solana/kit";

// Writes a new key file in the Solana CLI format (64 bytes as a JSON array).
const keyPath =
  process.env.ISSUER_KEYPAIR ?? join(homedir(), ".config", "solana", "id.json");
if (existsSync(keyPath)) throw new Error(`${keyPath} exists; not overwriting it`);
const { privateKey, publicKey } = generateKeyPairSync("ed25519");
const bytes = new Uint8Array([
  ...privateKey.export({ format: "der", type: "pkcs8" }).subarray(-32),
  ...publicKey.export({ format: "der", type: "spki" }).subarray(-32),
]);
mkdirSync(dirname(keyPath), { recursive: true });
writeFileSync(keyPath, JSON.stringify([...bytes]), { mode: 0o600 });
console.log(`Issuer address: ${(await createKeyPairSignerFromBytes(bytes)).address}`);
```

```bash Terminal
npx tsx keygen.ts
```

The key file is the issuer's private key: anyone who has it controls the
asset. Keep it out of version control. On devnet, paste the printed address
into the [Solana Faucet](https://faucet.solana.com/) to fund it. On a local
Surfpool network, `surfpool start` airdrops SOL at startup to the key file at
`~/.config/solana/id.json`. If you created the key file after starting
Surfpool, or keep it somewhere else, restart it with
`surfpool start --airdrop <issuer address>`.

Then run the script:

```bash Terminal
npx tsx run.ts
```

The examples package runs this script in its tests on a local Surfpool
network, next to the
[`demo.ts`](https://github.com/catmcgee/solana-com/blob/mintlify-migration/packages/docs-examples/paths/assets/issue-asset/demo.ts)
sequence that printed the recorded output on this page. Expect the same states,
errors and balances, with different addresses and signatures.
