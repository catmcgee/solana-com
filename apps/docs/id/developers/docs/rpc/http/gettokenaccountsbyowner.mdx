---
title: Metode RPC getTokenAccountsByOwner
sidebarTitle: getTokenAccountsByOwner
---

Mengembalikan semua akun Token SPL berdasarkan pemilik token.

<RequestExample>
  ```bash cURL
  curl https://api.devnet.solana.com -s -X POST \
    -H "Content-Type: application/json" \
    -d '
    {
      "jsonrpc": "2.0",
      "id": 1,
      "method": "getTokenAccountsByOwner",
      "params": [
        "A1TMhSGzQxMr1TboBKtgixKz1sS6REASMxPo1qsyTSJd",
        {
          "programId": "TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA"
        },
        {
          "commitment": "finalized",
          "encoding": "jsonParsed"
        }
      ]
    }
  '
  ```

  ```ts Kit
  import { address, createSolanaRpc } from "@solana/kit";

  const rpc_url = "https://api.devnet.solana.com";
  const rpc = createSolanaRpc(rpc_url);

  let owner = address("4kg8oh3jdNtn7j2wcS7TrUua31AgbLzDVkBZgTAe44aF");

  let tokenProgram = address("TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA");

  let tokenAccounts = await rpc
    .getTokenAccountsByOwner(
      owner,
      { programId: tokenProgram },
      { encoding: "base64" }
    )
    .send();

  console.log(tokenAccounts);
  ```

  ```rs Rust
  use anyhow::Result;
  use solana_client::{nonblocking::rpc_client::RpcClient, rpc_request::TokenAccountsFilter};
  use solana_sdk::{commitment_config::CommitmentConfig, pubkey};

  #[tokio::main]
  async fn main() -> Result<()> {
      let client = RpcClient::new_with_commitment(
          String::from("https://api.devnet.solana.com"),
          CommitmentConfig::confirmed(),
      );

      let owner = pubkey!("4kg8oh3jdNtn7j2wcS7TrUua31AgbLzDVkBZgTAe44aF");

      let token_program = pubkey!("TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA");

      let token_accounts = client
          .get_token_accounts_by_owner(&owner, TokenAccountsFilter::ProgramId(token_program))
          .await?;

      println!("{:#?}", token_accounts);

      Ok(())
  }
  ```

## Parameters

<ParamField body="pubkey" type="string" required>
  Pubkey dari pemilik akun yang ingin diquery, sebagai string yang dikodekan
  base-58
</ParamField>

<ParamField body="1" type="object" required>
  Objek JSON dengan salah satu field berikut:

  <Expandable title="properties" defaultOpen>
    <ParamField body="mint" type="string">
      Pubkey dari Mint token spesifik untuk membatasi akun, sebagai string yang
      dikodekan base-58
    </ParamField>

    <ParamField body="programId" type="string">
      Pubkey dari program Token yang memiliki akun, sebagai string yang dikodekan
      base-58
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="2" type="object">
  Objek konfigurasi yang berisi field berikut:

  <Expandable title="properties" defaultOpen>
    <ParamField body="commitment" type="string">
      Commitment menjelaskan seberapa final suatu blok pada titik waktu tertentu.
      Lihat [Mengonfigurasi State Commitment](/developers/docs/rpc#configuring-state-commitment).
    </ParamField>

    <ParamField body="minContextSlot" type="number">
      Slot minimum di mana permintaan dapat dievaluasi
    </ParamField>

    <ParamField body="dataSlice" type="object">
      Meminta potongan data dari akun.

      - `length: <usize>` - jumlah byte yang akan dikembalikan
      - `offset: <usize>` - offset byte dari mana mulai membaca

      <Info>
        Pemotongan data hanya tersedia untuk pengkodean `base58`, `base64`, atau
        `base64+zstd`
      </Info>
    </ParamField>

    <ParamField body="encoding" type="string">
      Values: `base58`, `base64`, `base64+zstd`, `jsonParsed`

      Format pengkodean untuk data Akun

      - `base58` lambat dan terbatas untuk data Akun kurang dari 129 byte.
      - `base64` akan mengembalikan data yang dikodekan base64 untuk data Akun dengan
        ukuran berapa pun.
      - `base64+zstd` mengompres data Akun menggunakan
        [Zstandard](https://facebook.github.io/zstd/) dan mengkodekan hasilnya dengan
        base64.
      - Pengkodean `jsonParsed` mencoba menggunakan parser status khusus program untuk
        mengembalikan data status akun yang lebih mudah dibaca dan eksplisit.
      - Jika `jsonParsed` diminta tetapi parser tidak ditemukan, bidang tersebut akan
        kembali ke pengkodean `base64`, yang dapat dideteksi ketika bidang `data`
        bertipe `string`.
    </ParamField>
  </Expandable>
</ParamField>

## Result

<ResponseField name="result" type="array">
  Array objek JSON yang berisi:

  <Expandable title="properties" defaultOpen>
    <ResponseField name="pubkey" type="string">
      Pubkey akun sebagai string yang dikodekan base-58
    </ResponseField>

    <ResponseField name="account" type="object">
      Objek JSON yang berisi:

      - `lamports: <u64>` - jumlah lamport yang ditetapkan ke akun ini, sebagai u64
      - `owner: <string>` - Pubkey yang dikodekan base-58 dari program yang telah
        ditetapkan ke akun ini
      - `data: <object>` - Data status Token yang terkait dengan akun, baik sebagai
        data biner yang dikodekan atau dalam format JSON `{<program>: <state>}`
      - `executable: <bool>` - boolean yang menunjukkan apakah akun berisi program
        (dan hanya bisa dibaca saja)
      - `rentEpoch: <u64>` - epoch di mana akun ini akan membayar rent berikutnya,
        sebagai u64
      - `space: <u64>` - ukuran data dari akun

      Ketika data diminta dengan pengkodean `jsonParsed` format yang mirip dengan
      [Struktur Token Balances](/developers/docs/rpc/json-structures#token-balances) dapat
      diharapkan di dalam struktur, baik untuk `tokenAmount` maupun
      `delegatedAmount` - dengan yang terakhir sebagai objek opsional.
    </ResponseField>
  </Expandable>
</ResponseField>
