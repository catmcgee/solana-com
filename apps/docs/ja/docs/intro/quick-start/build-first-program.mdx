このクイックスタートでは、`anchor init`によって生成された[Anchor フレームワーク](https://www.anchor-lang.com/docs)のスタータープロジェクトを使用します。プロジェクトをローカルに作成し、テストを実行してプログラムをビルドし、Anchorが生成するプログラムコードを詳しく見ていきます。

## 前提条件

開始する前に、[Solana開発ツールをインストールしてください](/docs/intro/installation)。インストールにはRust、Solana
CLI、およびAnchor CLIが含まれます。

このテンプレートにはAnchor
CLIバージョン1.1.2以降を使用してください。インストール済みのバージョンを確認するには：

```bash Terminal
anchor --version
```

<Steps titleSize="h3">

<Step title="プロジェクトの作成">

ターミナルで以下のコマンドを実行してください：

```bash Terminal
anchor init my-program
cd my-program
```

スタータープロジェクトには、`programs/my-program`配下にSolanaプログラムが1つ含まれています。このプログラムにはinstructionsが2つあります：カウンターアカウントを初期化するものと、カウンターをインクリメントするものです。

テンプレートの一部には、一般的なSolanaプログラムのパターンが示されています：[PDA](/docs/core/pda)アカウントアドレスの導出、SOLを転送するためのCross
Program
Invocation（[CPI](/docs/core/cpi)）の実行、そして条件が満たされない場合にinstructionsを停止するカスタムエラーチェックの使用です。

</Step>

<Step title="プログラムのビルド">

`anchor build`を実行してスタータープログラムをコンパイルします：

```bash Terminal
anchor build
```

コンパイルされたプログラムは`target/deploy/my_program.so`に書き込まれます。プログラムがデプロイされると、この`.so`ファイルの内容がオンチェーンのアカウントに保存されます。

</Step>

<Step title="テストの実行">

デフォルトのテストを実行します：

```bash Terminal
anchor test
```

このテンプレートの`Anchor.toml`はRustのテストコマンドを使用します：

```toml Anchor.toml
skip_local_validator = true

[scripts]
test = "cargo test"
```

このテストはコンパイル済みのプログラムを[LiteSVM](https://www.litesvm.com/)に読み込み、ペイヤーを作成し、`initialize`
と `increment`
のinstructionsを送信し、その後カウンターアカウントの状態を確認します。

`anchor test`を実行するとプログラムもコンパイルされるため、ローカルでテストする際に
`anchor build`を先に実行する必要はありません。

</Step>

<Step title="プログラムのデプロイ">

ローカルテストは最も素早いフィードバックループです。devnetなどのネットワークへのデプロイの準備ができたら、まずビルドし、その後クラスターへデプロイします。

SolanaプログラムのデプロイにはSOLが必要です。プログラムはアカウントに保存され、そのアカウントは使用するスペースの料金を支払う必要があるためです。devnetでは、[Solana Faucet](https://faucet.solana.com/)またはSolana
CLIを使って無料のdevnet SOLをリクエストできます：

```bash Terminal
solana airdrop 2 --url devnet
```

```bash Terminal
anchor build
anchor deploy --provider.cluster devnet
```

</Step>

</Steps>

## ソースファイル

`src`ディレクトリにはSolanaプログラムが含まれています。Anchorの
[Program Structure](https://www.anchor-lang.com/docs/basics/program-structure)
ドキュメントでは、`declare_id!`、
`#[program]`、`#[derive(Accounts)]`、`#[account]`などここで使用されているコアマクロについて説明しています。このセクションではテンプレートファイルを順に解説します。

### lib.rs

`lib.rs`はプログラムのエントリーポイントです。ソースファイルを接続し、プログラムアドレスを定義し、ユーザーが呼び出せるプログラムのinstructionsを定義します。

```rust programs/my-program/src/lib.rs wrap
pub mod constants;
pub mod error;
pub mod instructions;
pub mod state;

use anchor_lang::prelude::*;

pub use constants::*;
pub use instructions::*;
pub use state::*;

declare_id!("82sFkffP9wxwpyfZyeaKHH2chQoJPUGsJZSPi9mrUuXd");

#[program]
pub mod my_program {
    use super::*;

    pub fn initialize(ctx: Context<Initialize>) -> Result<()> {
        crate::instructions::initialize::handle_initialize(ctx)
    }

    pub fn increment(ctx: Context<Increment>) -> Result<()> {
        crate::instructions::increment::handle_increment(ctx)
    }
}
```

<Note>
  **`pub mod constants`**

  `pub mod constants` は `constants.rs`
  をプログラムクレートの一部にします。ここには、PDA
  seed、送金額、カウンターの最大値など、プログラムで共有される値をテンプレートが保持します。

  **`pub mod error`**

  `pub mod error` は `error.rs`
  をプログラムクレートの一部にします。このファイルは、instructionが無効な場合にプログラムが返すカスタムエラーを定義します。

  **`pub mod instructions`**

  `pub mod instructions` は `instructions.rs`
  をプログラムクレートの一部にします。そのファイルは、`src/instructions/`
  内のinstruction固有のファイルのインデックスとして機能します。

  **`pub mod state`**

  `pub mod state` は `state.rs`
  をプログラムクレートの一部にします。このファイルは、`Counter`
  アカウントを含む、このプログラムが所有するアカウントのデータレイアウトを定義します。

  **`anchor_lang::prelude`**

  `anchor_lang::prelude::*`
  は、`Context`、`Result`、`Pubkey`、`Account`、`Signer`、および Anchor アカウント属性など、Solana プログラムの定義に使用される Anchor の型とマクロをインポートします。

  `pub use`
  の行は、子モジュールのパブリックアイテムをクレートルートから利用できるようにします。これにより、長いモジュールパスではなく
  `Context<Initialize>`
  のように、instructionのエントリーポイントを短く保てます。

  **`declare_id!`**

  `declare_id!`
  はプログラムのアドレスを定義します。`Anchor.toml`、デプロイ済みの program
  account、およびプログラムを呼び出すユーザーやテストのアドレスと一致している必要があります。

  **`#[program]`**

  `#[program]`
  は、Solana プログラムのエントリーポイントおよびinstruction ディスパッチコードを生成するよう Anchor に指示します。このモジュール内のパブリック関数が、ユーザーが呼び出せる instructions になります。

  **`pub fn initialize`, `pub fn increment`**

  `initialize` と `increment`
  は、ユーザーが呼び出せる2つのinstruction名です。それぞれ `Context<T>`
  を受け取ります。`Context`
  内の型はそのinstructionに必要なアカウントを定義し、Anchor はinstruction実行前にそれらのアカウントを検証します。

  **`handle_initialize`, `handle_increment`**

  ハンドラー関数には、instructionsのロジックが含まれています。
</Note>

    ```toml Anchor.toml highlight={2} wrap
    [programs.localnet]
    my_program = "82sFkffP9wxwpyfZyeaKHH2chQoJPUGsJZSPi9mrUuXd"
    ```
  </div>

  <div>

### constants.rs

`constants.rs`は、共有する値を一か所にまとめます。このテンプレートでは、`COUNTER_SEED`がカウンターPDAを導出し、`HELLO_WORLD_LAMPORTS`が初期化時に転送され、`MAX_COUNT`がインクリメント前にチェックされます。

```rust programs/my-program/src/constants.rs wrap
use anchor_lang::prelude::*;

#[constant]
pub const COUNTER_SEED: &[u8] = b"counter";

#[constant]
pub const HELLO_WORLD_LAMPORTS: u64 = 1;

#[constant]
pub const MAX_COUNT: u64 = 10;
```

<Note>
  **`#[constant]`**

  `#[constant]`は、その値をプログラムIDLに含めるようAnchorに指示します。これにより、重要なプログラム定数が生成されたクライアントやツールから参照できるようになります。

  **`COUNTER_SEED`**

  `COUNTER_SEED`は、カウンターPDAを導出するために使用されるバイト文字列です。プログラムとテストの両方がこのseedを使用することで、別途keypairを保存することなくアカウントアドレスを一致させることができます。このテンプレートは固定seedを1つ使用するため、プログラムはカウンターアドレスを1つ持ちます。実際のプログラムでは、多くの関連アカウントを作成するために、seedにユーザーのアドレスや別の識別子を含めることがよくあります。

  **`HELLO_WORLD_LAMPORTS`**

  `HELLO_WORLD_LAMPORTS`は、`initialize`内でペイヤーからカウンターアカウントへ転送されるlamportの量です。このテンプレートはSystem
  ProgramへのCPIをデモするものであるため、意図的に少額に設定されています。

  **`MAX_COUNT`**

  `MAX_COUNT`は、`increment`によってチェックされる上限値です。ここに定義することで、プログラム、テスト、および生成されたIDLがそのルールに対して1つの共通名を持つことができます。
</Note>

    ```rust initialize.rs highlight={8,18} wrap
        // ...
        #[account(

    ```
  </div>

    - `COUNTER_SEED`
      はカウンターPDAアドレスを導出します。
    - `HELLO_WORLD_LAMPORTS`
      は支払者からカウンターアカウントへ転送される金額を設定します。

### state.rs

`state.rs`
は、プログラムが作成・所有するアカウントのカスタムデータ型を定義します。プログラムはそのデータを作成・初期化・更新するためのinstructionsを定義しますが、カウンターデータはプログラム自体の内部には保存されません。独自のアドレスを持つ別のアカウントに保存されます。

```rust programs/my-program/src/state.rs wrap
use anchor_lang::prelude::*;

#[account]
#[derive(InitSpace)]
pub struct Counter {
    pub count: u64,
    pub authority: Pubkey,
}
```

<Note>
  **`#[account]`**

  `#[account]`
  は、このstructがプログラムによって所有されるオンチェーンアカウントに保存できるデータであることをAnchorに伝えます。Anchorはこれを使用して
  `Counter` アカウントのシリアライズ、デシリアライズ、および検証を行います。

  **`InitSpace`**

  `InitSpace` により、Anchorはこのstructのフィールドに必要なバイト数である
  `Counter::INIT_SPACE`
  を計算できます。8バイトのAnchorアカウントディスクリミネーターは、アカウント作成時に別途追加されます。

  **`count`**

  `count` はアカウントデータ内に保存されるカウンター値です。

  **`authority`**

  `authority`
  はカウンターをインクリメントすることが許可されたアドレスを保存します。`initialize`
  がこのアドレスを書き込み、`increment` は同じアドレスによる署名を要求します。
</Note>

<Columns cols={2}>

    ```rust initialize.rs highlight={4,12-13} wrap
        payer = payer,
        space = 8 + Counter::INIT_SPACE,

        bump

    // ...

    pub fn handle_initialize(ctx: Context<Initialize>) -> Result<()> {
        ctx.accounts.counter.count = 0;

        Ok(())
    }
    ```

    ```rust increment.rs highlight={4} wrap

        ctx.accounts.counter.count += 1;
        Ok(())
    }
    ```
  </div>

  <div>
    `state.rs` は `Counter`
    アカウントデータを定義します。instructionsファイルは、アカウントの作成と更新の際にその型を使用します：

    - `Counter::INIT_SPACE` は `state.rs`
      で定義されたフィールドに合わせてアカウントのサイズを設定します。
    - `count` と `authority`
      は、アカウントの初期化時に書き込まれるフィールド値です。
    - `count += 1`
      は、バリデーションが通過した後にカウンターの保存値を更新します。
  </div>
</Columns>

### error.rs

`error.rs`
はプログラムのカスタムエラーを定義します。このテンプレートでは、呼び出し元がカウンターを更新する権限を持たない場合、またはカウンターがすでに
`MAX_COUNT`
に達している場合に、instructionハンドラーが停止する仕組みをエラーで示しています。

```rust programs/my-program/src/error.rs wrap
use anchor_lang::prelude::*;

#[error_code]
pub enum ErrorCode {
    #[msg("Only the counter authority can update this counter")]
    Unauthorized,
    #[msg("Counter has reached the maximum value")]
    CounterOverflow,
}
```

<Note>
  **`#[error_code]`**

  `#[error_code]`
  は、これらのバリアントをカスタムプログラムエラーに変換するよう Anchor に指示します。クライアントやテストは、生のエラーコードを推測する代わりにこれらのエラーを使用できます。

  **`Unauthorized`**

  `Unauthorized`
  は、トランザクションの署名者がカウンターアカウントに保存されている権限者でない場合に返されます。

  **`CounterOverflow`**

  `CounterOverflow` は、インクリメントによってプログラムの `MAX_COUNT`
  ルールが破られる場合に返されます。
</Note>

<Columns cols={2}>
  <div>
    ```rust increment.rs highlight={5,9} wrap
    pub fn handle_increment(ctx: Context<Increment>) -> Result<()> {
        require_keys_eq!(
            ctx.accounts.counter.authority,
            ctx.accounts.authority.key(),
            ErrorCode::Unauthorized,
        );
        require!(
            ctx.accounts.counter.count < MAX_COUNT,
            ErrorCode::CounterOverflow,
        );

        ctx.accounts.counter.count += 1;
        msg!("Hello, world! Counter is now {}", ctx.accounts.counter.count);
        Ok(())
    }
    ```
  </div>

  <div>
    `error.rs` は、instructionが返す可能性のあるエラーを定義します：

    - `ErrorCode::Unauthorized`
      は、署名者がカウンターアカウントに保存されている権限者でない場合に返されます。
    - `ErrorCode::CounterOverflow`
      は、カウンターがすでに `MAX_COUNT` に達している場合に返されます。
  </div>
</Columns>

### instructions.rs

`instructions.rs` は、instructionsファイルをプログラムクレートに接続し、
`lib.rs` が `initialize` および `increment`
のinstructionsコードにアクセスできるようにします。各instructionsファイルは、そのinstructionsが必要とするアカウントと、Anchor がそれらのアカウントを検証した後に実行されるハンドラーロジックを定義します。

```rust programs/my-program/src/instructions.rs wrap
pub mod initialize;
pub mod increment;

pub use initialize::*;
pub use increment::*;
```

<Note>
  **`pub mod initialize`**

  `pub mod` の行は、`src/instructions/initialize.rs` と
  `src/instructions/increment.rs` をプログラムクレートの一部にします。

  **`pub use initialize`**

  `pub use`
  の行は、それらのファイルからパブリックアイテムを再エクスポートします。これにより、instructionsアカウント構造体とハンドラー関数が
  `instructions` モジュールを通じて利用可能になります。
</Note>

### initialize.rs

`initialize.rs`
は、カウンターアカウントを作成するために必要なアカウントを定義し、アカウントの初期値を書き込みます。`#[derive(Accounts)]`
構造体は、Anchor の
[アカウント制約](https://www.anchor-lang.com/docs/references/account-constraints)
を使用して、必要なアカウントと新しいカウンターアカウントの作成方法を指定します。

```rust programs/my-program/src/instructions/initialize.rs wrap
use anchor_lang::prelude::*;

use crate::{constants::*, state::Counter};

#[derive(Accounts)]
pub struct Initialize<'info> {
    #[account(mut)]
    pub payer: Signer<'info>,
    #[account(
        init,
        payer = payer,
        space = 8 + Counter::INIT_SPACE,
        seeds = [COUNTER_SEED],
        bump
    )]
    pub counter: Account<'info, Counter>,
    pub system_program: Program<'info, System>,
}

pub fn handle_initialize(ctx: Context<Initialize>) -> Result<()> {
    ctx.accounts.counter.count = 0;
    ctx.accounts.counter.authority = ctx.accounts.payer.key();

    let cpi_accounts = anchor_lang::system_program::Transfer {
        from: ctx.accounts.payer.to_account_info(),
        to: ctx.accounts.counter.to_account_info(),
    };
    let cpi_ctx = CpiContext::new(anchor_lang::system_program::ID, cpi_accounts);
    anchor_lang::system_program::transfer(cpi_ctx, HELLO_WORLD_LAMPORTS)?;

    msg!("Hello, world! Counter initialized");
    Ok(())
}
```

<Note>
  このファイルは共有定数と `Counter`
  アカウントタイプをインポートします。instructionsはこれらの定義を使用してPDAを導出し、転送額を選択し、適切なデータサイズでアカウントを割り当てます。

  **`derive(Accounts)`**

  `Initialize` は `initialize`
  instructionsのアカウントコンテキストです。struct内の各フィールドは、instructionsが呼び出される際に含める必要がある個別のアカウントを表します。Anchorはstructを使用して、ハンドラーが実行される前にこれらの受信アカウントを検証します。

  **`#[account(mut)]`**

  `#[account(mut)]`
  はAnchorに対して、支払いアカウントが書き込み可能である必要があることを伝えます。アカウント作成と転送CPIの両方が支払い者からlamportを差し引くため、これは必須です。

  **`Signer<'info>`**

  `Signer<'info>`
  はAnchorに対して、支払い者がトランザクションに署名する必要があることを伝えます。

  **`#[account(`**

  `#[account(...)]`
  ブロックは、ハンドラーが実行される前にカウンターアカウントを作成および検証する方法をAnchorに伝えます。

  **`init`**

  `init` は、ハンドラーが実行される前に `counter`
  アカウントを作成するよう Anchor に指示します。新しいアカウントはこのプログラムが所有するため、このプログラムは
  `Counter` データをそこに保存できます。

  **`payer = payer`**

  `payer = payer` は、新しいカウンターアカウントの作成費用の支払い者として
  `payer` アカウントを指定します。

  **`space = 8 + Counter::INIT_SPACE`**

  `space = 8 + Counter::INIT_SPACE`
  は、Anchor のアカウントディスクリミネーターと `state.rs` の `Counter`
  フィールド分のバイトを割り当てます。ディスクリミネーターは、アカウントを読み取る前に期待される型が格納されているかどうかを Anchor が確認するのに役立ちます。

  **`seeds = [COUNTER_SEED]`**

  `seeds = [COUNTER_SEED]`
  は、カウンターアカウントのアドレスがこの seed とプログラム ID から導出された PDA でなければならないことを示します。固定の seed が1つであるため、このプログラムに対してカウンター PDA は1つだけ存在します。実際のプログラムで個別のカウンターを作成するには、通常はユーザーのアドレスなど別の seed を追加します。

  **`bump`**

  `bump`
  は、PDA のバンプ（導出アドレスを PDA として有効にする追加の1バイト）を検索して検証するよう Anchor に指示します。

  **`Account<'info, Counter>`**

  `Account<'info, Counter>` は、アカウントデータを `state.rs` の `Counter`
  型として扱うよう Anchor に指示します。また、Anchor はアカウントがこのプログラムによって所有されていることも確認します。

  **`Program<'info, System>`**

  `Program<'info, System>` は、呼び出し元に System
  Program の提供を要求します。Anchor は `init`
  アカウント作成制約のためにこれを使用します。ハンドラーのトランスファー CPI も System
  Program を呼び出します。

  **`handle_initialize`**

  ハンドラーは Anchor がアカウントを検証してカウンターアカウントを作成した後に実行されるため、アカウントの初期データを安全に書き込むことができます。

  **`counter.count = 0`**

  カウンターアカウントの `count` フィールドを `0` に設定します。

  **`counter.authority = ctx.accounts.payer.key()`**

  カウンターアカウントの `authority`
  フィールドを支払い者のアドレスに設定します。

  **`system_program::Transfer`**

  これらは、System Program のtransfer
  instructionsに渡されるアカウントです。このtransfer
  CPIは、CPIが別のプログラムにアカウントを渡す方法を示すためだけに含まれています。

  **`CpiContext::new`**

  `CpiContext` は、Cross Program
  Invocationのためにターゲットプログラムと必要なアカウントをまとめます。コンテキストを作成することで、呼び出したいプログラムとそのプログラムが必要とするアカウントを対応付け、CPIの準備を整えます。

  **`system_program::transfer`**

  このCPIはSystem Programのtransfer
  instructionsを呼び出し、`HELLO_WORLD_LAMPORTS`
  をpayerからcounterアカウントに移動します。

  **`msg!`**

  `msg!`
  は、プログラムが呼び出されたときにプログラムログにメッセージを書き込みます。
</Note>

### increment.rs

`increment.rs`
は、既存のcounterアカウントを更新するために必要なアカウントを定義します。ハンドラーは、署名者が保存されたauthorityと一致するかを確認し、countが指定された`MAX_COUNT`に達していないかをチェックしたうえで、countをインクリメントします。

```rust programs/my-program/src/instructions/increment.rs wrap
use anchor_lang::prelude::*;

use crate::{constants::*, error::ErrorCode, state::Counter};

#[derive(Accounts)]
pub struct Increment<'info> {
    #[account(
        mut,
        seeds = [COUNTER_SEED],
        bump
    )]
    pub counter: Account<'info, Counter>,
    pub authority: Signer<'info>,
}

pub fn handle_increment(ctx: Context<Increment>) -> Result<()> {
    require_keys_eq!(
        ctx.accounts.counter.authority,
        ctx.accounts.authority.key(),
        ErrorCode::Unauthorized,
    );
    require!(
        ctx.accounts.counter.count < MAX_COUNT,
        ErrorCode::CounterOverflow,
    );

    ctx.accounts.counter.count += 1;
    msg!("Hello, world! Counter is now {}", ctx.accounts.counter.count);
    Ok(())
}
```

<Note>
  **`derive(Accounts)`**

  `Increment` は `increment`
  instructions のアカウントコンテキストです。Anchor はこれを使用して、ミュータブルなカウンターアカウントと必要な署名者を検証します。

  **`mut`**

  `mut` は、ハンドラーが保存された `count`
  の値を更新するため、カウンターアカウントが書き込み可能でなければならないことを Anchor に伝えます。

  **`seeds = [COUNTER_SEED]`**

  `seeds = [COUNTER_SEED]`
  は、提供されたカウンターアカウントがこの seed とプログラム ID から導出された PDA であることを検証します。

  **`bump`**

  `bump`
  は、カウンターアカウントの PDA バンプを検索して検証するよう Anchor に指示します。

  **`Account<'info, Counter>`**

  `Account<'info, Counter>` は、アカウントデータを `state.rs` の `Counter`
  型としてデシリアライズするよう Anchor に指示します。また、Anchor はアカウントがこのプログラムによって所有されていることも確認します。

  **`Signer`**

  `Signer`
  は権限者の署名を要求します。ハンドラーはその後、この署名者のアドレスをカウンターアカウントに保存された権限者と比較します。

  **`handle_increment`**

  ハンドラーは、Anchor がアカウントリストを検証し、所有権を確認し、カウンターアカウントをデシリアライズした後に実行されます。

  **`require_keys_eq!`**

  `require_keys_eq!`
  は2つの公開鍵を比較し、署名者のアドレスがカウンターアカウントに保存された権限者と一致しない限り、instructionを停止します。これはテンプレートのアプリケーションレベルの認可ルールです。

  **`require!`**

  `require!` はブール値のルールを確認し、カウンターがすでに `MAX_COUNT`
  に達している場合は `CounterOverflow`
  でinstructionを停止します。このテンプレートルールは、カスタムエラーとミューテーション前の失敗処理を示しています。

  **`count += 1`**

  両方のチェックが通過した場合にのみ、ハンドラーはカウンターアカウントのデータを更新します。どちらかのチェックが失敗した場合、トランザクションは失敗し、アカウントは変更されません。

  **`msg!`**

  `msg!`
  は、プログラムが呼び出されたときにプログラムログにメッセージを書き込みます。
</Note>

    で停止します。この上限はテンプレート内の人為的なルールであり、カスタムエラーがアカウントデータが変更される前に instructions を停止する仕組みを確認できます。

    ```rust increment.rs focus={18-21}
    #[derive(Accounts)]
    pub struct Increment<'info> {
        #[account(
            mut,
            seeds = [COUNTER_SEED],
            bump
        )]
        pub counter: Account<'info, Counter>,
        pub authority: Signer<'info>,
    }

    pub fn handle_increment(ctx: Context<Increment>) -> Result<()> {
        require_keys_eq!(
            ctx.accounts.counter.authority,
            ctx.accounts.authority.key(),
            ErrorCode::Unauthorized,
        );
        require!(
            ctx.accounts.counter.count < MAX_COUNT,
            ErrorCode::CounterOverflow,
        );

        ctx.accounts.counter.count += 1;
        msg!("Hello, world! Counter is now {}", ctx.accounts.counter.count);
        Ok(())
    }
    ```
  </Step>

  <Step title="カウントの更新">
    両方のチェックが通過した後にのみ、ハンドラーはアカウントデータを更新します。この行は保存されたカウンター値に 1 を加算します。

```rust programs/my-program/tests/test_initialize.rs wrap
use {
    anchor_lang::{
        prelude::Pubkey,
        solana_program::{instruction::Instruction, system_program},
        AccountDeserialize, InstructionData, ToAccountMetas,
    },
    litesvm::LiteSVM,
    solana_keypair::Keypair,
    solana_message::{Message, VersionedMessage},
    solana_signer::Signer,
    solana_transaction::versioned::VersionedTransaction,
};

#[test]
fn test_initialize() {
    let program_id = my_program::id();
    let payer = Keypair::new();
    let counter = Pubkey::find_program_address(
        &[my_program::constants::COUNTER_SEED],
        &program_id,
    )
    .0;
    let mut svm = LiteSVM::new();
    let bytes = include_bytes!(concat!(
        env!("CARGO_TARGET_TMPDIR"),
        "/../deploy/my_program.so"
    ));
    svm.add_program(program_id, bytes).unwrap();
    svm.airdrop(&payer.pubkey(), 1_000_000_000).unwrap();

    let instruction = Instruction::new_with_bytes(
        program_id,
        &my_program::instruction::Initialize {}.data(),
        my_program::accounts::Initialize {
            payer: payer.pubkey(),
            counter,
            system_program: system_program::ID,
        }
        .to_account_metas(None),
    );

    let blockhash = svm.latest_blockhash();
    let msg = Message::new_with_blockhash(&[instruction], Some(&payer.pubkey()), &blockhash);
    let tx = VersionedTransaction::try_new(VersionedMessage::Legacy(msg), &[&payer]).unwrap();

    let res = svm.send_transaction(tx);
    assert!(res.is_ok());

    let counter_account = svm.get_account(&counter).unwrap();
    let mut data: &[u8] = &counter_account.data;
    let counter_state = my_program::state::Counter::try_deserialize(&mut data).unwrap();
    assert_eq!(counter_state.count, 0);
    assert_eq!(counter_state.authority, payer.pubkey());

    let instruction = Instruction::new_with_bytes(
        program_id,
        &my_program::instruction::Increment {}.data(),
        my_program::accounts::Increment {
            counter,
            authority: payer.pubkey(),
        }
        .to_account_metas(None),
    );

    let blockhash = svm.latest_blockhash();
    let msg = Message::new_with_blockhash(&[instruction], Some(&payer.pubkey()), &blockhash);
    let tx = VersionedTransaction::try_new(VersionedMessage::Legacy(msg), &[&payer]).unwrap();

    let res = svm.send_transaction(tx);
    assert!(res.is_ok());

    let counter_account = svm.get_account(&counter).unwrap();
    let mut data: &[u8] = &counter_account.data;
    let counter_state = my_program::state::Counter::try_deserialize(&mut data).unwrap();
    assert_eq!(counter_state.count, 1);
    assert_eq!(counter_state.authority, payer.pubkey());
}
```

<Note>
  **`litesvm::LiteSVM`**

  `LiteSVM` はテスト用のインプロセスSolana
  VMです。validator プロセスを起動せずに、コンパイル済みプログラムの登録、アカウントの作成、トランザクションの送信、アカウント状態の確認をテストで行えます。

  **`let program_id`**

  テストは `my_program::id()` を通じて `declare_id!`
  の値からプログラムアドレスを取得し、テストトランザクション用の新しい支払者 keypair を作成します。

  **`Pubkey::find_program_address`**

  カウンターアドレスは、プログラムが使用するのと同じ `COUNTER_SEED`
  から導出されます。これにより、テストは `initialize.rs`
  が期待するPDAを対象とします。

  **`include_bytes!`**

  `include_bytes!` は、ビルドによって生成されたコンパイル済みの
  `my_program.so`
  ファイルを読み込みます。これらのバイトは、LiteSVMがテストで実行する実行可能なプログラムコードです。

  **`svm.add_program`**

  `svm.add_program`
  は、コンパイル済みプログラムのバイトをLiteSVM内のプログラムアドレスに登録します。エアドロップにより、支払者はトランザクションおよびアカウント作成に必要な十分なローカルSOLを受け取ります。

  **`let instruction`**

  `Instruction::new_with_bytes`
  は、プログラムを呼び出すためのinstructionsを作成します。プログラムID、instruction
  data、およびinstructionsアカウントが含まれます。

  **`svm.latest_blockhash`**

  すべてのSolanaトランザクションには最新のブロックハッシュが必要です。このテストでは、LiteSVMがトランザクションに使用するブロックハッシュを提供します。

  **`Message::new_with_blockhash`**

  メッセージにはinstructions、手数料支払者、およびブロックハッシュが含まれます。これは署名されるトランザクションデータです。

  **`VersionedTransaction::try_new`**

  `VersionedTransaction::try_new`
  は、支払者のkeypairでメッセージに署名します。支払者はトランザクション手数料を支払い、新しいカウンターアカウントに資金を提供するため、署名を行います。

  **`svm.send_transaction`**

  `svm.send_transaction` は、LiteSVM内でトランザクションを実行します。

  **`svm.get_account`**

  トランザクション実行後、テストはLiteSVMから直接カウンターアカウントを読み取り、アカウントデータを検査します。

  **`Counter::try_deserialize`**

  カウンターアカウントはシリアライズされたデータを格納しています。`Counter::try_deserialize`
  はAnchorのアカウントディスクリミネーターを確認し、アカウントデータを `state.rs`
  の `Counter` 型に戻します。

  **`assert_eq!(counter_state.count, 0)`**

  `initialize`
  が成功した後、テストはカウンターアカウントをデシリアライズし、初期状態が
  `handle_initialize` が書き込んだ内容と一致することを確認します。

  **`assert_eq!(counter_state.count, 1)`**

  `increment` が成功した後、同じカウンターアカウントの `count` が `1`
  に設定され、同じ権限が維持されているはずです。
</Note>

ルートプロジェクトファイルは、AnchorとCargoにプログラムのビルド、テスト、デプロイの方法を指示します。完全なリファレンスについては、[Anchor.toml の設定](https://www.anchor-lang.com/docs/references/anchor-toml)および
[Anchor CLI](https://www.anchor-lang.com/docs/references/cli)
に関する Anchor ドキュメントをご参照ください。

```toml Anchor.toml
skip_local_validator = true

[toolchain]

[features]
resolution = true
skip-lint = false

[programs.localnet]
my_program = "82sFkffP9wxwpyfZyeaKHH2chQoJPUGsJZSPi9mrUuXd"

[provider]
cluster = "localnet"
wallet = "~/.config/solana/id.json"

[scripts]

[hooks]
```

<Note>
  **`skip_local_validator`**

  `skip_local_validator = true` は、`anchor test`
  に対して validator を起動しないよう Anchor に指示します。Rust テストでは代わりに LiteSVM を使用します。

  **`programs.localnet`**

  `[programs.localnet]`
  は、Rust クレート名をローカルのビルドおよびテストで使用する program
  account のアドレスにマッピングします。

  **`provider`**

  `[provider]` は、`anchor deploy`
  などのコマンドに使用するデフォルトのクラスターとウォレットを設定します。

  **`scripts`**

  `[scripts]` は、`anchor test`
  が実行する内容を変更します。このテンプレートでは、`anchor test` は `cargo test`
  を実行します。
</Note>
