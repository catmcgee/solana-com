## Was sind Metadaten-Zeiger- und Token-Metadaten-Erweiterungen?

Die `MetadataPointer`-Mint-Erweiterung des Token Extensions Program
speichert zwei Felder auf einem Mint:

- Eine Autorisierung, die den Zeiger aktualisieren kann
- Die Adresse des Kontos, das die Metadaten des Tokens speichert

Dieser Zeiger kann auf jedes Konto verweisen, das einem Programm gehört, welches
die
[Token-Metadaten-Schnittstelle](https://github.com/solana-program/token-metadata/tree/main/interface)
implementiert.

Das Token Extensions Program implementiert dieselbe Schnittstelle auch direkt
über die `TokenMetadata`-Mint-Erweiterung. Mit `TokenMetadata` speichert
der Mint den `name`, das `symbol`, den `uri`, das
`update_authority` und benutzerdefinierte Metadaten des Tokens direkt im
Mint-Konto.

<Info>
  **Off-Chain-Metadaten-URI**

  Das Feld `uri` verweist auf Off-Chain-JSON-Metadaten. Siehe
  [Off-Chain-Metadaten-Format](/docs/tokens/metaplex#off-chain-metadata-format).
</Info>

Die beiden Erweiterungen lösen unterschiedliche Probleme:

- `MetadataPointer` gibt das Konto an, das Metadaten speichert.
- `TokenMetadata` speichert die Metadaten direkt im Mint-Konto.

<Info>
  **Erweiterung mit variabler Länge**

  `TokenMetadata` ist eine TLV-Erweiterung mit variabler Länge.
`InitializeTokenMetadata`, `UpdateField` und `RemoveKey` können
  die Größe der Mint-Kontodaten ändern, übertragen jedoch keine zusätzlichen
  Lamports. Das Mint-Konto benötigt genügend Lamports, um für die gespeicherten
  Metadaten mietbefreit zu bleiben. Wenn die Metadaten später wachsen, müssen
  zusätzliche Lamports auf das Mint-Konto übertragen werden, bevor die
  Anweisungen ausgeführt werden, die dessen Größe ändern.
</Info>

## So speichern Sie Token-Metadaten im Mint-Konto

Um Metadaten im Mint-Konto zu speichern:

1. Berechnen Sie die Größe des Mint-Kontos und die benötigte Miete für das Mint,
   die Erweiterungen und die Metadaten.
2. Erstellen Sie das Mint-Konto mit `CreateAccount`, initialisieren Sie
   `MetadataPointer` und initialisieren Sie das Mint mit
   `InitializeMint`.
3. Initialisieren Sie `TokenMetadata` auf dem Mint-Konto und verwenden Sie
   dann `UpdateField`, um Metadaten hinzuzufügen oder zu aktualisieren.
4. Verwenden Sie `RemoveKey`, `UpdateAuthority` und `Emit`, um
   benutzerdefinierte Metadaten zu entfernen, die Upgrade-Authority zu ändern
   oder zu löschen oder die aktuellen Metadaten in den Transaktionsrückgabedaten
   zurückzugeben.

  <Step title="Kontengröße berechnen">
    Berechnen Sie die Größe des Mint-Kontos für das Basis-Mint plus die
    `MetadataPointer`- Erweiterung. Dies ist die Größe, die in
    `CreateAccount` verwendet wird.

    ```ts Beispiel focus={14-17,19}
    const client = await createClient()
      .use(generatedPayer())
      .use(
        solanaRpc({
          rpcUrl: "http://localhost:8899",
          rpcSubscriptionsUrl: "ws://localhost:8900"

      )
      .use(rpcAirdrop())
      .use(airdropPayer(lamports(1_000_000_000n)));

    const mint = await generateKeyPairSigner();

    const metadataPointerExtension = extension("MetadataPointer", {
      authority: client.payer.address,
      metadataAddress: mint.address
    });

    const mintSpace = BigInt(getMintSize([metadataPointerExtension]));
    ```
  </Step>

  <Step title="Metadaten aktualisieren, entfernen oder ausgeben">
    Nachdem die Mint initialisiert wurde, verwenden Sie `UpdateField`, um
    Metadaten zu aktualisieren, `UpdateMetadataPointer`, um den Metadaten-Zeiger
    zu aktualisieren, `RemoveKey`, um benutzerdefinierte Metadaten zu entfernen,
    `UpdateAuthority`, um die Update-Authority zu löschen, und `Emit`, um
    die aktuellen Metadaten zurückzugeben.

    ```ts Beispiel focus={74-99} expandable
    const client = await createClient()
      .use(generatedPayer())
      .use(
        solanaRpc({
          rpcUrl: "http://localhost:8899",
          rpcSubscriptionsUrl: "ws://localhost:8900"
        })
      )
      .use(rpcAirdrop())
      .use(airdropPayer(lamports(1_000_000_000n)));

    const mint = await generateKeyPairSigner();

    const metadataPointerExtension = extension("MetadataPointer", {
      authority: client.payer.address,
      metadataAddress: mint.address
    });

    const mintSpace = BigInt(getMintSize([metadataPointerExtension]));

    const maxTokenMetadataExtension = extension("TokenMetadata", {
      updateAuthority: client.payer.address,
      mint: mint.address,
      name: "Example Token v2",
      symbol: "EXMPL",
      uri: "https://example.com/token.json",
      additionalMetadata: new Map([
        ["description", "Metadata stored on mint account"]
      ])
    });
    const maxMintSpace = BigInt(
      getMintSize([metadataPointerExtension, maxTokenMetadataExtension])
    );
    const mintRent = await client.rpc
      .getMinimumBalanceForRentExemption(maxMintSpace)
      .send();

    await client.sendTransaction([
      getCreateAccountInstruction({
        payer: client.payer, // Account funding account creation.
        newAccount: mint, // New mint account to create.
        lamports: mintRent, // Lamports funding the mint account rent.
        space: mintSpace, // Account size in bytes for the mint plus MetadataPointer.
        programAddress: TOKEN_2022_PROGRAM_ADDRESS // Program that owns the mint account.
      }),
      getInitializeMetadataPointerInstruction({
        mint: mint.address, // Mint account that stores the MetadataPointer extension.
        authority: client.payer.address, // Authority allowed to update the metadata pointer later.
        metadataAddress: mint.address // Account address that stores the metadata.
      }),
      getInitializeMintInstruction({
        mint: mint.address, // Mint account to initialize.
        decimals: 0, // Number of decimals for the token.
        mintAuthority: client.payer.address, // Authority allowed to mint new tokens.
        freezeAuthority: client.payer.address // Authority allowed to freeze token accounts.
      }),
      getInitializeTokenMetadataInstruction({
        metadata: mint.address, // Mint account that stores the metadata.
        updateAuthority: client.payer.address, // Authority allowed to update metadata later.
        mint: mint.address, // Mint that the metadata describes.
        mintAuthority: client.payer, // Signer authorizing metadata initialization for the mint.
        name: "Example Token", // Token name stored in metadata.
        symbol: "EXMPL", // Token symbol stored in metadata.
        uri: "https://example.com/token.json" // URI pointing to off-chain JSON metadata.
      }),
      getUpdateTokenMetadataFieldInstruction({
        metadata: mint.address, // Mint account that stores the metadata.
        updateAuthority: client.payer, // Signer authorized to update metadata fields.
        field: tokenMetadataField("Key", ["description"]), // Custom metadata field to add.
        value: "Metadata stored on mint account" // Value stored for the custom metadata field.
      })
    ]);

    await client.sendTransaction([
      getUpdateTokenMetadataFieldInstruction({
        metadata: mint.address,
        updateAuthority: client.payer,
        field: tokenMetadataField("Name"),
        value: "Example Token v2"
      }),
      getUpdateMetadataPointerInstruction({
        mint: mint.address,
        metadataPointerAuthority: client.payer,
        metadataAddress: mint.address
      }),
      getRemoveTokenMetadataKeyInstruction({
        metadata: mint.address,
        updateAuthority: client.payer,
        key: "description"
      }),
      getUpdateTokenMetadataUpdateAuthorityInstruction({
        metadata: mint.address,
        updateAuthority: client.payer,
        newUpdateAuthority: null
      }),
      getEmitTokenMetadataInstruction({
        metadata: mint.address
      })
    ]);
    ```
  </Step>
</Steps>

<Info>
  **Anweisungsreihenfolge**

  `MetadataPointerInstruction::Initialize` muss vor `InitializeMint`
  kommen. `CreateAccount`, `MetadataPointerInstruction::Initialize` und
`InitializeMint` müssen in derselben Transaktion enthalten sein.
</Info>

### Typescript

Das `Kit`-Beispiel unten verwendet die generierten Anweisungen direkt. Legacy-Beispiele mit `@solana/web3.js`, `@solana/spl-token` und
`@solana/spl-token-metadata` sind als Referenz enthalten. Die Legacy-Beispiele begrenzen
`maxSupportedTransactionVersion` auf `0`, da web3.js v1 keine
[v1-Transaktionen](/docs/core/transactions/versioned-transactions#v1-message-format) deserialisieren kann.
