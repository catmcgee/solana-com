<Info>
  **Zusammenfassung**

  Konten haben 5 Felder: lamports, data, owner, executable und rent_epoch. Jedes
  Konto wird durch eine eindeutige 32-Byte-Adresse identifiziert. Konten müssen
  einen Mindest-lamport-Saldo proportional zu ihrer Datengröße halten, um
  onchain zu bleiben.
</Info>

## Konten-Adresse

Jede Konten-Adresse ist ein 32-Byte-Wert, der als base58-kodierter String
angezeigt wird. Eine Adresse kann einer von zwei Typen sein:

1. **Public key**: entspricht einem [Ed25519](https://ed25519.cr.yp.to/) keypair
   (hat einen private key)
2. **Program Derived Address (PDA)**: deterministisch abgeleitet von einer
   Programm-ID und Seeds (kein private key)

### Public key

Ein `Keypair` besteht aus einem public key (verwendet als Konten-Adresse)
und einem private key (verwendet zum Signieren von Transaktionen). Das folgende
Beispiel generiert ein keypair mit dem Solana SDK.

<CodeGroup>

```ts Kit
import { generateKeyPairSigner } from "@solana/kit";

// Kit does not enable extractable private keys
const keypairSigner = await generateKeyPairSigner();
console.log(keypairSigner);
```

```ts Legacy
import { Keypair } from "@solana/web3.js";

const keypair = Keypair.generate();
console.log(`Public Key: ${keypair.publicKey}`);
console.log(`Secret Key: ${keypair.secretKey}`);
```

```rs Rust
use solana_sdk::signer::{keypair::Keypair, Signer};

#[tokio::main]
async fn main() {
    let keypair = Keypair::new();
    println!("Public Key: {}", keypair.pubkey());
    println!("Secret Key: {:?}", keypair.to_bytes());
}
```

</CodeGroup>

### Program Derived Address

Eine [Program Derived Address](/docs/core/pda) (PDA) wird deterministisch von
einer Programm-ID und einem oder mehreren optionalen Seeds abgeleitet. PDAs
haben keinen entsprechenden private key. Das folgende Beispiel leitet eine PDA
mit dem Solana SDK ab.

<CodeGroup>

```ts Kit
import { Address, getProgramDerivedAddress } from "@solana/kit";

const programAddress = "11111111111111111111111111111111" as Address;

const seeds = ["helloWorld"];
const [pda, bump] = await getProgramDerivedAddress({
  programAddress,
  seeds
});

console.log(`PDA: ${pda}`);
console.log(`Bump: ${bump}`);
```

```ts Legacy
import { PublicKey } from "@solana/web3.js";

const programAddress = new PublicKey("11111111111111111111111111111111");

const seeds = [Buffer.from("helloWorld")];
const [pda, bump] = await PublicKey.findProgramAddressSync(
  seeds,
  programAddress
);

console.log(`PDA: ${pda}`);
console.log(`Bump: ${bump}`);
```

```rs Rust
use solana_sdk::pubkey; // macro
use solana_sdk::pubkey::Pubkey;

#[tokio::main]
async fn main() {
    let program_address = pubkey!("11111111111111111111111111111111");
    let seeds = [b"helloWorld".as_ref()];
    let (pda, bump) = Pubkey::find_program_address(&seeds, &program_address);
    println!("PDA: {}", pda);
    println!("Bump: {}", bump);
}
```

</CodeGroup>

## Konten-Felder

Jedes
[`Account`](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/account/src/lib.rs#L32-L56)
hat eine maximale Größe von
[`MAX_ACCOUNT_DATA_LEN`](https://github.com/anza-xyz/agave/blob/v3.1.8/transaction-context/src/lib.rs#L34)
(10 MiB, entspricht `MAX_PERMITTED_DATA_LENGTH`) und enthält fünf Felder:

| Feld         | Typ       | Beschreibung                                                                  |
| ------------ | --------- | ----------------------------------------------------------------------------- |
| `lamports`   | `u64`     | Guthaben in lamport. Owner kann belasten; jedes Programm kann gutschreiben.   |
| `data`       | `Vec<u8>` | Konto-Status oder Programm-Bytecode. Max. 10 MiB. Nur vom Owner beschreibbar. |
| `owner`      | `Pubkey`  | Programm mit Schreibzugriff. Nur neu zuweisbar, wenn Daten auf null gesetzt.  |
| `executable` | `bool`    | True = program account.                                                       |
| `rent_epoch` | `Epoch`   | Veraltet. Auf `u64::MAX` für rent-exempt Konten gesetzt.                      |

```rust Account
pub struct Account {
    /// lamports in the account
    pub lamports: u64,
    /// data held in this account
    #[cfg_attr(feature = "serde", serde(with = "serde_bytes"))]
    pub data: Vec<u8>,
    /// the program that owns this account. If executable, the program that loads this account.
    pub owner: Pubkey,
    /// if true, this account's data contains a program (and is now read-only)
    pub executable: bool,
    /// deprecated
    pub rent_epoch: Epoch,
}
```

<Steps>
  <Step title="Lamport">
    Das Feld `lamports` enthält das Guthaben des Kontos in
    [lamport](/docs/references/terminology#lamport) (1 SOL = 1.000.000.000 lamport).

    Jedes Konten muss ein Mindestguthaben an lamport aufrechterhalten, um seine Daten
    onchain gespeichert zu halten. Dieses erstattungsfähige Speicherguthaben ist proportional zur
    Datengröße des Kontos.

    <Info>
      Die Runtime und die RPC-Methodennamen bezeichnen dies als "rent-exempt minimum", jedoch
      ist die laufende rent-Erhebung deaktiviert. Betrachten Sie das Guthaben als eine erstattungsfähige
      Speicherkaution für das Konten: Das gesamte Guthaben kann zurückgewonnen werden, wenn das Konten geschlossen wird.
    </Info>

    Siehe
    [`minimum_balance()`](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/rent/src/lib.rs#L93)
    und die rent
    [Konstanten](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/rent/src/lib.rs#L47-L80).

    ```rust title="Account Examples" focus={3,13}
    // Example Token Mint Account
    Account {
        lamports: 1461600,
        data.len: 82,
        owner: TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb,
        executable: false,
        rent_epoch: 0,
        data: 010000001e213c90625a7e643d9555bb01b6c3fe6416d7afd523ce8c7ddd9b923ceafb9d00000000000000000901010000001e213c90625a7e643d9555bb01b6,
    }

    // Example Token Program Account
    Account {
        lamports: 4513200894,
        data.len: 134080,
        owner: BPFLoader2111111111111111111111111111111111,
        executable: true,
        rent_epoch: 18446744073709551615,
        data: 7f454c460201010000000000000000000300f70001000000d8f90000000000004000000000000000800902000000000000000000400038000400400009000800,
    }
    ```
  </Step>

  <Step title="Daten">
    Das Feld `data` speichert ein beliebiges Byte-Array. Sein Inhalt hängt vom
    Konto-Typ ab:

    - **Program accounts**: Enthält ausführbaren Bytecode oder die Adresse eines
      [program data account](/docs/core/accounts/account-types#program-data-accounts),
      das den Bytecode speichert.
    - **Data accounts**: Enthält programmdefinierte Statusdaten. Das besitzende
      Programm definiert das Serialisierungsformat.

    Das Lesen von Kontodaten erfordert zwei Schritte:

    1. Abrufen des Kontos über seine [Adresse](#konten-adresse).
    2. Deserialisieren des Feldes `data` von rohen Bytes in die programmdefinierte
       Datenstruktur.

    ```rust title="Account Examples" focus={4,8,14,18}
    // Example Token Mint Account
    Account {
        lamports: 1461600,
        data.len: 82,
        owner: TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb,
        executable: false,
        rent_epoch: 0,
        data: 010000001e213c90625a7e643d9555bb01b6c3fe6416d7afd523ce8c7ddd9b923ceafb9d00000000000000000901010000001e213c90625a7e643d9555bb01b6,
    }

    // Example Token Program Account
    Account {
        lamports: 4513200894,
        data.len: 134080,
        owner: BPFLoader2111111111111111111111111111111111,
        executable: true,
        rent_epoch: 18446744073709551615,
        data: 7f454c460201010000000000000000000300f70001000000d8f90000000000004000000000000000800902000000000000000000400038000400400009000800,
    }
    ```
  </Step>

  <Step title="Eigentümer">
    Das Feld `owner` enthält die Programm-ID (öffentlicher Schlüssel) des Programms,
    das dieses Konto besitzt.

    Das Eigentümerprogramm ist das einzige Programm, das:

    - Das Feld `data` des Kontos ändern kann
    - Lamports vom Feld `lamports` des Kontos abziehen kann

    Jedes Programm kann Lamports zu einem anderen Konto hinzufügen, aber nur der
    Eigentümer kann Lamports davon abziehen.

    Bei Programmkonten ist der Eigentümer das
    [Loader-Programm](/docs/core/programs/builtin-programs#loader-programs) des
    Kontos.

    ```rust title="Account Examples" focus={5,15}
    // Example Token Mint Account
    Account {
        lamports: 1461600,
        data.len: 82,
        owner: TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb,
        executable: false,
        rent_epoch: 0,
        data: 010000001e213c90625a7e643d9555bb01b6c3fe6416d7afd523ce8c7ddd9b923ceafb9d00000000000000000901010000001e213c90625a7e643d9555bb01b6,
    }

    // Example Token Program Account
    Account {
        lamports: 4513200894,
        data.len: 134080,
        owner: BPFLoader2111111111111111111111111111111111,
        executable: true,
        rent_epoch: 18446744073709551615,
        data: 7f454c460201010000000000000000000300f70001000000d8f90000000000004000000000000000800902000000000000000000400038000400400009000800,
    }
    ```
  </Step>

  <Step title="Ausführbar">
    Das Feld `executable` ist ein boolescher Wert, der bestimmt, ob das Konto ein
    [Programmkonto](/docs/core/accounts/account-types#program-accounts) oder ein
    [Datenkonto](/docs/core/accounts/account-types#data-accounts) ist:

    - `true` = Programmkonto (enthält ausführbaren Code)
    - `false` = Datenkonto (speichert Zustand)

  </Step>

  <Step title="Rent-Epoche">
    **Das Feld `rent_epoch` ist veraltet.**

    Früher wurde verfolgt, wann einem Konten automatisch lamport abgezogen wurden, um
    die Kosten für die Speicherung seiner Daten onchain zu decken. Da die laufende rent-Erhebung deaktiviert ist,
    wird `rent_epoch` für alle neuen Konten, die das Mindestspeicherguthaben erfüllen, auf `u64::MAX` gesetzt.

    ```rust title="Account Examples" focus={7,17}
    // Example Token Mint Account
    Account {
    ```
