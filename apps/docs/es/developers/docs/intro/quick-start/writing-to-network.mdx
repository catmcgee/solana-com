title: Escribiendo en la red
description:
  Learn how to write data to the Solana network by sending transactions and
  instructions. Follow step-by-step examples to transfer SOL and create a token
  mint using Solana Kit.
---

En la sección anterior, aprendiste cómo
[leer datos de la red de Solana](/developers/docs/intro/quick-start/reading-from-network)
mediante la consulta de cuentas. Para escribir datos en la red de Solana se
necesita una [transacción](/developers/docs/core/transactions). Una transacción contiene
una o más [instrucciones](/developers/docs/core/instructions), y cada instrucción invoca un
programa.

Los programas definen la lógica de negocio de cada instrucción. Cuando envías
una transacción, el runtime de Solana ejecuta las instrucciones de la
transacción en orden. Las transacciones son atómicas: o todas las instrucciones
de la transacción se ejecutan correctamente, o la transacción completa falla.

Los ejemplos de esta sección muestran cómo:

1. Transferir SOL entre cuentas
2. Crear un nuevo token mint

## Transferir SOL

El ejemplo a continuación transfiere SOL de una cuenta a otra. Solo el programa designado como propietario de una cuenta puede modificar los datos de esa cuenta o deducir lamports de su saldo. Las cuentas de billetera son propiedad del
[System Program](/developers/docs/core/programs/builtin-programs#the-system-program), por lo que transferir SOL entre cuentas de billetera requiere una instrucción que invoque la instrucción
[transfer](https://github.com/anza-xyz/agave/blob/v2.1.11/programs/system/src/system_processor.rs#L183-L213)
del System Program. La cuenta de origen también debe firmar la transacción.

```ts title="Transfer SOL"
import { createClient, generateKeyPairSigner, lamports } from "@solana/kit";
import { solanaRpc, rpcAirdrop } from "@solana/kit-plugin-rpc";
import { generatedPayer, airdropPayer } from "@solana/kit-plugin-signer";
import { getTransferSolInstruction } from "@solana-program/system";

const client = await createClient()
  .use(generatedPayer())
  .use(
    solanaRpc({
      rpcUrl: "http://localhost:8899",
      rpcSubscriptionsUrl: "ws://localhost:8900"
    })
  )
  .use(rpcAirdrop())
  .use(airdropPayer(lamports(1_000_000_000n)));

const receiver = await generateKeyPairSigner();

const transferInstruction = getTransferSolInstruction({
  source: client.payer,
  destination: receiver.address,
  amount: lamports(10_000_000n)
});

const result = await client.sendTransaction([transferInstruction]);

console.log("Transaction Signature:", result.context.signature);

const { value: senderBalance } = await client.rpc
  .getBalance(client.payer.address)
  .send();
const { value: receiverBalance } = await client.rpc
  .getBalance(receiver.address)
  .send();

console.log("Sender Balance:", senderBalance);
console.log("Receiver Balance:", receiverBalance);
```

<Note>
  **`createClient`**

  Crea un cliente Kit para el validator local. `generatedPayer()` agrega un
  firmante pagador, `solanaRpc()` agrega capacidades de RPC y envío de
  transacciones, `rpcAirdrop()` agrega `client.airdrop`, y `airdropPayer()`
  financia al pagador con SOL de prueba.

  **`receiver`**

  Genera un firmante para la cuenta que recibirá SOL. El receptor no necesita
  firmar esta transferencia. Si la dirección del receptor aún no tiene una cuenta,
  recibir SOL crea una cuenta del sistema en esa dirección.

  **`transferInstruction`**

  Construye la instrucción de System Program que transfiere lamports del pagador
  del cliente al receptor.

  **`sendTransaction`**

  Envía la instrucción como una transacción. El cliente de Kit obtiene un
  blockhash reciente, establece el pagador de comisiones, firma con los firmantes
  requeridos, envía la transacción y espera la confirmación.

  **`balances`**

  Obtiene los saldos del remitente y del receptor una vez confirmada la
  transacción.
</Note>

## Crear un token

El siguiente ejemplo crea un nuevo mint de token usando el
[Token Extensions Program](/developers/docs/tokens/extensions). Una mint account es la
cuenta que define la configuración global de un token, como los decimales, el
suministro, la autoridad de emisión y la autoridad de congelación.

Crear una mint account requiere dos instrucciones:

1. Invocar el System Program para crear una nueva cuenta propiedad del Token
   Extensions Program.
2. Invocar el Token Extensions Program para inicializar esa cuenta como un mint.

```ts title="Create mint account"
import { createClient, generateKeyPairSigner, lamports } from "@solana/kit";
import { solanaRpc, rpcAirdrop } from "@solana/kit-plugin-rpc";
import { generatedPayer, airdropPayer } from "@solana/kit-plugin-signer";
import { getCreateAccountInstruction } from "@solana-program/system";
import {
  fetchMint,
  getInitializeMintInstruction,
  getMintSize,
  TOKEN_2022_PROGRAM_ADDRESS
} from "@solana-program/token-2022";

const client = await createClient()
  .use(generatedPayer())
  .use(
    solanaRpc({
      rpcUrl: "http://localhost:8899",
      rpcSubscriptionsUrl: "ws://localhost:8900"
    })
  )
  .use(rpcAirdrop())
  .use(airdropPayer(lamports(1_000_000_000n)));

const mint = await generateKeyPairSigner();

const space = BigInt(getMintSize());

const rent = await client.rpc.getMinimumBalanceForRentExemption(space).send();

const createAccountInstruction = getCreateAccountInstruction({
  payer: client.payer,
  newAccount: mint,
  space,
  lamports: rent,
  programAddress: TOKEN_2022_PROGRAM_ADDRESS
});

const initializeMintInstruction = getInitializeMintInstruction({
  mint: mint.address,
  decimals: 2,
  mintAuthority: client.payer.address,
  freezeAuthority: client.payer.address,
  tokenProgram: TOKEN_2022_PROGRAM_ADDRESS
});

const result = await client.sendTransaction([
  createAccountInstruction,
  initializeMintInstruction
]);

console.log("Mint Address:", mint.address);
console.log("Transaction Signature:", result.context.signature);

const mintAccount = await fetchMint(client.rpc, mint.address);
console.log("Mint Account:", mintAccount);
```

<Note>
  **`createClient`**

  Crea y financia un cliente Kit para el validator local. El pagador financiado
  cubre el rent de la cuenta y las comisiones de transacción.

  **`mint`**

  Genera un firmante para usar como dirección de la nueva mint account. El
  firmante autoriza la creación de esa cuenta.

  **`space`**

  Calcula el número de bytes requeridos para una mint account sin extensiones.

  **`rent`**

  Calcula los lamports necesarios para que la mint account esté exenta de rent.

  **`createAccountInstruction`**

  Construye la instrucción del System Program que crea la mint account y la asigna
  al Token Extensions Program.

  **`initializeMintInstruction`**

  Construye la instrucción del Token Extensions Program que escribe los datos
  iniciales del mint en la nueva cuenta.

  **`sendTransaction`**

  Envía ambas instrucciones como una sola transacción. El orden de las
  instrucciones importa: la cuenta debe crearse antes de que pueda inicializarse.

  **`mintAccount`**

  Obtén el mint account después de la confirmación. El helper lee la cuenta y
  deserializa el campo de datos del mint account en el tipo Mint.
</Note>

  </Step>
</Steps>

<Info>
  Estos ejemplos usan `generatedPayer()` para crear un keypair desechable para
  pruebas locales. Las aplicaciones en producción nunca deben almacenar claves
  privadas en texto plano dentro del código — delega la firma a un backend de
  gestión de claves. Consulta [Firma en
  Producción](/developers/docs/core/transactions/signing-in-production).
</Info>
