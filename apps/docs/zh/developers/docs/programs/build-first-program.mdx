本快速入门使用由 `anchor init` 生成的
[Anchor 框架](https://www.anchor-lang.com/docs)入门项目。您将在本地创建该项目，运行其测试，构建程序，并了解 Anchor 生成的程序代码。

## 前提条件

在开始之前，请[安装 Solana 开发工具](/developers/docs/quickstart)。安装内容包括 Rust、Solana
CLI 和 Anchor CLI。

本模板需要使用 Anchor CLI 1.1.2 或更高版本。检查已安装的版本：

```bash Terminal
anchor --version
```

<Steps titleSize="h3">

<Step title="创建项目">

在终端中运行以下命令：

```bash Terminal
anchor init my-program
cd my-program
```

入门项目在 `programs/my-program`
下包含一个 Solana 程序。该程序包含两条指令：一条用于初始化计数器账户，另一条用于递增计数器。

模板的某些部分展示了常见的 Solana 程序模式：派生 [PDA](/developers/docs/core/pda)
账户地址、通过 Cross Program
Invocation（[CPI](/developers/docs/core/cpi)）转移 SOL，以及使用自定义错误检查在条件不满足时终止指令。

<Step title="构建程序">

运行 `anchor build` 以编译入门程序：

```bash Terminal
anchor build
```

编译后的程序将写入 `target/deploy/my_program.so`。程序部署后，该 `.so`
文件的内容将存储在链上账户中。

</Step>

<Step title="运行测试">

运行默认测试：

```bash Terminal
anchor test
```

此模板的 `Anchor.toml` 使用 Rust 测试命令：

```toml Anchor.toml
skip_local_validator = true

[scripts]
test = "cargo test"
```

该测试将已编译的程序加载到 [LiteSVM](https://www.litesvm.com/)
中，创建一个付款方，发送 `initialize` 和 `increment`
指令，然后检查计数器账户状态。

运行 `anchor test` 也会编译程序，因此在本地测试时无需先运行 `anchor build`。

</Step>

<Step title="部署程序">

本地测试是最快速的反馈方式。当您准备好部署到网络（例如 devnet）时，请先构建，再部署到集群。

部署 Solana 程序需要 SOL，因为程序存储在账户中，而账户必须为其占用的空间支付费用。在 devnet 上，可通过
[Solana Faucet](https://faucet.solana.com/) 或 Solana CLI 免费获取 devnet SOL：

```bash Terminal
solana airdrop 2 --url devnet
```

```bash Terminal
anchor build
anchor deploy --provider.cluster devnet
```

</Step>

</Steps>

## 源文件

`src` 目录包含 Solana 程序。Anchor 的
[程序结构](https://www.anchor-lang.com/docs/basics/program-structure)
文档说明了此处使用的核心宏，包括 `declare_id!`、
`#[program]`、`#[derive(Accounts)]` 和
`#[account]`。本节将逐步介绍模板文件。

### lib.rs

`lib.rs`
是程序入口点。它连接各源文件，定义程序地址，并定义用户可调用的程序指令。

```rust programs/my-program/src/lib.rs wrap
pub mod constants;
pub mod error;
pub mod instructions;
pub mod state;

use anchor_lang::prelude::*;

pub use constants::*;
pub use instructions::*;
pub use state::*;

declare_id!("82sFkffP9wxwpyfZyeaKHH2chQoJPUGsJZSPi9mrUuXd");

#[program]
pub mod my_program {
    use super::*;

    pub fn initialize(ctx: Context<Initialize>) -> Result<()> {
        crate::instructions::initialize::handle_initialize(ctx)
    }

    pub fn increment(ctx: Context<Increment>) -> Result<()> {
        crate::instructions::increment::handle_increment(ctx)
    }
}
```

<Note>
  **`pub mod constants`**

  `pub mod constants` 将 `constants.rs`
  纳入程序 crate。这里存放模板中共享的程序值，例如 PDA
  seed、转账金额和计数器最大值。

  **`pub mod error`**

  `pub mod error` 将 `error.rs`
  纳入程序 crate。该文件定义了程序在指令无效时可返回的自定义错误。

  **`pub mod instructions`**

  `pub mod instructions` 将 `instructions.rs` 纳入程序 crate。该文件充当
  `src/instructions/` 中各指令专属文件的索引。

  **`pub mod state`**

  `pub mod state` 将 `state.rs`
  纳入程序 crate。该文件定义了此程序所拥有账户的数据布局，包括 `Counter`
  账户。

  **`anchor_lang::prelude`**

  `anchor_lang::prelude::*` 导入用于定义 Solana 程序的 Anchor 类型和宏，包括
  `Context`、`Result`、`Pubkey`、`Account`、`Signer`
  以及 Anchor 账户属性。

  `pub use`
  这几行将子模块中的公开项暴露到 crate 根目录，从而使指令入口点更简洁，例如使用
  `Context<Initialize>` 而非更长的模块路径。

  **`declare_id!`**

  `declare_id!` 定义程序地址。它应与 `Anchor.toml`、已部署的 program
  account 以及所有调用该程序的用户或测试中的地址保持一致。

  **`#[program]`**

  `#[program]`
  指示 Anchor 生成 Solana 程序入口点和指令分发代码。该模块中的公开函数将成为用户可调用的指令。

  **`pub fn initialize`, `pub fn increment`**

  `initialize` 和 `increment` 是用户可调用的两个指令名称。每个指令接收一个
  `Context<T>`。`Context`
  内的类型定义了该指令所需的账户，Anchor 会在指令执行前对这些账户进行验证。

  **`handle_initialize`, `handle_increment`**

  处理函数包含指令的逻辑。
</Note>

### constants.rs

`constants.rs` 将共享值集中在一处。在此模板中， `COUNTER_SEED`
用于派生计数器 PDA，`HELLO_WORLD_LAMPORTS` 在初始化时转入，`MAX_COUNT`
在递增前进行检查。

```rust programs/my-program/src/constants.rs wrap
use anchor_lang::prelude::*;

#[constant]
pub const COUNTER_SEED: &[u8] = b"counter";

#[constant]
pub const HELLO_WORLD_LAMPORTS: u64 = 1;

#[constant]
pub const MAX_COUNT: u64 = 10;
```

<Note>
  **`#[constant]`**

  `#[constant]`
  告诉 Anchor 将该值包含在程序 IDL 中。这使重要的程序常量对生成的客户端和工具可见。

  **`COUNTER_SEED`**

  `COUNTER_SEED`
  是用于派生计数器 PDA 的字节字符串。程序和测试都使用此 seed，因此无需存储单独的 keypair 即可确定账户地址。此模板使用一个固定的 seed，因此程序只有一个计数器地址。实际程序通常会在 seeds 中包含用户地址或其他标识符，以创建多个关联账户。

  **`HELLO_WORLD_LAMPORTS`**

  `HELLO_WORLD_LAMPORTS` 是在 `initialize`
  中从付款方转入计数器账户的 lamport 数量。该值有意设置得很小，因为此模板旨在演示对 System
  Program 的 CPI 调用。

  **`MAX_COUNT`**

  `MAX_COUNT` 是由 `increment`
  检查的上限值。将其定义在此处，可让程序、测试和生成的 IDL 共享同一个规则名称。
</Note>

        #[account(

    - `COUNTER_SEED` 用于推导计数器 PDA 地址。
    - `HELLO_WORLD_LAMPORTS`
      设置从付款方转入计数器账户的金额。
  </div>

### state.rs

`state.rs`
为程序创建并拥有的账户定义自定义数据类型。程序定义了创建、初始化和更新该数据的指令，但计数器数据并不存储在程序本身内，而是存储在一个拥有独立地址的单独账户中。

```rust programs/my-program/src/state.rs wrap
use anchor_lang::prelude::*;

#[account]
#[derive(InitSpace)]
pub struct Counter {
    pub count: u64,
    pub authority: Pubkey,
}
```

<Note>
  **`#[account]`**

  `#[account]`
  告知 Anchor 此结构体是可存储在该程序所拥有的链上账户中的数据。Anchor 使用它来序列化、反序列化和验证
  `Counter` 账户。

  **`InitSpace`**

  `InitSpace` 让 Anchor 计算
  `Counter::INIT_SPACE`，即此结构体字段所需的字节数。创建账户时，8 字节的 Anchor 账户鉴别器将单独添加。

  **`count`**

  `count` 是存储在账户数据中的计数器值。

  **`authority`**

  `authority` 存储允许递增计数器的地址。`initialize`
  写入该地址，`increment` 则要求该地址进行签名。
</Note>

<Columns cols={2}>
  <div>
    ```rust initialize.rs highlight={4,12-13} wrap

        init,
        payer = payer,
        space = 8 + Counter::INIT_SPACE,
        seeds = [COUNTER_SEED],
        bump

    pub counter: Account<'info, Counter>,
    // ...

    pub fn handle_initialize(ctx: Context<Initialize>) -> Result<()> {
        ctx.accounts.counter.count = 0;
        ctx.accounts.counter.authority = ctx.accounts.payer.key();

        Ok(())
    }
    ```

    ```rust increment.rs highlight={4} wrap

        // ...

        ctx.accounts.counter.count += 1;
        Ok(())
    }
    ```
  </div>

  <div>
    `state.rs` 定义了 `Counter` 账户数据。指令文件在创建和更新账户时使用该类型：

    - `Counter::INIT_SPACE` 根据 `state.rs`
      中定义的字段为账户分配空间。
    - `count` 和 `authority`
      是账户初始化时写入的字段值。
    - `count += 1` 在验证通过后更新存储的计数器值。
  </div>
</Columns>

### error.rs

`error.rs`
定义了程序的自定义错误。在此模板中，这些错误展示了当调用方无权更新计数器，或计数器已达到
`MAX_COUNT` 时，指令处理程序如何停止执行。

```rust programs/my-program/src/error.rs wrap
use anchor_lang::prelude::*;

#[error_code]
pub enum ErrorCode {
    #[msg("Only the counter authority can update this counter")]
    Unauthorized,
    #[msg("Counter has reached the maximum value")]
    CounterOverflow,
}
```

<Note>
  **`#[error_code]`**

  `#[error_code]`
  告知 Anchor 将这些变体转换为自定义程序错误。客户端和测试可以使用这些错误，而无需从原始错误码中猜测。

  **`Unauthorized`**

  当交易签名者不是计数器账户中存储的授权方时，将返回 `Unauthorized`。

  **`CounterOverflow`**

  当递增操作将违反程序的 `MAX_COUNT` 规则时，将返回 `CounterOverflow`。
</Note>

<Columns cols={2}>
  <div>
    ```rust increment.rs highlight={5,9} wrap
    pub fn handle_increment(ctx: Context<Increment>) -> Result<()> {
        require_keys_eq!(
            ctx.accounts.counter.authority,
            ctx.accounts.authority.key(),
            ErrorCode::Unauthorized,
        );
        require!(
            ctx.accounts.counter.count < MAX_COUNT,
            ErrorCode::CounterOverflow,
        );

        ctx.accounts.counter.count += 1;
        msg!("Hello, world! Counter is now {}", ctx.accounts.counter.count);
        Ok(())
    }
    ```
  </div>

  <div>
    `error.rs` 列出了指令可能返回的错误：

    - 当签名者不是计数器账户中存储的授权方时，将返回
      `ErrorCode::Unauthorized`。
    - 当计数器已达到 `MAX_COUNT` 时，将返回
      `ErrorCode::CounterOverflow`。
  </div>
</Columns>

### instructions.rs

`instructions.rs` 将指令文件连接到程序 crate，使 `lib.rs` 能够访问
`initialize` 和 `increment`
指令代码。每个指令文件定义该指令所需的账户，以及在 Anchor 验证这些账户后执行的处理逻辑。

```rust programs/my-program/src/instructions.rs wrap
pub mod initialize;
pub mod increment;

pub use initialize::*;
pub use increment::*;
```

<Note>
  **`pub mod initialize`**

  `pub mod` 行使 `src/instructions/initialize.rs` 和
  `src/instructions/increment.rs` 成为程序 crate 的一部分。

  **`pub use initialize`**

  `pub use` 行重新导出这些文件中的公开项，使指令账户结构体和处理函数可通过
  `instructions` 模块访问。
</Note>

### initialize.rs

`initialize.rs`
定义创建计数器账户所需的账户，并写入账户的初始值。`#[derive(Accounts)]`
结构体使用 Anchor
[账户约束](https://www.anchor-lang.com/docs/references/account-constraints)
来指定所需账户以及新计数器账户的创建方式。

```rust programs/my-program/src/instructions/initialize.rs wrap
use anchor_lang::prelude::*;

use crate::{constants::*, state::Counter};

#[derive(Accounts)]
pub struct Initialize<'info> {
    #[account(mut)]
    pub payer: Signer<'info>,
    #[account(
        init,
        payer = payer,
        space = 8 + Counter::INIT_SPACE,
        seeds = [COUNTER_SEED],
        bump
    )]
    pub counter: Account<'info, Counter>,
    pub system_program: Program<'info, System>,
}

pub fn handle_initialize(ctx: Context<Initialize>) -> Result<()> {
    ctx.accounts.counter.count = 0;
    ctx.accounts.counter.authority = ctx.accounts.payer.key();

    let cpi_accounts = anchor_lang::system_program::Transfer {
        from: ctx.accounts.payer.to_account_info(),
        to: ctx.accounts.counter.to_account_info(),
    };
    let cpi_ctx = CpiContext::new(anchor_lang::system_program::ID, cpi_accounts);
    anchor_lang::system_program::transfer(cpi_ctx, HELLO_WORLD_LAMPORTS)?;

    msg!("Hello, world! Counter initialized");
    Ok(())
}
```

<Note>
  此文件导入共享常量和 `Counter`
  账户类型。该指令使用这些定义来推导 PDA、选择转账金额，并以正确的数据大小分配账户。

  **`derive(Accounts)`**

  `Initialize` 是 `initialize`
  指令的账户上下文。结构体中的每个字段代表调用该指令时必须包含的一个独立账户。Anchor 在处理程序运行之前使用该结构体对传入的账户进行验证。

  **`#[account(mut)]`**

  `#[account(mut)]`
  告知 Anchor 付款账户必须是可写的。这是必须的，因为账户创建和转账 CPI 都会从付款账户中扣除 lamport。

  **`Signer<'info>`**

  `Signer<'info>` 告知 Anchor 付款方必须对交易进行签名。

  **`#[account(`**

  `#[account(...)]` 块告知 Anchor 如何在处理程序运行之前创建并验证计数器账户。

  **`init`**

  `init` 指示 Anchor 在处理程序运行之前创建 `counter`
  账户。新账户由本程序拥有，因此本程序可以在其中存储 `Counter` 数据。

  **`payer = payer`**

  `payer = payer` 指定 `payer` 账户作为创建新计数器账户的付款方。

  **`space = 8 + Counter::INIT_SPACE`**

  `space = 8 + Counter::INIT_SPACE` 为 Anchor 的账户判别器以及来自 `state.rs`
  的 `Counter`
  字段分配字节空间。判别器帮助 Anchor 在读取账户之前确认其存储的是预期类型。

  **`seeds = [COUNTER_SEED]`**

  `seeds = [COUNTER_SEED]`
  表示计数器账户地址必须是由此 seed 和程序 ID 派生出的 PDA。使用单一固定 seed 时，该程序只有一个计数器 PDA。若要在实际程序中创建独立的计数器，通常需要添加另一个 seed，例如用户地址。

  **`bump`**

  `bump`
  指示 Anchor 查找并验证 PDA 的 bump 值，即使派生地址作为有效 PDA 所需的额外字节。

  **`Account<'info, Counter>`**

  `Account<'info, Counter>` 指示 Anchor 将账户数据视为来自 `state.rs` 的
  `Counter` 类型。Anchor 同时还会验证该账户归本程序所有。

  **`Program<'info, System>`**

  `Program<'info, System>` 要求调用方提供 System Program。Anchor 将其用于
  `init` 账户创建约束。处理程序中的转账 CPI 也会调用 System Program。

  **`handle_initialize`**

  处理程序在 Anchor 验证账户并创建计数器账户之后运行，因此可以安全地写入账户的初始数据。

  **`counter.count = 0`**

  将计数器账户中的 `count` 字段设置为 `0`。

  **`counter.authority = ctx.accounts.payer.key()`**

  将计数器账户中的 `authority` 字段设置为付款方的地址。

  **`system_program::Transfer`**

  这些是传递给 System Program 转账指令的账户。此转账 Cross Program
  Invocation 仅用于演示 CPI 如何将账户传递给另一个程序。

  **`CpiContext::new`**

  `CpiContext` 将目标程序和所需账户打包，用于 Cross Program
  Invocation。创建上下文通过将您要调用的程序与该程序所需的账户配对来准备 CPI。

  **`system_program::transfer`**

  此 CPI 调用 System Program 的转账指令，将 `HELLO_WORLD_LAMPORTS`
  从付款方转移到计数器账户。

  **`msg!`**

  `msg!` 在程序被调用时向程序日志写入一条消息。
</Note>

### increment.rs

`increment.rs`
定义了更新现有计数器账户所需的账户。处理程序会检查签名者是否为已存储的授权方，检查计数是否已达到指定的
`MAX_COUNT`，然后递增计数。

```rust programs/my-program/src/instructions/increment.rs wrap
use anchor_lang::prelude::*;

use crate::{constants::*, error::ErrorCode, state::Counter};

#[derive(Accounts)]
pub struct Increment<'info> {
    #[account(
        mut,
        seeds = [COUNTER_SEED],
        bump
    )]
    pub counter: Account<'info, Counter>,
    pub authority: Signer<'info>,
}

pub fn handle_increment(ctx: Context<Increment>) -> Result<()> {
    require_keys_eq!(
        ctx.accounts.counter.authority,
        ctx.accounts.authority.key(),
        ErrorCode::Unauthorized,
    );
    require!(
        ctx.accounts.counter.count < MAX_COUNT,
        ErrorCode::CounterOverflow,
    );

    ctx.accounts.counter.count += 1;
    msg!("Hello, world! Counter is now {}", ctx.accounts.counter.count);
    Ok(())
}
```

<Note>
  **`derive(Accounts)`**

  `Increment` 是 `increment`
  指令的账户上下文。Anchor 使用它来验证可变计数器账户和所需的签名者。

  **`mut`**

  `mut` 告诉 Anchor 计数器账户必须是可写的，因为处理程序会更新存储的
  `count` 值。

  **`seeds = [COUNTER_SEED]`**

  `seeds = [COUNTER_SEED]`
  验证所提供的计数器账户是否为从此 seed 和程序 ID 派生的 PDA。

  **`bump`**

  `bump` 告诉 Anchor 查找并验证计数器账户的 PDA bump。

  **`Account<'info, Counter>`**

  `Account<'info, Counter>` 告诉 Anchor 将账户数据反序列化为 `state.rs` 中的
  `Counter` 类型。Anchor 还会检查该账户是否归此程序所有。

  **`Signer`**

  `Signer`
  要求权限方提供签名。处理程序随后将此签名者的地址与计数器账户中存储的权限地址进行比对。

  **`handle_increment`**

  处理程序在 Anchor 验证账户列表、检查所有权并反序列化计数器账户后运行。

  **`require_keys_eq!`**

  `require_keys_eq!`
  比较两个公钥，若签名者地址与计数器账户中存储的权限地址不匹配，则终止指令。这是该模板的应用层授权规则。

  **`require!`**

  `require!` 检查一个布尔规则，若计数器已达到 `MAX_COUNT`，则以
  `CounterOverflow`
  终止指令。该模板规则演示了自定义错误及在修改数据前提前失败的机制。

  **`count += 1`**

  只有在两项检查均通过后，处理程序才会更新计数器账户数据。若任意一项检查失败，则交易失败，账户不会被更改。

  **`msg!`**

  `msg!` 在程序被调用时向程序日志写入一条消息。
</Note>

```rust programs/my-program/tests/test_initialize.rs wrap
use {
    anchor_lang::{
        prelude::Pubkey,
        solana_program::{instruction::Instruction, system_program},
        AccountDeserialize, InstructionData, ToAccountMetas,
    },
    litesvm::LiteSVM,
    solana_keypair::Keypair,
    solana_message::{Message, VersionedMessage},
    solana_signer::Signer,
    solana_transaction::versioned::VersionedTransaction,
};

#[test]
fn test_initialize() {
    let program_id = my_program::id();
    let payer = Keypair::new();
    let counter = Pubkey::find_program_address(
        &[my_program::constants::COUNTER_SEED],
        &program_id,
    )
    .0;
    let mut svm = LiteSVM::new();
    let bytes = include_bytes!(concat!(
        env!("CARGO_TARGET_TMPDIR"),
        "/../deploy/my_program.so"
    ));
    svm.add_program(program_id, bytes).unwrap();
    svm.airdrop(&payer.pubkey(), 1_000_000_000).unwrap();

    let instruction = Instruction::new_with_bytes(
        program_id,
        &my_program::instruction::Initialize {}.data(),
        my_program::accounts::Initialize {
            payer: payer.pubkey(),
            counter,
            system_program: system_program::ID,
        }
        .to_account_metas(None),
    );

    let blockhash = svm.latest_blockhash();
    let msg = Message::new_with_blockhash(&[instruction], Some(&payer.pubkey()), &blockhash);
    let tx = VersionedTransaction::try_new(VersionedMessage::Legacy(msg), &[&payer]).unwrap();

    let res = svm.send_transaction(tx);
    assert!(res.is_ok());

    let counter_account = svm.get_account(&counter).unwrap();
    let mut data: &[u8] = &counter_account.data;
    let counter_state = my_program::state::Counter::try_deserialize(&mut data).unwrap();
    assert_eq!(counter_state.count, 0);
    assert_eq!(counter_state.authority, payer.pubkey());

    let instruction = Instruction::new_with_bytes(
        program_id,
        &my_program::instruction::Increment {}.data(),
        my_program::accounts::Increment {
            counter,
            authority: payer.pubkey(),
        }
        .to_account_metas(None),
    );

    let blockhash = svm.latest_blockhash();
    let msg = Message::new_with_blockhash(&[instruction], Some(&payer.pubkey()), &blockhash);
    let tx = VersionedTransaction::try_new(VersionedMessage::Legacy(msg), &[&payer]).unwrap();

    let res = svm.send_transaction(tx);
    assert!(res.is_ok());

    let counter_account = svm.get_account(&counter).unwrap();
    let mut data: &[u8] = &counter_account.data;
    let counter_state = my_program::state::Counter::try_deserialize(&mut data).unwrap();
    assert_eq!(counter_state.count, 1);
    assert_eq!(counter_state.authority, payer.pubkey());
}
```

<Note>
  **`litesvm::LiteSVM`**

  `LiteSVM`
  是一个用于测试的进程内 Solana 虚拟机。它允许测试注册已编译的程序、创建账户、发送交易并检查账户状态，而无需启动 validator 进程。

  **`let program_id`**

  测试通过 `my_program::id()` 从 `declare_id!`
  值中获取程序地址，并为测试交易创建一个新的 keypair 付款方。

  **`Pubkey::find_program_address`**

  计数器地址由程序使用的同一 `COUNTER_SEED` 派生而来。这使测试能够针对
  `initialize.rs` 所期望的 PDA。

  **`include_bytes!`**

  `include_bytes!` 读取构建生成的已编译 `my_program.so`
  文件。这些字节是 LiteSVM 将在测试中运行的可执行程序代码。

  **`svm.add_program`**

  `svm.add_program`
  将已编译的程序字节注册到 LiteSVM 中的程序地址。空投为付款方提供足够的本地 SOL 以支付交易和账户创建费用。

  **`let instruction`**

  `Instruction::new_with_bytes`
  创建一条调用程序的指令。它包含程序 ID、instruction data 和指令账户。

  **`svm.latest_blockhash`**

  每笔 Solana 交易都需要一个最新的区块哈希。在此测试中，LiteSVM 提供一个用于交易的区块哈希。

  **`Message::new_with_blockhash`**

  消息包含指令、手续费付款方和区块哈希。这是将被签名的交易数据。

  **`VersionedTransaction::try_new`**

  `VersionedTransaction::try_new`
  使用付款方 keypair 对消息进行签名。付款方签名是因为它支付交易手续费并为新计数器账户提供资金。

  **`svm.send_transaction`**

  `svm.send_transaction` 在 LiteSVM 中执行交易。

  **`svm.get_account`**

  交易执行后，测试直接从 LiteSVM 读取计数器账户，以便检查账户数据。

  **`Counter::try_deserialize`**

  计数器账户存储序列化数据。`Counter::try_deserialize`
  验证 Anchor 的账户鉴别器，并将账户数据还原为来自 `state.rs` 的 `Counter`
  类型。

  **`assert_eq!(counter_state.count, 0)`**

  `initialize` 成功后，测试对计数器账户进行反序列化，并验证初始状态与
  `handle_initialize` 写入的内容一致。

  **`assert_eq!(counter_state.count, 1)`**

  `increment` 成功后，同一计数器账户的 `count` 应设置为
  `1`，同时保持相同的权限。
</Note>

根目录项目文件告诉 Anchor 和 Cargo 如何构建、测试和部署程序。完整参考请参阅 Anchor 文档中的

[Anchor CLI](https://www.anchor-lang.com/docs/references/cli)。

skip_local_validator = true

[toolchain]

resolution = true

my_program = "82sFkffP9wxwpyfZyeaKHH2chQoJPUGsJZSPi9mrUuXd"

[provider]
cluster = "localnet"
wallet = "~/.config/solana/id.json"

[scripts]

[hooks]

<Note>
  **`skip_local_validator`**

  `skip_local_validator = true` 告诉 Anchor 不要为 `anchor test`
  启动 validator。Rust 测试使用 LiteSVM 代替。

  **`programs.localnet`**

  `[programs.localnet]` 将 Rust crate 名称映射到用于本地构建和测试的 program
  account 地址。

  **`provider`**

  `[provider]` 为 `anchor deploy` 等命令设置默认集群和钱包。

  **`scripts`**

  `[scripts]` 更改 `anchor test` 的运行内容。在此模板中，`anchor test` 会运行
  `cargo test`。
</Note>
