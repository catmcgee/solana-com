---
title: sendTransaction RPC 方法
sidebarTitle: sendTransaction
---

提交已签名的交易到集群进行处理。

此方法不会以任何方式更改交易；它将客户端创建的交易原样传递到节点。

如果节点的 RPC 服务接收到交易，此方法会立即成功，而无需等待任何确认。此方法的成功响应并不保证交易已被集群处理或确认。

尽管 RPC 服务会合理地重试提交，但如果交易的 `recent_blockhash`
在落地之前过期，交易可能会被拒绝。

使用 [`getSignatureStatuses`](/docs/rpc/http/getsignaturestatuses)
确保交易已被处理并确认。

在提交之前，将执行以下预检：

1. 验证交易签名
2. 根据预检承诺指定的银行 slot 模拟交易。如果失败，将返回错误。如果需要，可以禁用预检。建议指定相同的承诺和预检承诺以避免混淆行为。

返回的签名是交易中的第一个签名，用于标识交易（[交易 ID](/docs/references/terminology#transaction-id)）。此标识符可以在提交之前轻松从交易数据中提取。

  ```rs Rust
  use anyhow::Result;
  use base64::{Engine as _, engine::general_purpose};
  use solana_client::{nonblocking::rpc_client::RpcClient, rpc_config::RpcSendTransactionConfig};
  use solana_sdk::{
      commitment_config::{CommitmentConfig, CommitmentLevel},
      transaction::VersionedTransaction,
  };
  use solana_transaction_status_client_types::UiTransactionEncoding;

  #[tokio::main]
  async fn main() -> Result<()> {
      let client = RpcClient::new_with_commitment(
          String::from("https://api.devnet.solana.com"),
          CommitmentConfig::confirmed(),
      );

      let b64_tx = "AbuRLtc5C9bZtAUT4F4Y2H5SRRUK1HwOFZOK3V4qm/78MDJt+M2de/RCCaI3iTyodDepmrkUWbss0XRHS0lk5AOAAQABAzfDSQC/GjcggrLsDpYz7jAlT+Gca846HqtFb8UQMM9cCWPIi4AX32PV8HrY7/1WgoRc3IATttceZsUMeQ1qx7UAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAD2dTRgcJmzcoGH1R3c2WqtHah2H19KvbC1p6BxLDqfoAQICAAEMAgAAAADKmjsAAAAAAA==";
      let tx_bytes = general_purpose::STANDARD.decode(b64_tx).unwrap();
      let tx: VersionedTransaction = bincode::deserialize(&tx_bytes).unwrap();

      let config = RpcSendTransactionConfig {
          skip_preflight: true,
          preflight_commitment: CommitmentLevel::Finalized.into(),
          encoding: UiTransactionEncoding::Base64.into(),
          max_retries: None,
          min_context_slot: None,
      };

      match client.send_transaction_with_config(&tx, config).await {
          Ok(signature) => println!("Transaction Signature: {}", signature),
          Err(err) => eprintln!("Error transferring tokens: {}", err),
      }

      Ok(())
  }
  ```

## Parameters

<ParamField body="transaction" type="string" required>
  完全签名的交易，作为编码字符串。
</ParamField>

<ParamField body="config" type="object">
  包含以下字段的配置对象：

  <Expandable title="properties" defaultOpen>
    <ParamField body="encoding" type="string" default="base58">
      Values: `base58`, `base64`

      用于交易数据的编码。值：`base58`（_较慢_，**已弃用**），或 `base64`。
    </ParamField>

    <ParamField body="skipPreflight" type="bool">
      当 `true` 时，跳过预检事务检查。默认值：`false`。
    </ParamField>

    <ParamField body="preflightCommitment" type="string">
      用于预检的承诺级别。请参阅
      [配置状态承诺](/docs/rpc#configuring-state-commitment)。默认值：`finalized`。
    </ParamField>

    <ParamField body="maxRetries" type="usize">
      RPC 节点重试将事务发送到领导者的最大次数。如果未提供此参数，RPC 节点将重试事务，直到其被最终确定或直到 blockhash 过期。
    </ParamField>

    <ParamField body="minContextSlot" type="number">
      设置执行预检事务检查的最小 slot
    </ParamField>
  </Expandable>
</ParamField>

## Result

<ResponseField name="result" type="string">
  嵌入在事务中的第一个事务签名，作为 base-58 编码字符串（[事务 ID](/docs/references/terminology#transaction-id)）
</ResponseField>
