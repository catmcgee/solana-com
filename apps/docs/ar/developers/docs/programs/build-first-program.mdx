يستخدم هذا الدليل السريع مشروع البداية الخاص بـ
[إطار عمل Anchor](https://www.anchor-lang.com/docs) الذي يُنشئه `anchor init`.
ستقوم بإنشاء المشروع محليًا، وتشغيل اختباراته، وبناء البرنامج، والتجوُّل عبر كود
البرنامج الذي يُولِّده Anchor.

## المتطلبات الأساسية

قبل أن تبدأ، [ثبِّت أدوات تطوير سولانا](/developers/docs/intro/installation). يشمل التثبيت
Rust وواجهة سطر أوامر سولانا وواجهة سطر أوامر Anchor.

استخدم الإصدار 1.1.2 أو أعلى من واجهة سطر أوامر Anchor لهذا القالب. تحقق من
الإصدار المثبت لديك:

```bash Terminal
anchor --version
```

<Steps titleSize="h3">

<Step title="إنشاء المشروع">

شغِّل الأوامر التالية في طرفيتك:

```bash Terminal
anchor init my-program
cd my-program
```

يتضمن مشروع البداية برنامج سولانا واحدًا ضمن `programs/my-program`. يحتوي
البرنامج على تعليمتين: إحداهما لتهيئة حساب عداد والأخرى لزيادة قيمة العداد.

تُوضح بعض أجزاء القالب أنماطًا شائعة في برامج سولانا: اشتقاق عناوين حسابات
[PDA](/developers/docs/core/pda)، وإجراء Cross Program Invocation ([CPI](/developers/docs/core/cpi))
لنقل SOL، واستخدام فحوصات أخطاء مخصصة لإيقاف التعليمة عند فشل أحد الشروط.

</Step>

<Step title="بناء البرنامج">

شغِّل `anchor build` لتصريف برنامج البداية:

```bash Terminal
anchor build
```

يُكتب البرنامج المُصرَّف إلى `target/deploy/my_program.so`. عند نشر البرنامج،
يُخزَّن محتوى ملف `.so` هذا في حساب على السلسلة.

</Step>

<Step title="تشغيل الاختبار">

شغّل الاختبار الافتراضي:

```bash Terminal
anchor test
```

يستخدم `Anchor.toml` الخاص بهذا القالب أمر اختبار Rust:

```toml Anchor.toml
skip_local_validator = true

[scripts]
test = "cargo test"
```

يقوم الاختبار بتحميل البرنامج المُجمَّع في [LiteSVM](https://www.litesvm.com/)،
وإنشاء دافع، وإرسال تعليمتَي `initialize` و`increment`، ثم التحقق من
حالة حساب العداد.

يقوم تشغيل `anchor test` أيضاً بتجميع البرنامج، لذا لا تحتاج إلى تشغيل
`anchor build` أولاً عند الاختبار محلياً.

</Step>

<Step title="نشر البرنامج">

تُعدّ الاختبارات المحلية أسرع حلقة للتغذية الراجعة. عندما تكون مستعداً للنشر على
شبكة، مثل devnet، قم أولاً بالبناء ثم انشر على الكلاستر.

يتطلب نشر برنامج سولانا SOL لأن البرنامج مخزّن في program account، ويجب على
الحساب دفع تكلفة المساحة التي يستخدمها. على devnet، اطلب SOL مجاني من
[Solana Faucet](https://faucet.solana.com/) أو باستخدام Solana CLI:

```bash Terminal
solana airdrop 2 --url devnet
```

```bash Terminal
anchor build
anchor deploy --provider.cluster devnet
```

</Step>

</Steps>

## الملفات المصدرية

يحتوي دليل `src` على برنامج سولانا. تشرح وثائق
[هيكل البرنامج](https://www.anchor-lang.com/docs/basics/program-structure)
الخاصة بـ Anchor الماكرو الأساسية المستخدمة هنا، بما فيها `declare_id!`،
و`#[program]`، و`#[derive(Accounts)]`، و`#[account]`. يستعرض هذا
القسم ملفات القالب.

### lib.rs

`lib.rs` هو نقطة دخول البرنامج. يربط الملفات المصدرية، ويحدد عنوان البرنامج،
ويعرّف تعليمات البرنامج التي يمكن للمستخدمين استدعاؤها.

```rust programs/my-program/src/lib.rs wrap
pub mod constants;
pub mod error;
pub mod instructions;
pub mod state;

use anchor_lang::prelude::*;

pub use constants::*;
pub use instructions::*;
pub use state::*;

declare_id!("82sFkffP9wxwpyfZyeaKHH2chQoJPUGsJZSPi9mrUuXd");

#[program]
pub mod my_program {
    use super::*;

    pub fn initialize(ctx: Context<Initialize>) -> Result<()> {
        crate::instructions::initialize::handle_initialize(ctx)
    }

    pub fn increment(ctx: Context<Increment>) -> Result<()> {
        crate::instructions::increment::handle_increment(ctx)
    }
}
```

<Note>
  **`pub mod constants`**

  `pub mod constants` يجعل `constants.rs` جزءًا من حزمة البرنامج. هذا هو
  المكان الذي يحتفظ فيه القالب بالقيم المشتركة للبرنامج، مثل seed الـ PDA، ومبلغ
  التحويل، والحد الأقصى لقيمة العداد.

  **`pub mod error`**

  `pub mod error` يجعل `error.rs` جزءًا من حزمة البرنامج. يُعرِّف هذا الملف
  الأخطاء المخصصة التي يمكن للبرنامج إرجاعها عندما تكون التعليمة غير صالحة.

  **`pub mod instructions`**

  `pub mod instructions` يجعل `instructions.rs` جزءًا من حزمة البرنامج. يعمل
  هذا الملف كفهرس للملفات الخاصة بالتعليمات في `src/instructions/`.

  **`pub mod state`**

  `pub mod state` يجعل `state.rs` جزءًا من حزمة البرنامج. يُعرِّف هذا الملف
  تخطيط البيانات للحسابات المملوكة لهذا البرنامج، بما في ذلك حساب `Counter`.

  **`anchor_lang::prelude`**

  `anchor_lang::prelude::*` يستورد أنواع Anchor ووحداته الماكروية المستخدمة
  لتعريف برنامج سولانا، بما في ذلك `Context`، و`Result`، و`Pubkey`،
  و`Account`، و`Signer`، وسمات حسابات Anchor.

  أسطر `pub use` تجعل العناصر العامة من الوحدات الفرعية متاحةً من جذر الحزمة.
  يُبقي ذلك نقاط دخول التعليمات مختصرة، مثل `Context<Initialize>` بدلاً من
  مسار وحدة أطول.

  **`declare_id!`**

  `declare_id!` يُعرِّف عنوان البرنامج. يجب أن يتطابق مع العنوان في
  `Anchor.toml`، وفي program account المنشور، وفي أي مستخدمين أو اختبارات تستدعي
  البرنامج.

  **`#[program]`**

  `#[program]` يُخبر Anchor بتوليد نقطة دخول برنامج سولانا وكود توزيع
  التعليمات. تصبح الدوال العامة في هذه الوحدة هي التعليمات التي يمكن للمستخدمين
  استدعاؤها.

  **`pub fn initialize`, `pub fn increment`**

  `initialize` و`increment` هما اسما التعليمتين اللتين يمكن للمستخدمين
  استدعاؤهما. تتلقى كل منهما `Context<T>`. يُعرِّف النوع داخل `Context`
  الحسابات المطلوبة لتلك التعليمة، ويتحقق Anchor من صحة تلك الحسابات قبل تنفيذ
  التعليمة.

  **`handle_initialize`, `handle_increment`**

  تحتوي دالة المعالج على المنطق الخاص بالتعليمات.
</Note>

داخل البرنامج نفسه لأغراض التحقق الأمني.

### constants.rs

يحتفظ `constants.rs` بالقيم المشتركة في مكان واحد. في هذا القالب، يشتق
`COUNTER_SEED` عنوان PDA الخاص بالعداد، ويُنقل `HELLO_WORLD_LAMPORTS`
أثناء التهيئة، ويُفحص `MAX_COUNT` قبل عملية الزيادة.

```rust programs/my-program/src/constants.rs wrap
use anchor_lang::prelude::*;

#[constant]
pub const COUNTER_SEED: &[u8] = b"counter";

#[constant]
pub const HELLO_WORLD_LAMPORTS: u64 = 1;

#[constant]
pub const MAX_COUNT: u64 = 10;
```

<Note>
  **`#[constant]`**

  يخبر `#[constant]` Anchor بتضمين القيمة في IDL الخاص بالبرنامج. وهذا يجعل
  ثوابت البرنامج المهمة مرئية للعملاء والأدوات التي يتم توليدها تلقائياً.

  **`COUNTER_SEED`**

  `COUNTER_SEED` هو السلسلة الثنائية المستخدمة لاشتقاق عنوان PDA الخاص
  بالعداد. يستخدم كل من البرنامج والاختبار هذا الـ seed لكي يتفقا على عنوان الحساب
  دون الحاجة إلى تخزين keypair منفصل. يستخدم هذا القالب seed ثابتاً واحداً، لذا
  يمتلك البرنامج عنوان عداد واحداً. غالباً ما تُدرج البرامج الفعلية عنوان المستخدم
  أو معرِّفاً آخر في الـ seeds لإنشاء حسابات مترابطة متعددة.

  **`HELLO_WORLD_LAMPORTS`**

  `HELLO_WORLD_LAMPORTS` هو مقدار الـ lamport المنقول من الدافع إلى حساب
  العداد داخل `initialize`. وهو صغير بشكل مقصود لأن هذا القالب يوضح استخدام
  CPI للـ System Program.

  **`MAX_COUNT`**

  `MAX_COUNT` هو الحد الأعلى الذي يفحصه `increment`. إبقاؤه هنا يمنح
  البرنامج والاختبارات وIDL المولَّد اسماً مشتركاً واحداً لهذه القاعدة.
</Note>

### state.rs

يُعرِّف `state.rs` أنواع بيانات مخصصة للحسابات التي يُنشئها البرنامج ويمتلكها.
يُعرِّف البرنامج تعليمات لإنشاء تلك البيانات وتهيئتها وتحديثها، غير أن بيانات
العداد لا تُخزَّن داخل البرنامج نفسه، بل تُخزَّن في حساب منفصل له عنوانه الخاص.

```rust programs/my-program/src/state.rs wrap
use anchor_lang::prelude::*;

#[account]
#[derive(InitSpace)]
pub struct Counter {
    pub count: u64,
    pub authority: Pubkey,
}
```

<Note>
  **`#[account]`**

  يُخبر `#[account]` برنامجَ Anchor بأن هذا الهيكل هو بيانات يمكن تخزينها في
  حساب على السلسلة تمتلكه هذا البرنامج. يستخدمه Anchor لتسلسل البيانات وفك تسلسلها
  والتحقق من صحة حسابات `Counter`.

  **`InitSpace`**

  يتيح `InitSpace` لبرنامج Anchor حساب `Counter::INIT_SPACE`، وهو عدد
  البايتات اللازمة لحقول هذا الهيكل. يُضاف محدد حساب Anchor المكوَّن من 8 بايت
  bseparately عند إنشاء الحساب.

  **`count`**

  `count` هو قيمة العداد المخزَّنة داخل بيانات الحساب.

  **`authority`**

  يخزِّن `authority` العنوانَ المسموح له بزيادة العداد. يكتب `initialize`
  هذا العنوان، ويشترط `increment` توقيع ذلك العنوان نفسه.
</Note>

    ```rust initialize.rs highlight={4,12-13} wrap
    }
    ```

  </div>

  <div>
    `state.rs` يُعرِّف بيانات حساب `Counter`. تستخدم ملفات التعليمات هذا النوع
    عند إنشاء الحساب وتحديثه:

    - `Counter::INIT_SPACE` يُحدِّد حجم الحساب وفقاً
      للحقول المُعرَّفة في `state.rs`.
    - `count` و `authority` هي قيم الحقول
      المكتوبة عند تهيئة الحساب.
    - `count += 1` يُحدِّث قيمة العداد المخزَّنة بعد
      اجتياز التحقق.
  </div>
</Columns>

### error.rs

`error.rs` يُعرِّف الأخطاء المخصَّصة للبرنامج. في هذا القالب، توضِّح الأخطاء كيف
تتوقف معالجات التعليمات عندما لا يكون للمُستدعي صلاحية تحديث العداد، أو عندما
يكون العداد قد بلغ `MAX_COUNT` بالفعل.

```rust programs/my-program/src/error.rs wrap
use anchor_lang::prelude::*;

#[error_code]
pub enum ErrorCode {
    #[msg("Only the counter authority can update this counter")]
    Unauthorized,
    #[msg("Counter has reached the maximum value")]
    CounterOverflow,
}
```

<Note>
  **`#[error_code]`**

  `#[error_code]` يُخبر Anchor بتحويل هذه المتغيرات إلى أخطاء برنامج مخصَّصة.
  يمكن للعملاء والاختبارات استخدام تلك الأخطاء بدلاً من التخمين من رموز الأخطاء
  الخام.

  **`Unauthorized`**

  `Unauthorized` يُرجَع عندما لا يكون موقِّع المعاملة هو الجهة المخوَّلة
  المخزَّنة في حساب العداد.

  **`CounterOverflow`**

  `CounterOverflow` يُرجَع عندما كان التزايد سيُخلّ بقاعدة `MAX_COUNT`
  الخاصة بالبرنامج.
</Note>

<Columns cols={2}>
  <div>
    ```rust increment.rs highlight={5,9} wrap
    pub fn handle_increment(ctx: Context<Increment>) -> Result<()> {
        require_keys_eq!(
            ctx.accounts.counter.authority,
            ctx.accounts.authority.key(),
            ErrorCode::Unauthorized,
        );
        require!(
            ctx.accounts.counter.count < MAX_COUNT,
            ErrorCode::CounterOverflow,
        );

        ctx.accounts.counter.count += 1;
        msg!("Hello, world! Counter is now {}", ctx.accounts.counter.count);
        Ok(())
    }
    ```
  </div>

  <div>
    `error.rs` يُسمِّي الأخطاء التي يمكن أن تُرجعها التعليمة:

    - `ErrorCode::Unauthorized` يُرجَع عندما لا
      يكون الموقِّع هو الجهة المخوَّلة المخزَّنة في حساب العداد.
    - `ErrorCode::CounterOverflow` يُرجَع عندما يكون
      العداد قد بلغ `MAX_COUNT` بالفعل.
  </div>
</Columns>

### instructions.rs

`instructions.rs` يربط ملفات التعليمات بـ crate الخاص بالبرنامج حتى يتمكن
`lib.rs` من الوصول إلى كود تعليمات `initialize` و`increment`. يُعرِّف كل
ملف تعليمات الحسابات المطلوبة لتلك التعليمة ومنطق المعالج الذي يعمل بعد أن يتحقق
Anchor من صحة تلك الحسابات.

```rust programs/my-program/src/instructions.rs wrap
pub mod initialize;
pub mod increment;

pub use initialize::*;
pub use increment::*;
```

<Note>
  **`pub mod initialize`**

  أسطر `pub mod` تجعل `src/instructions/initialize.rs` و
  `src/instructions/increment.rs` جزءًا من crate الخاص بالبرنامج.

  **`pub use initialize`**

  أسطر `pub use` تُعيد تصدير العناصر العامة من تلك الملفات. مما يجعل هياكل
  حسابات التعليمات ودوال المعالج متاحةً من خلال وحدة `instructions`.
</Note>

### initialize.rs

`initialize.rs` يُعرِّف الحسابات المطلوبة لإنشاء حساب العداد، ثم يكتب القيم
الأولية للحساب. تستخدم بنية `#[derive(Accounts)]`
[قيود الحساب](https://www.anchor-lang.com/docs/references/account-constraints)
الخاصة بـ Anchor لتحديد الحسابات المطلوبة وكيفية إنشاء حساب العداد الجديد.

```rust programs/my-program/src/instructions/initialize.rs wrap
use anchor_lang::prelude::*;

use crate::{constants::*, state::Counter};

#[derive(Accounts)]
pub struct Initialize<'info> {
    #[account(mut)]
    pub payer: Signer<'info>,
    #[account(
        init,
        payer = payer,
        space = 8 + Counter::INIT_SPACE,
        seeds = [COUNTER_SEED],
        bump
    )]
    pub counter: Account<'info, Counter>,
    pub system_program: Program<'info, System>,
}

pub fn handle_initialize(ctx: Context<Initialize>) -> Result<()> {
    ctx.accounts.counter.count = 0;
    ctx.accounts.counter.authority = ctx.accounts.payer.key();

        from: ctx.accounts.payer.to_account_info(),
        to: ctx.accounts.counter.to_account_info(),
    };
```

<Note>
  يستورد هذا الملف الثوابت المشتركة ونوع حساب `Counter`. تستخدم التعليمة تلك
  التعريفات لاشتقاق PDA، وتحديد مبلغ التحويل، وتخصيص الحساب بحجم البيانات الصحيح.

  **`derive(Accounts)`**

  `Initialize` هو سياق الحساب لتعليمة `initialize`. يمثّل كل حقل في البنية
  حساباً منفصلاً يجب تضمينه عند استدعاء التعليمة. يستخدم Anchor البنية للتحقق من
  صحة تلك الحسابات الواردة قبل تشغيل المعالج.

  **`#[account(mut)]`**

  `#[account(mut)]` يُخبر Anchor بأن حساب الدافع يجب أن يكون قابلاً للكتابة.
  هذا مطلوب لأن إنشاء الحساب وCPI الخاص بالتحويل كلاهما يخصمان lamports من الدافع.

  **`Signer<'info>`**

  `Signer<'info>` يُخبر Anchor بأن الدافع يجب أن يوقّع على المعاملة.

  **`#[account(`**

  يُخبر الكتلة `#[account(...)]` Anchor بكيفية إنشاء حساب العداد والتحقق من
  صحته قبل تشغيل المعالج.

  **`init`**

  `init` يخبر Anchor بإنشاء حساب `counter` قبل تشغيل المعالج. الحساب
  الجديد مملوك لهذا البرنامج، لذا يمكن لهذا البرنامج تخزين بيانات `Counter`
  فيه.

  **`payer = payer`**

  `payer = payer` يحدد حساب `payer` بوصفه الجهة الدافعة لتكاليف إنشاء حساب
  العداد الجديد.

  **`space = 8 + Counter::INIT_SPACE`**

  `space = 8 + Counter::INIT_SPACE` يخصص بايتات لمُميِّز حساب Anchor إضافةً
  إلى حقول `Counter` من `state.rs`. يساعد المُميِّز Anchor على التحقق من أن
  الحساب يخزّن النوع المتوقع قبل قراءته.

  **`seeds = [COUNTER_SEED]`**

  `seeds = [COUNTER_SEED]` يشترط أن يكون عنوان حساب العداد هو PDA المشتق من
  هذا الـ seed ومعرّف البرنامج. مع seed ثابت واحد، يوجد PDA عداد واحد لهذا
  البرنامج. لإنشاء عدادات منفصلة في برنامج حقيقي، عادةً ما تضيف seed آخر مثل عنوان
  المستخدم.

  **`bump`**

  `bump` يخبر Anchor بإيجاد bump الخاص بـ PDA والتحقق منه، وهو البايت الإضافي
  الذي يجعل العنوان المشتق صالحاً كـ PDA.

  **`Account<'info, Counter>`**

  `Account<'info, Counter>` يخبر Anchor بمعاملة بيانات الحساب باعتبارها من
  النوع `Counter` المأخوذ من `state.rs`. كما يتحقق Anchor من أن الحساب مملوك
  لهذا البرنامج.

  **`Program<'info, System>`**

  `Program<'info, System>` يشترط على المُستدعي توفير System Program. يستخدمه
  Anchor لقيد إنشاء حساب `init`. كما يستدعي CPI الخاص بالنقل في المعالج System
  Program أيضاً.

  **`handle_initialize`**

  يعمل المعالج بعد أن يتحقق Anchor من الحسابات وينشئ حساب العداد، وبذلك يمكنه
  كتابة البيانات الأولية للحساب بأمان.

  **`counter.count = 0`**

  يضبط حقل `count` في حساب العداد على القيمة `0`.

  **`counter.authority = ctx.accounts.payer.key()`**

  يضبط حقل `authority` في حساب العداد على عنوان الجهة الدافعة.

  **`system_program::Transfer`**

  هذه هي الحسابات التي تُمرَّر إلى تعليمة التحويل الخاصة بـ System Program. يُدرج
  تعليمة Cross Program Invocation هذه فقط لتوضيح كيفية تمرير CPI للحسابات إلى
  برنامج آخر.

  **`CpiContext::new`**

  `CpiContext` يُغلّف البرنامج المستهدف والحسابات المطلوبة لإجراء
  cross-program invocation. يُعدّ إنشاء السياق لـ CPI عن طريق إقران البرنامج الذي
  تريد استدعاءه بالحسابات التي يتوقعها ذلك البرنامج.

  **`system_program::transfer`**

  يستدعي هذا الـ CPI تعليمة التحويل الخاصة بـ System Program وينقل
  `HELLO_WORLD_LAMPORTS` من الدافع إلى حساب العداد.

  **`msg!`**

  `msg!` يكتب رسالة إلى سجلات البرنامج عند استدعاء البرنامج.
</Note>

### increment.rs

`increment.rs` يُعرّف الحسابات المطلوبة لتحديث حساب عداد موجود. يتحقق المعالج من
أن الموقّع هو الجهة المخوّلة المخزّنة، ويتحقق من أن العدد لم يبلغ الحد
`MAX_COUNT` المحدد، ثم يزيد العدد.

```rust programs/my-program/src/instructions/increment.rs wrap
use anchor_lang::prelude::*;

use crate::{constants::*, error::ErrorCode, state::Counter};

#[derive(Accounts)]
pub struct Increment<'info> {
    #[account(
        mut,
        seeds = [COUNTER_SEED],
        bump
    )]
    pub counter: Account<'info, Counter>,
    pub authority: Signer<'info>,
}

pub fn handle_increment(ctx: Context<Increment>) -> Result<()> {
    require_keys_eq!(
        ctx.accounts.counter.authority,
        ctx.accounts.authority.key(),
        ErrorCode::Unauthorized,
    );
    require!(
        ctx.accounts.counter.count < MAX_COUNT,
        ErrorCode::CounterOverflow,
    );

    ctx.accounts.counter.count += 1;
    msg!("Hello, world! Counter is now {}", ctx.accounts.counter.count);
    Ok(())
}
```

<Note>
  **`derive(Accounts)`**

  `Increment` هو سياق الحساب لتعليمة `increment`. يستخدمه Anchor للتحقق من
  حساب العداد القابل للتعديل والموقِّع المطلوب.

  **`mut`**

  `mut` يُخبر Anchor بأن حساب العداد يجب أن يكون قابلاً للكتابة لأن المُعالج
  يُحدّث قيمة `count` المخزّنة.

  **`seeds = [COUNTER_SEED]`**

  `seeds = [COUNTER_SEED]` يتحقق من أن حساب العداد المُقدَّم هو عنوان PDA
  المشتق من هذا seed ومعرّف البرنامج.

  **`bump`**

  `bump` يُخبر Anchor بإيجاد والتحقق من bump الخاص بعنوان PDA لحساب العداد.

  **`Account<'info, Counter>`**

  `Account<'info, Counter>` يُخبر Anchor بإلغاء تسلسل بيانات الحساب بوصفها نوع
  `Counter` من `state.rs`. كما يتحقق Anchor من أن الحساب مملوك لهذا البرنامج.

  **`Signer`**

  `Signer` يشترط توقيع الجهة المخوّلة. ثم يُقارن المُعالج عنوان هذا الموقّع
  بالجهة المخوّلة المخزّنة في حساب العداد.

  **`handle_increment`**

  يعمل المُعالج بعد أن يتحقق Anchor من قائمة الحسابات، ويتحقق من الملكية، ويُلغي
  تسلسل بيانات حساب العداد.

  **`require_keys_eq!`**

  `require_keys_eq!` يُقارن مفتاحين عامَّين ويوقف التعليمة ما لم يتطابق عنوان
  الموقّع مع الجهة المخوّلة المخزّنة في حساب العداد. وهذه هي قاعدة التفويض على
  مستوى التطبيق في هذا القالب.

  **`require!`**

  `require!` يتحقق من شرط منطقي ويوقف التعليمة بـ `CounterOverflow` إذا
  كان العداد قد بلغ `MAX_COUNT` بالفعل. يوضح هذا القالب الأخطاء المخصصة والفشل
  قبل التعديل.

  **`count += 1`**

  فقط بعد اجتياز كلا الفحصَين يُحدّث المُعالج بيانات حساب العداد. إذا فشل أيٌّ من
  الفحصَين، تفشل المعاملة ولا يتغير الحساب.

  **`msg!`**

```rust programs/my-program/tests/test_initialize.rs wrap
use {
    anchor_lang::{
        prelude::Pubkey,
        solana_program::{instruction::Instruction, system_program},
        AccountDeserialize, InstructionData, ToAccountMetas,
    },
    litesvm::LiteSVM,
    solana_keypair::Keypair,
    solana_message::{Message, VersionedMessage},
    solana_signer::Signer,
    solana_transaction::versioned::VersionedTransaction,
};

#[test]
fn test_initialize() {
    let program_id = my_program::id();
    let payer = Keypair::new();
    let counter = Pubkey::find_program_address(
        &[my_program::constants::COUNTER_SEED],
        &program_id,
    )
    .0;
    let mut svm = LiteSVM::new();
    let bytes = include_bytes!(concat!(
        env!("CARGO_TARGET_TMPDIR"),
        "/../deploy/my_program.so"
    ));
    svm.add_program(program_id, bytes).unwrap();
    svm.airdrop(&payer.pubkey(), 1_000_000_000).unwrap();

    let instruction = Instruction::new_with_bytes(
        program_id,
        &my_program::instruction::Initialize {}.data(),
        my_program::accounts::Initialize {
            payer: payer.pubkey(),
            counter,
            system_program: system_program::ID,
        }
        .to_account_metas(None),
    );

    let blockhash = svm.latest_blockhash();
    let msg = Message::new_with_blockhash(&[instruction], Some(&payer.pubkey()), &blockhash);
    let tx = VersionedTransaction::try_new(VersionedMessage::Legacy(msg), &[&payer]).unwrap();

    let res = svm.send_transaction(tx);
    assert!(res.is_ok());

    let counter_account = svm.get_account(&counter).unwrap();
    let mut data: &[u8] = &counter_account.data;
    let counter_state = my_program::state::Counter::try_deserialize(&mut data).unwrap();
    assert_eq!(counter_state.count, 0);
    assert_eq!(counter_state.authority, payer.pubkey());

    let instruction = Instruction::new_with_bytes(
        program_id,
        &my_program::instruction::Increment {}.data(),
        my_program::accounts::Increment {
            counter,
            authority: payer.pubkey(),
        }
        .to_account_metas(None),
    );

    let blockhash = svm.latest_blockhash();
    let msg = Message::new_with_blockhash(&[instruction], Some(&payer.pubkey()), &blockhash);
    let tx = VersionedTransaction::try_new(VersionedMessage::Legacy(msg), &[&payer]).unwrap();

    let res = svm.send_transaction(tx);
    assert!(res.is_ok());

    let counter_account = svm.get_account(&counter).unwrap();
    let mut data: &[u8] = &counter_account.data;
    let counter_state = my_program::state::Counter::try_deserialize(&mut data).unwrap();
    assert_eq!(counter_state.count, 1);
    assert_eq!(counter_state.authority, payer.pubkey());
}
```

<Note>
  **`litesvm::LiteSVM`**

  `LiteSVM` هو آلة افتراضية لسولانا تعمل داخل العملية وتُستخدم للاختبارات.
  يتيح للاختبار تسجيل البرنامج المُترجَم، وإنشاء الحسابات، وإرسال المعاملات، وفحص
  حالة الحسابات دون الحاجة إلى تشغيل عملية validator.

  **`let program_id`**

  يحصل الاختبار على عنوان البرنامج من قيمة `declare_id!` عبر
  `my_program::id()` وينشئ keypair جديدًا للدافع لمعاملة الاختبار.

  **`Pubkey::find_program_address`**

  عنوان العداد مشتق من نفس `COUNTER_SEED` الذي يستخدمه البرنامج. هذا يجعل
  الاختبار يستهدف PDA الذي يتوقعه `initialize.rs`.

  **`include_bytes!`**

  يقرأ `include_bytes!` ملف `my_program.so` المُترجَم الذي ينتجه البناء. تلك
  البايتات هي كود البرنامج القابل للتنفيذ الذي سيشغّله LiteSVM في الاختبار.

  **`svm.add_program`**

  يُسجّل `svm.add_program` بايتات البرنامج المُترجَمة على عنوان البرنامج في
  LiteSVM. يمنح الإسقاط الجوي الدافعَ ما يكفي من SOL المحلي لدفع رسوم المعاملة
  وإنشاء الحساب.

  **`let instruction`**

  يُنشئ `Instruction::new_with_bytes` تعليمة لاستدعاء البرنامج. وتتضمن معرّف
  البرنامج، وinstruction data، وحسابات التعليمة.

  **`svm.latest_blockhash`**

  كل معاملة سولانا تحتاج إلى blockhash حديث. في هذا الاختبار، يوفر LiteSVM
  blockhash لاستخدامه في المعاملة.

  **`Message::new_with_blockhash`**

  تحتوي الرسالة على التعليمة، ودافع الرسوم، والـ blockhash. هذه هي بيانات المعاملة
  التي سيتم توقيعها.

  **`VersionedTransaction::try_new`**

  يوقّع `VersionedTransaction::try_new` الرسالةَ باستخدام keypair الدافع.
  يوقّع الدافع لأنه يدفع رسوم المعاملة ويموّل حساب العداد الجديد.

  **`svm.send_transaction`**

  يُنفّذ `svm.send_transaction` المعاملة في LiteSVM.

  **`svm.get_account`**

  بعد تشغيل المعاملة، يقرأ الاختبار حساب العداد مباشرةً من LiteSVM حتى يتمكن من
  فحص بيانات الحساب.

  **`Counter::try_deserialize`**

  يخزّن حساب العداد بيانات مُتسلسلة. يتحقق `Counter::try_deserialize` من
  مُميِّز حساب Anchor ويحوّل بيانات الحساب إلى nوع `Counter` من `state.rs`.

  **`assert_eq!(counter_state.count, 0)`**

  بعد نجاح `initialize`، يُجري الاختبار عملية إلغاء تسلسل لحساب العداد ويتحقق
  من أن الحالة الابتدائية تطابق ما كتبه `handle_initialize`.

  **`assert_eq!(counter_state.count, 1)`**

  بعد نجاح `increment`، يجب أن يكون لدى حساب العداد ذاته `count` مضبوطاً
  على `1` مع الحفاظ على نفس الصلاحية.
</Note>

```toml Anchor.toml
[scripts]
test = "cargo test"

[hooks]
```

<Note>
  **`skip_local_validator`**

  `skip_local_validator = true` يخبر Anchor بعدم تشغيل validator لـ `anchor test`.
  يستخدم اختبار Rust بدلاً من ذلك LiteSVM.

  **`programs.localnet`**

  `[programs.localnet]` يربط اسم حزمة Rust بعنوان program account المستخدم في
  عمليات البناء والاختبار المحلية.

  **`provider`**

  `[provider]` يضبط الكتلة الافتراضية والمحفظة للأوامر مثل `anchor deploy`.

  **`scripts`**

  `[scripts]` يغيّر ما يُنفّذه `anchor test`. في هذا القالب، يقوم `anchor test`
  bتشغيل `cargo test`.
</Note>
