Solana is a public network of computers, called validators, that all keep the
same copy of one shared record. The record is made of accounts: some hold data,
such as token balances, and some hold code, called programs, that the network
runs. Apps and wallets make changes by sending the network transactions, which
usually settle in under a second and cost a fraction of a cent.

Seven concepts form the execution model of Solana development. Start with
Accounts and Programs, then follow how Instructions become Transactions. PDAs,
CPIs, and Fees build on that execution model. The
[concepts for app developers](#concepts-for-app-developers) below (wallets,
confirmation, fee sponsorship, and rent) cover what an app sees when it moves
money or assets.

<Columns cols={2}>
  <Card title="Accounts" href="/developers/docs/core/accounts">
    Solana stores all state in accounts, a key-value store keyed by 32-byte
    addresses. Each account has five fields: lamports, data, owner, executable,
    and rent_epoch.
  </Card>
  <Card title="Programs" href="/developers/docs/core/programs">
    Solana's smart contracts, compiled to sBPF. Programs are stateless and all
    mutable state lives in separate data accounts passed via instructions.
  </Card>
  <Card title="Instructions" href="/developers/docs/core/instructions">
    A request to execute one program, containing a program ID, accounts list,
    and opaque data bytes. Multiple instructions compose into a single
    transaction.
  </Card>
  <Card title="Transactions" href="/developers/docs/core/transactions">
    The atomic unit of execution on Solana. Contains signatures and a message
    (account addresses, recent blockhash, and compiled instructions). Max 1232
    bytes, or 4096 with the v1 format.
  </Card>
  <Card title="Fees" href="/developers/docs/core/fees">
    Base fee of 5,000 lamports per signature, plus an optional priority fee
    based on compute units requested. Max 1.4M compute units per transaction.
  </Card>
  <Card title="Program-derived addresses (PDAs)" href="/developers/docs/core/pda">
    Deterministic addresses derived from a program ID and seeds. Only the owning
    program can sign on behalf of a PDA via invoke_signed.
  </Card>
  <Card title="Cross-Program Invocations (CPIs)" href="/developers/docs/core/cpi">
    One program calling another via invoke or invoke_signed. Signer and writable
    privileges extend to the callee. Max instruction stack depth of 5, top-level
    plus CPIs (9 with SIMD-0268).
  </Card>
</Columns>
