A stablecoin is a token redeemable for a reference currency. The token is the
issuer's liability, and the reserve backing it is held separately. In
[token design](/developers/docs/tokenization/design) terms, the token is the
asset.

## The sequence

1. **[Design the token](/developers/docs/tokenization/design)**: confirm which
   register governs the liability and how the reserve is evidenced, then choose
   the token program and lay out the authorities that mint, freeze, and pause.
2. **[Choose transfer controls](/developers/docs/tokenization/design/choosing-controls)**:
   which controls the asset needs, and which of them constrain the payment
   flows below.
3. **[Evidence compliance](/developers/docs/tokenization/compliance)**: bind a
   KYC or sanctions decision to an address without publishing personal data.
4. **[Gate the holders](/developers/docs/tokenization/token-acl)**: allowlists
   and blocklists, where holder eligibility is restricted.
5. **[Integrate custody](/developers/docs/tokenization/custody)**: what a
   custodian needs from the mint before it can hold or distribute the token.
6. **[Operate it](/developers/docs/tokenization/tutorials)**: build a gated mint
   and run the supply operations against it.

## Payments and settlement

[Payments](/developers/docs/payments) covers accepting, sending, and
reconciling stablecoin payments.
[Choosing the cash leg](/developers/docs/defi/cash-leg) covers a stablecoin
used as the cash side of a settlement against another asset.

See [Tokens](/developers/docs/tokens) for the token programs and the extension
reference.
