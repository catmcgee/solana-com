These pages treat a tokenized security as an instrument with a register of
record, a transfer agent or equivalent registrar, and holders restricted by
rule.

## The sequence

1. **[Design the token](/developers/docs/tokenization/design)**: whether the
   mint is the register or mirrors one held offchain. The choice is fixed at
   creation.
2. **[Design the authorities](/developers/docs/tokenization/design/program-and-authority-design)**:
   which key or multisig holds each authority, and how that maps onto the
   transfer agent's duties.
3. **[Choose transfer controls](/developers/docs/tokenization/design/choosing-controls)**:
   the controls used for an instrument with restricted holders.
4. **[Evidence holder eligibility](/developers/docs/tokenization/compliance)**:
   attestations that evidence an eligibility decision without publishing the
   underlying data, and [Token ACL](/developers/docs/tokenization/token-acl) to
   enforce it.
5. **[Integrate custody](/developers/docs/tokenization/custody)**: the
   custodian relationship and the
   [issuer and transfer agent boundary](/developers/docs/tokenization/custody/transfer-agent-responsibilities).
6. **[Settle against payment](/developers/docs/defi/dvp-program)**: exchange
   the security for its cash leg in one transaction, through the DvP program or
   [delegated authority](/developers/docs/tokenization/dvp).
7. **[Operate it](/developers/docs/tokenization/tutorials)**: build a gated
   mint and run the ongoing operations against it.

See [Tokens](/developers/docs/tokens) for the token programs and the extension
reference.
