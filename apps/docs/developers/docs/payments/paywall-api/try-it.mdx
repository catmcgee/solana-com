Start as the client. The API below sells tomorrow's forecast for 0.01 USDC per
request. The client is a script with its own wallet holding test USDC, so it
can pay without a person approving each call. Press **Run** to step through
the output of this tutorial's example code on a local test network (Surfpool).
Nothing is sent from your browser, and no real money moves.

<Demo />

What happened:

- The first call got `402 Payment Required`. The body listed the price as
  `10000` base units of USDC (USDC has 6 decimals, so that is 0.01 USDC), the
  USDC mint address, the address to pay (`payTo`) and the network.
- The client signed a USDC transfer for exactly that amount and sent the same
  request again with the signed transfer in the `X-PAYMENT` header.
- The server sent the transfer to the network, waited for it to confirm, and
  answered `200` with the forecast. The network fee for that
  <span className="sol-chip" data-concept="transaction"><Tooltip headline="Transactions" tip="A transaction is a signed request to change the shared ledger. It either fully happens or doesn't happen at all, and once confirmed anyone can look it up." cta="Learn more" href="/developers/docs/core/transactions">transaction</Tooltip><span className="nojs-only"> ([Transactions](/developers/docs/core/transactions): A transaction is a signed request to change the shared ledger.   5,000 lamports (0.000005 SOL).
- Sending the same `X-PAYMENT` header again got `402 payment already used`, so
  one payment buys one response.
- A client configured to pay at most 5,000 base units refused the 10,000 price
  and signed nothing.

The output comes from a local Surfpool test network, so the addresses and
signatures don't exist on public networks. The `network` field still shows the
devnet ID (`solana:EtWT…xqa1`): that is the example's default `NETWORK` in
`x402.ts`, the network the code targets when you point it at devnet.

## Why 402?

HTTP has reserved status code 402 "Payment Required" since 1997, without
defining how to pay. [x402](https://www.x402.org/) is an open protocol that
fills that gap. The 402 response lists the payments the server accepts, and the
client retries with a signed payment in a header. On Solana the network fee for
that payment is a fraction of a cent, so a price of one cent still works.
