[Commerce Kit](/developers/docs/tools/commerce-kit) is a set of React components for
taking Solana payments. Its `PaymentButton` does in one component what the
script behind the payment in the previous step did: it connects the
customer's wallet, builds the transfer, asks the wallet to sign it, and sends it
to the network. Configure one in the live demo. Paying with it is
optional: the previous step already showed the payment, and step 3 checks
payments from your own server.

## What the button is configured with

<Danger>
  Commerce Kit is currently in beta. APIs may change before the stable
  release.
</Danger>

To add the same button to your own React or Next.js app (Node.js 20.18 or
higher), install the kit and render `PaymentButton` with your store's wallet
address. `mode: "tip"` lets the
payer choose the amount, so it needs no product list:

```bash
npm install @solana-commerce/kit
```

```tsx
import { PaymentButton } from "@solana-commerce/kit";

function Checkout() {
  return (
    <PaymentButton
      config={{
        merchant: { name: "My Store", wallet: "your-wallet-address" },
        mode: "tip"
      }}
      onPaymentSuccess={(signature) => {
        // Not proof of payment on its own: see the warning below.
        console.log("Payment sent:", signature);
      }}
    />
  );
}
```

These are the `PaymentButton` settings that matter for a checkout. The full
list is in the [PaymentButton reference](/developers/docs/tools/commerce-kit/quickstart/payment-button).

- **`config.merchant.wallet`** is the
  <span className="sol-chip" data-concept="wallet"><Tooltip headline="Wallets & signatures" tip="A wallet holds a key pair: a public address that anyone can pay, and a private key that signs approvals and never leaves the device." cta="Learn more" href="/developers/docs/core/wallets">wallet address</Tooltip><span className="nojs-only"> ([Wallets & signatures](/developers/docs/core/wallets): A wallet holds a key pair: a public address that anyone can pay, and a private key that signs approvals and never leaves the device.)</span></span> that
  payments land in. Anyone can send to it; only the holder of its key can move
  money out.
- **`config.mode`** sets the flow: `"buyNow"` for one fixed-price product,
  `"cart"` for several, `"tip"` when the payer picks the amount. `"buyNow"` and
  `"cart"` take their prices from `paymentConfig.products`.
- **`config.network`** is `"mainnet"`, `"devnet"`, or `"testnet"`. It defaults
  to `"mainnet"`.
- **`config.allowedMints`** limits which tokens the payer can choose. Set it to
  the USDC mint if you only accept dollars.
- **`onPaymentSuccess(signature)`** runs when the
  <span className="sol-chip" data-concept="transaction"><Tooltip headline="Transactions" tip="A transaction is a signed request to change the shared ledger. It either fully happens or doesn't happen at all, and once confirmed anyone can look it up." cta="Learn more" href="/developers/docs/core/transactions">transaction</Tooltip><span className="nojs-only"> ([Transactions](/developers/docs/core/transactions): A transaction is a signed request to change the shared ledger. It either fully happens or doesn't happen at all, and once confirmed anyone can look it up.)</span></span> is
  confirmed. It receives the transaction's signature.

<Warning>
  **Don't ship orders from a browser callback alone.** Anything that runs in
  the browser can be faked. In the next step your server looks the signature
  up on the network and checks the amount, the recipient, and the order itself.
</Warning>

## The transfer the button sends

A USDC payment is one `TransferChecked` instruction: move this many base units
of this mint from the customer's
<span className="sol-chip" data-concept="token-account"><Tooltip headline="Token accounts" tip="Wallets don't hold tokens directly. Each token (USDC, or your own asset) gets a small account owned by the wallet, and transfers move between these accounts." cta="Learn more" href="/developers/docs/tokens/basics/create-token-account">USDC account</Tooltip><span className="nojs-only"> ([Token accounts](/developers/docs/tokens/basics/create-token-account): Wallets don't hold tokens directly. Each token (USDC, or your own asset) gets a small account owned by the wallet, and transfers move between these accounts.)</span></span> to
the store's. Here is the same payment written with
[`@solana/kit`](/developers/docs/clients/official/javascript). It is the code that
produced the payment in step 1, and it adds the order's reference as an
extra read-only account so your server can match the payment to the order
(the [Solana Pay reference](/developers/docs/tools/solana-pay/specification/version1-1#reference)
convention).

<PayExample />

This is the payment code the rest of the tutorial uses. The button in the
live demo builds a similar transfer, but it doesn't take your order's
reference, so the confirm endpoint in the next step can't match a button
payment to an order. Call `payStore` from your checkout instead. It works in
any frontend, React or not, and on a server: it takes the customer's signer
and the order. For connecting the customer's wallet outside React (Vue, Svelte
or plain JavaScript), see Commerce Kit's
[headless `ConnectorClient`](/developers/docs/tools/commerce-kit/quickstart/wallet-connection#headless-usage-no-react),
which discovers and connects Wallet Standard wallets without a framework.
