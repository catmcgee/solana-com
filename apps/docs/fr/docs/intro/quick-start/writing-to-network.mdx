Dans la section précédente, vous avez appris à
[lire des données depuis le réseau Solana](/docs/intro/quick-start/reading-from-network)
en récupérant des comptes. L'écriture de données sur le réseau Solana nécessite
une [transaction](/docs/core/transactions). Une transaction contient une ou
plusieurs [instructions](/docs/core/instructions), et chaque instruction invoque
un programme.

Les programmes définissent la logique métier de chaque instruction. Lorsque vous
envoyez une transaction, le runtime Solana exécute les instructions de la
transaction dans l'ordre. Les transactions sont atomiques. Soit toutes les
instructions de la transaction réussissent, soit la transaction entière échoue.

Les exemples de cette section montrent comment :

1. Transférer des SOL entre des comptes
2. Créer un nouveau mint de token

## Transférer des SOL

L'exemple ci-dessous transfère des SOL d'un compte à un autre. Seul le programme désigné comme propriétaire d'un compte peut modifier les données de ce compte ou déduire des lamports de son solde. Les comptes de portefeuille appartiennent au
[System Program](/docs/core/programs/builtin-programs#the-system-program), donc
transférer des SOL entre comptes de portefeuille nécessite une instruction qui invoque l'instruction
[transfer](https://github.com/anza-xyz/agave/blob/v2.1.11/programs/system/src/system_processor.rs#L183-L213)
du System Program. Le compte source doit également signer la transaction.

```ts title="Transfer SOL"
import { createClient, generateKeyPairSigner, lamports } from "@solana/kit";
import { solanaRpc, rpcAirdrop } from "@solana/kit-plugin-rpc";
import { generatedPayer, airdropPayer } from "@solana/kit-plugin-signer";
import { getTransferSolInstruction } from "@solana-program/system";

const client = await createClient()
  .use(generatedPayer())
  .use(
    solanaRpc({
      rpcUrl: "http://localhost:8899",
      rpcSubscriptionsUrl: "ws://localhost:8900"
    })
  )
  .use(rpcAirdrop())
  .use(airdropPayer(lamports(1_000_000_000n)));

const receiver = await generateKeyPairSigner();

const transferInstruction = getTransferSolInstruction({
  source: client.payer,
  destination: receiver.address,
  amount: lamports(10_000_000n)
});

const result = await client.sendTransaction([transferInstruction]);

console.log("Transaction Signature:", result.context.signature);

const { value: senderBalance } = await client.rpc
  .getBalance(client.payer.address)
  .send();
const { value: receiverBalance } = await client.rpc
  .getBalance(receiver.address)
  .send();

console.log("Sender Balance:", senderBalance);
console.log("Receiver Balance:", receiverBalance);
```

<Note>
  **`createClient`**

  Créez un client Kit pour le validator local. `generatedPayer()` ajoute un
  signataire payeur, `solanaRpc()` ajoute les capacités RPC et d'envoi de
  transactions, `rpcAirdrop()` ajoute `client.airdrop`, et `airdropPayer()`
  crédite le payeur en SOL de test.

  **`receiver`**

  Générez un signataire pour le compte destinataire des SOL. Le destinataire n'a
  pas besoin de signer ce transfert. Si l'adresse du destinataire ne possède pas
  encore de compte, la réception de SOL crée un compte système à cette adresse.

  **`transferInstruction`**

  Construisez l'instruction System Program qui transfère des lamports du payeur
  client vers le destinataire.

  **`sendTransaction`**

  Envoyez l'instruction sous forme de transaction. Le client Kit récupère un
  blockhash récent, définit le payeur des frais, signe avec les signataires
  requis, envoie la transaction et attend la confirmation.

  **`balances`**

  Récupérez les soldes de l'expéditeur et du destinataire après confirmation de la
  transaction.
</Note>

## Créer un token

L'exemple ci-dessous crée un nouveau mint de token en utilisant le
[Token Extensions Program](/docs/tokens/extensions). Un mint account est le
compte qui définit les paramètres globaux d'un token, tels que les décimales,
l'offre, l'autorité de mint et l'autorité de gel.

La création d'un mint account nécessite deux instructions :

1. Invoquer le System Program pour créer un nouveau compte appartenant au Token
   Extensions Program.
2. Invoquer le Token Extensions Program pour initialiser ce compte en tant que
   mint.

```ts title="Create mint account"
import { createClient, generateKeyPairSigner, lamports } from "@solana/kit";
import { solanaRpc, rpcAirdrop } from "@solana/kit-plugin-rpc";
import { generatedPayer, airdropPayer } from "@solana/kit-plugin-signer";
import { getCreateAccountInstruction } from "@solana-program/system";
import {
  fetchMint,
  getInitializeMintInstruction,
  getMintSize,
  TOKEN_2022_PROGRAM_ADDRESS
} from "@solana-program/token-2022";

const client = await createClient()
  .use(generatedPayer())
  .use(
    solanaRpc({
      rpcUrl: "http://localhost:8899",
      rpcSubscriptionsUrl: "ws://localhost:8900"
    })
  )
  .use(rpcAirdrop())
  .use(airdropPayer(lamports(1_000_000_000n)));

const mint = await generateKeyPairSigner();

const space = BigInt(getMintSize());

const rent = await client.rpc.getMinimumBalanceForRentExemption(space).send();

const createAccountInstruction = getCreateAccountInstruction({
  payer: client.payer,
  newAccount: mint,
  space,
  lamports: rent,
  programAddress: TOKEN_2022_PROGRAM_ADDRESS
});

const initializeMintInstruction = getInitializeMintInstruction({
  mint: mint.address,
  decimals: 2,
  mintAuthority: client.payer.address,
  freezeAuthority: client.payer.address,
  tokenProgram: TOKEN_2022_PROGRAM_ADDRESS
});

const result = await client.sendTransaction([
  createAccountInstruction,
  initializeMintInstruction
]);

console.log("Mint Address:", mint.address);
console.log("Transaction Signature:", result.context.signature);

const mintAccount = await fetchMint(client.rpc, mint.address);
console.log("Mint Account:", mintAccount);
```

<Note>
  **`createClient`**

  Créez et approvisionnez un client Kit pour le validator local. Le payeur
  approvisionné règle le rent du compte et les frais de transaction.

  **`mint`**

  Générez un signataire à utiliser comme adresse du nouveau mint account. Le
  signataire autorise la création de ce compte.

  **`space`**

  Calculez le nombre d'octets requis pour un mint account sans extensions.

  **`rent`**

  Calculez les lamports nécessaires pour rendre le mint account rent-exempt.

  **`createAccountInstruction`**

  Construisez l'instruction du System Program qui crée le mint account et assigne
  le compte au Token Extensions Program.

  **`initializeMintInstruction`**

  Construisez l'instruction du Token Extensions Program qui écrit les données
  initiales du mint dans le nouveau compte.

  **`sendTransaction`**

  Envoyez les deux instructions en une seule transaction. L'ordre des instructions
  est important : le compte doit être créé avant de pouvoir être initialisé.

  **`mintAccount`**

  Récupérez le mint account après confirmation. L'assistant lit le compte et
  désérialise le champ de données du mint account dans le type Mint.
</Note>

<Info>
  Ces exemples utilisent `generatedPayer()` pour créer un keypair jetable à des
  fins de test local. Les applications en production ne doivent jamais stocker
  des clés privées brutes dans le code — déléguez la signature à un backend de
  gestion des clés. Voir [Signature en
  production](/docs/core/transactions/signing-in-production).
</Info>
