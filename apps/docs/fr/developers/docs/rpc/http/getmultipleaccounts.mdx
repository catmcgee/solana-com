Renvoie les informations de compte pour une liste de pubkeys.

<RequestExample>
  ```bash cURL
  curl https://api.devnet.solana.com -s -X POST \
    -H "Content-Type: application/json" \
    -d '
    {
      "jsonrpc": "2.0",
      "id": 1,
      "method": "getMultipleAccounts",
      "params": [
        [
          "vines1vzrYbzLMRdu58ou5XTby4qAqVRLmqo36NKPTg",
          "4fYNw3dojWmQ4dXtSGE9epjRGy9pFSx62YypT7avPYvA"
        ],
        {
          "encoding": "base58",
          "commitment": "finalized"
        }
      ]
    }
  '
  ```

  ```ts Kit
  import { address, createSolanaRpc } from "@solana/kit";

  const rpc_url = "https://api.devnet.solana.com";
  const rpc = createSolanaRpc(rpc_url);

  let addresses = [
    address("vines1vzrYbzLMRdu58ou5XTby4qAqVRLmqo36NKPTg"),
    address("4fYNw3dojWmQ4dXtSGE9epjRGy9pFSx62YypT7avPYvA")
  ];

  let config = {
    encoding: "base58",
    commitment: "finalized"
  };

  let accounts = await rpc.getMultipleAccounts(addresses, config).send();

  console.log(accounts);
  ```

  ```rs Rust
  use anyhow::Result;
  use solana_account_decoder::UiAccountEncoding;
  use solana_client::{nonblocking::rpc_client::RpcClient, rpc_config::RpcAccountInfoConfig};
  use solana_sdk::{commitment_config::CommitmentConfig, pubkey};

  #[tokio::main]
  async fn main() -> Result<()> {
      let client = RpcClient::new_with_commitment(
          String::from("https://api.devnet.solana.com"),
          CommitmentConfig::confirmed(),
      );

      let addresses = [
          pubkey!("vines1vzrYbzLMRdu58ou5XTby4qAqVRLmqo36NKPTg"),
          pubkey!("4fYNw3dojWmQ4dXtSGE9epjRGy9pFSx62YypT7avPYvA"),
      ];

      let config = RpcAccountInfoConfig {
          encoding: UiAccountEncoding::Base58.into(),
          data_slice: None,
          commitment: CommitmentConfig::finalized().into(),
          min_context_slot: None,
      };

      let accounts = client
          .get_multiple_accounts_with_config(&addresses, config)
          .await?;

      println!("{:#?}", accounts);

      Ok(())
  }
  ```

## Parameters

<ParamField body="0" type="array" required>
  Un tableau de pubkeys à interroger, sous forme de chaînes encodées en base-58
  (jusqu'à un maximum de 100)
</ParamField>

<ParamField body="1" type="object">
  Objet de configuration contenant les champs suivants :

  <Expandable title="properties" defaultOpen>
    <ParamField body="commitment" type="string">
      Le commitment décrit le niveau de finalisation d'un bloc à un moment donné. Voir
      [Configuration de l'engagement d'état](/developers/docs/rpc#configuring-state-commitment).
    </ParamField>

    <ParamField body="minContextSlot" type="number">
      Le slot minimum auquel la requête peut être évaluée
    </ParamField>

    <ParamField body="dataSlice" type="object">
      Demande une tranche des données du compte.

      - `length: <usize>` - nombre d'octets à renvoyer
      - `offset: <usize>` - décalage en octets à partir duquel commencer la lecture

      <Info>
        Le découpage de données n'est disponible que pour les encodages `base58`,
        `base64` ou `base64+zstd`.
      </Info>
    </ParamField>

    <ParamField body="encoding" type="string" default="base64">
      Values: `jsonParsed`, `base58`, `base64`, `base64+zstd`

      Format d'encodage pour les données de compte retournées

      - `base58` est lent et limité à moins de 129 octets de données de compte.
      - `base64` retournera des données encodées en base64 pour des données de compte
        de toute taille.
      - `base64+zstd` compresse les données de compte en utilisant
        [Zstandard](https://facebook.github.io/zstd/) et encode le résultat en base64.
      - L'encodage `jsonParsed` tente d'utiliser des analyseurs d'état spécifiques au
        programme pour retourner des données d'état de compte plus lisibles et
        explicites.
      - Si `jsonParsed` est demandé mais qu'aucun analyseur ne peut être trouvé, le
        champ se replie sur l'encodage `base64`, détectable lorsque le champ `data`
        est de type `<string>`.
    </ParamField>
  </Expandable>
</ParamField>

## Result

<ResponseField name="result" type="array">
  Le résultat sera un tableau contenant soit :

  - `null` - si le compte à cette pubkey n'existe pas, ou
  - Des objets de compte avec les champs suivants :

  <Expandable title="properties" defaultOpen>
    <ResponseField name="data" type="[string,encoding] | object">
      Données associées au compte, soit sous forme de données binaires encodées, soit
      au format JSON `{<program>: <state>}` - selon le paramètre d'encodage
    </ResponseField>

    <ResponseField name="executable" type="bool">
      Booléen indiquant si le compte contient un programme (et est strictement en
      lecture seule)
    </ResponseField>

    <ResponseField name="lamports" type="u64">
      Nombre de lamports attribués à ce compte
    </ResponseField>

    <ResponseField name="owner" type="string">
      Pubkey encodée en base-58 du programme auquel ce compte a été assigné
    </ResponseField>

    <ResponseField name="rentEpoch" type="u64">
      L'epoch à laquelle ce compte devra payer le prochain loyer
    </ResponseField>

    <ResponseField name="space" type="u64">
      La taille des données du compte
    </ResponseField>
  </Expandable>
</ResponseField>
