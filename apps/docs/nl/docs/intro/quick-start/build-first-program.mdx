Deze quickstart gebruikt het
[Anchor framework](https://www.anchor-lang.com/docs) startersproject gegenereerd
door `anchor init`. Je maakt het project lokaal aan, voert de tests uit, bouwt
het programma en doorloopt de programmacode die Anchor generiert.

## Vereisten

Voordat je begint,
[installeer de Solana-ontwikkeltools](/docs/intro/installation). De installatie
omvat Rust, de Solana CLI en de Anchor CLI.

Gebruik Anchor CLI versie 1.1.2 of hoger voor dit sjabloon. Controleer je
geïnstalleerde versie:

```bash Terminal
anchor --version
```

<Steps titleSize="h3">

<Step title="Maak het project aan">

Voer de volgende opdrachten uit in je terminal:

```bash Terminal
anchor init my-program
cd my-program
```

Het startersproject bevat één Solana-programma onder `programs/my-program`. Het
programma bevat twee instructies: één om een telleraccount te initialiseren en
één om de teller te verhogen.

Sommige onderdelen van het sjabloon demonstreren veelvoorkomende
Solana-programmapatronen: het afleiden van
[PDA](/docs/core/pda)-accountadressen, het uitvoeren van een Cross Program
Invocation ([CPI](/docs/core/cpi)) om SOL over te maken, en het gebruik van
aangepaste foutcontroles om een instructie te stoppen wanneer een conditie
mislukt.

<Step title="Programma Bouwen">

Voer `anchor build` uit om het startersprogramma te compileren:

```bash Terminal
anchor build
```

Het gecompileerde programma wordt geschreven naar `target/deploy/my_program.so`.
Wanneer het programma wordt uitgerold, wordt de inhoud van dit `.so`-bestand
opgeslagen in een account onchain.

</Step>

<Step title="Test uitvoeren">

Voer de standaardtest uit:

```bash Terminal
anchor test
```

De `Anchor.toml` van dit sjabloon gebruikt de Rust-testopdracht:

```toml Anchor.toml
skip_local_validator = true

[scripts]
test = "cargo test"
```

De test laadt het gecompileerde programma in
[LiteSVM](https://www.litesvm.com/), maakt een betaler aan, verstuurt de
`initialize` en `increment` instructies, en controleert vervolgens de
status van het telleraccount.

Het uitvoeren van `anchor test` compileert het programma ook, dus u hoeft
`anchor build` niet eerst uit te voeren bij lokaal testen.

</Step>

<Step title="Programma implementeren">

Lokale tests bieden de snelste feedbackcyclus. Wanneer u klaar bent om te
implementeren op een netwerk, bijvoorbeeld devnet, bouw dan eerst en
implementeer daarna op een cluster.

Voor het implementeren van een Solana-programma is SOL vereist, omdat het
programma wordt opgeslagen in een account, en het account moet betalen voor de
ruimte die het gebruikt. Op devnet kunt u gratis devnet SOL aanvragen via de
[Solana Faucet](https://faucet.solana.com/) of met de Solana CLI:

```bash Terminal
solana airdrop 2 --url devnet
```

```bash Terminal
anchor build
anchor deploy --provider.cluster devnet
```

</Step>

</Steps>

## Bronbestanden

De map `src` bevat het Solana-programma. De
[Programmastructuur](https://www.anchor-lang.com/docs/basics/program-structure)-documentatie
van Anchor legt de kernmacro's uit die hier worden gebruikt, waaronder
`declare_id!`, `#[program]`, `#[derive(Accounts)]` en
`#[account]`. Dit gedeelte beschrijft de sjabloonbestanden.

### lib.rs

`lib.rs` is het toegangspunt van het programma. Het verbindt de bronbestanden,
definieert het programmaadres en definieert de programma-instructies die
gebruikers kunnen aanroepen.

```rust programs/my-program/src/lib.rs wrap
pub mod constants;
pub mod error;
pub mod instructions;
pub mod state;

use anchor_lang::prelude::*;

pub use constants::*;
pub use instructions::*;
pub use state::*;

declare_id!("82sFkffP9wxwpyfZyeaKHH2chQoJPUGsJZSPi9mrUuXd");

#[program]
pub mod my_program {
    use super::*;

    pub fn initialize(ctx: Context<Initialize>) -> Result<()> {
        crate::instructions::initialize::handle_initialize(ctx)
    }

    pub fn increment(ctx: Context<Increment>) -> Result<()> {
        crate::instructions::increment::handle_increment(ctx)
    }
}
```

<Note>
  **`pub mod constants`**

  `pub mod constants` maakt `constants.rs` deel uit van de program crate. Dit
  is waar de template gedeelde programmawaarden opslaat, zoals de PDA seed, het
  overdrachtsbedrag en de maximale tellerwaarde.

  **`pub mod error`**

  `pub mod error` maakt `error.rs` deel uit van de program crate. Dit bestand
  definieert de aangepaste fouten die het programma kan teruggeven wanneer een
  instructie ongeldig is.

  **`pub mod instructions`**

  `pub mod instructions` maakt `instructions.rs` deel uit van de program
  crate. Dat bestand fungeert als een index voor de instructiespecifieke bestanden
  in `src/instructions/`.

  **`pub mod state`**

  `pub mod state` maakt `state.rs` deel uit van de program crate. Dit bestand
  definieert de gegevensindeling voor accounts die eigendom zijn van dit
  programma, inclusief het `Counter` account.

  **`anchor_lang::prelude`**

  `anchor_lang::prelude::*` importeert de Anchor-typen en macro's die worden
  gebruikt om een Solana-programma te definiëren, waaronder `Context`,
  `Result`, `Pubkey`, `Account`, `Signer`, en
  Anchor-accountattributen.

  De `pub use`-regels maken publieke items uit de onderliggende modules
  beschikbaar vanaf de crate-root. Dat houdt de instructie-ingangspunten kort,
  zoals `Context<Initialize>` in plaats van een langer modulepad.

  **`declare_id!`**

  `declare_id!` definieert het adres van het programma. Dit moet overeenkomen
  met het adres in `Anchor.toml`, het gedeployde program account, en alle
  gebruikers of tests die het programma aanroepen.

  **`#[program]`**

  `#[program]` instrueert Anchor om het Solana-programma-ingangspunt en de
  instructie-verzendcode te genereren. Publieke functies in deze module worden de
  instructies die gebruikers kunnen aanroepen.

  **`pub fn initialize`, `pub fn increment`**

  `initialize` en `increment` zijn de twee instructienamen die gebruikers
  kunnen aanroepen. Elk ontvangt een `Context<T>`. Het type binnen
  `Context` definieert de accounts die vereist zijn door die instructie, en
  Anchor valideert die accounts vóór de instructie wordt uitgevoerd.

  **`handle_initialize`, `handle_increment`**

  De handleerfunctie bevat de logica voor de instructie.
</Note>

### constants.rs

`constants.rs` bewaart gedeelde waarden op één plek. In dit sjabloon leidt
`COUNTER_SEED` de teller-PDA af, wordt `HELLO_WORLD_LAMPORTS`
overgedragen tijdens initialisatie, en wordt `MAX_COUNT` gecontroleerd vóór
het ophogen.

```rust programs/my-program/src/constants.rs wrap
use anchor_lang::prelude::*;

#[constant]
pub const COUNTER_SEED: &[u8] = b"counter";

#[constant]
pub const HELLO_WORLD_LAMPORTS: u64 = 1;

#[constant]
pub const MAX_COUNT: u64 = 10;
```

<Note>
  **`#[constant]`**

  `#[constant]` vertelt Anchor om de waarde op te nemen in de programma-IDL.
  Dat maakt belangrijke programmaconstan­ten zichtbaar voor gegenereerde clients
  en tooling.

  **`COUNTER_SEED`**

  `COUNTER_SEED` is de byte-string die wordt gebruikt om de teller-PDA af te
  leiden. Het programma en de test gebruiken beide dit seed zodat ze het eens zijn
  over het accountadres zonder een aparte keypair op te slaan. Dit sjabloon
  gebruikt één vast seed, zodat het programma éen teller-adres heeft. Echte
  programma's nemen vaak het adres van een gebruiker of een andere identificator
  op in de seeds om veel gerelateerde accounts aan te maken.

  **`HELLO_WORLD_LAMPORTS`**

  `HELLO_WORLD_LAMPORTS` is de hoeveelheid lamports die van de betaler naar
  het teller-account wordt overgedragen binnen `initialize`. Het is bewust
  klein omdat het sjabloon een CPI naar het System Program demonstreert.

  **`MAX_COUNT`**

  `MAX_COUNT` is de bovengrens die wordt gecontroleerd door `increment`.
  Door het hier te bewaren heeft het programma, de tests en de gegenereerde IDL
  één gedeelde naam voor de regel.
</Note>

### state.rs

`state.rs` definieert aangepaste gegevenstypen voor accounts die het programma
aanmaakt en beheert. Het programma definieert instructies om die gegevens aan te
maken, te initialiseren en bij te werken, maar de tellergegevens worden niet in
het programma zelf opgeslagen. Ze worden opgeslagen in een aparte account met
een eigen adres.

```rust programs/my-program/src/state.rs wrap
use anchor_lang::prelude::*;

#[account]
#[derive(InitSpace)]
pub struct Counter {
    pub count: u64,
    pub authority: Pubkey,
}
```

<Note>
  **`#[account]`**

  `#[account]` vertelt Anchor dat deze struct gegevens zijn die kunnen worden
  opgeslagen in een onchain account dat eigendom is van dit programma. Anchor
  gebruikt dit om `Counter`-accounts te serialiseren, te deserialiseren en te
  valideren.

  **`InitSpace`**

  `InitSpace` laat Anchor `Counter::INIT_SPACE` berekenen: het aantal
  bytes dat nodig is voor de velden van deze struct. De 8-byte
  Anchor-accountdiscriminator wordt apart toegevoegd wanneer het account wordt
  aangemaakt.

  **`count`**

  `count` is de tellerwaarde die is opgeslagen in de accountgegevens.

  **`authority`**

  `authority` slaat het adres op dat gemachtigd is om de teller te verhogen.
  `initialize` schrijft dit adres, en `increment` vereist dat datzelfde
  adres ondertekent.
</Note>

    - `Counter::INIT_SPACE` bepaalt de grootte van het

    - `count += 1` werkt de opgeslagen tellerwaarde
      bij nadat de validatie is geslaagd.
  </div>
</Columns>

### error.rs

`error.rs` definieert de aangepaste fouten van het programma. In dit sjabloon
laten de fouten zien hoe instructie-handlers stoppen wanneer een aanroeper niet
bevoegd is om de teller bij te werken of de teller al `MAX_COUNT` heeft
bereikt.

```rust programs/my-program/src/error.rs wrap
use anchor_lang::prelude::*;

#[error_code]
pub enum ErrorCode {
    #[msg("Only the counter authority can update this counter")]
    Unauthorized,
    #[msg("Counter has reached the maximum value")]
    CounterOverflow,
}
```

<Note>
  **`#[error_code]`**

  `#[error_code]` vertelt Anchor om deze varianten om te zetten in aangepaste
  programmafouten. Clients en tests kunnen die fouten gebruiken in plaats van te
  raden op basis van ruwe foutcodes.

  **`Unauthorized`**

  `Unauthorized` wordt geretourneerd wanneer de transactieondertekenaar niet
  de authority is die is opgeslagen in het telleraccount.

  **`CounterOverflow`**

  `CounterOverflow` wordt geretourneerd wanneer verhogen de
  `MAX_COUNT`-regel van het programma zou schenden.
</Note>

<Columns cols={2}>
  <div>
    ```rust increment.rs highlight={5,9} wrap
    pub fn handle_increment(ctx: Context<Increment>) -> Result<()> {
        require_keys_eq!(
            ctx.accounts.counter.authority,
            ctx.accounts.authority.key(),
            ErrorCode::Unauthorized,
        );

            ctx.accounts.counter.count < MAX_COUNT,
            ErrorCode::CounterOverflow,
        );

        ctx.accounts.counter.count += 1;
        msg!("Hello, world! Counter is now {}", ctx.accounts.counter.count);
        Ok(())
    }
    ```
  </div>

  <div>
    `error.rs` benoemt de fouten die de instructie kan retourneren:

    - `ErrorCode::Unauthorized` wordt
      geretourneerd wanneer de ondertekenaar niet de authority is die is opgeslagen
      in het telleraccount.
    - `ErrorCode::CounterOverflow` wordt geretourneerd
      wanneer de teller al `MAX_COUNT` heeft bereikt.
  </div>
</Columns>

### instructions.rs

`instructions.rs` verbindt de instructiebestanden met de programma-crate zodat
`lib.rs` toegang heeft tot de `initialize`- en
`increment`-instructiecode. Elk instructiebestand definieert de accounts die
vereist zijn door die instructie en de handlerlogica die wordt uitgevoerd nadat
Anchor die accounts heeft gevalideerd.

```rust programs/my-program/src/instructions.rs wrap
pub mod initialize;
pub mod increment;

pub use initialize::*;
pub use increment::*;
```

<Note>
  **`pub mod initialize`**

  De `pub mod`-regels maken `src/instructions/initialize.rs` en
  `src/instructions/increment.rs` onderdeel van de programma-crate.

  **`pub use initialize`**

  De `pub use`-regels re-exporteren publieke items uit die bestanden. Daardoor
  zijn de instruction-accountstructuren en handlefuncties beschikbaar via de
  `instructions`-module.
</Note>

### initialize.rs

`initialize.rs` definieert de accounts die nodig zijn om het tegenaccount aan te
maken, en schrijft vervolgens de eerste waarden van het account. De
`#[derive(Accounts)]`-struct gebruikt Anchor
[account constraints](https://www.anchor-lang.com/docs/references/account-constraints)
om aan te geven welke accounts vereist zijn en hoe het nieuwe tegenaccount wordt
aangemaakt.

```rust programs/my-program/src/instructions/initialize.rs wrap
use anchor_lang::prelude::*;

use crate::{constants::*, state::Counter};

#[derive(Accounts)]
pub struct Initialize<'info> {
    #[account(mut)]
    pub payer: Signer<'info>,
    #[account(
        init,
        payer = payer,
        space = 8 + Counter::INIT_SPACE,
        seeds = [COUNTER_SEED],
        bump
    )]
    pub counter: Account<'info, Counter>,
    pub system_program: Program<'info, System>,
}

pub fn handle_initialize(ctx: Context<Initialize>) -> Result<()> {
    ctx.accounts.counter.count = 0;
    ctx.accounts.counter.authority = ctx.accounts.payer.key();

    let cpi_accounts = anchor_lang::system_program::Transfer {
        from: ctx.accounts.payer.to_account_info(),
        to: ctx.accounts.counter.to_account_info(),
    };
    let cpi_ctx = CpiContext::new(anchor_lang::system_program::ID, cpi_accounts);
    anchor_lang::system_program::transfer(cpi_ctx, HELLO_WORLD_LAMPORTS)?;

    msg!("Hello, world! Counter initialized");
    Ok(())
}
```

<Note>
  Dit bestand importeert de gedeelde constanten en het `Counter`-accounttype.
  De instructie gebruikt deze definities om de PDA af te leiden, het
  overdrachtsbedrag te kiezen en het account te alloceren met de juiste
  gegevensgrootte.

  **`derive(Accounts)`**

  `Initialize` is de accountcontext voor de `initialize`-instructie. Elk
  veld in de struct vertegenwoordigt een afzonderlijk account dat moet worden
  meegestuurd wanneer de instructie wordt aangeroepen. Anchor gebruikt de struct
  om die inkomende accounts te valideren voordat de handler wordt uitgevoerd.

  **`#[account(mut)]`**

  `#[account(mut)]` vertelt Anchor dat het betalersaccount schrijfbaar moet
  zijn. Dit is vereist omdat zowel het aanmaken van accounts als de transfer CPI
  lamports van de betaler aftrekken.

  **`Signer<'info>`**

  `Signer<'info>` vertelt Anchor dat de betaler de transactie moet
  ondertekenen.

  **`#[account(`**

  Het `#[account(...)]`-blok vertelt Anchor hoe het teileraccount aangemaakt
  en gevalideerd moet worden voordat de handler wordt uitgevoerd.

  **`init`**

  `init` vertelt Anchor om het `counter` account aan te maken voordat de
  handler wordt uitgevoerd. Het nieuwe account is eigendom van dit programma,
  zodat dit programma `Counter` gegevens erin kan opslaan.

  **`payer = payer`**

  `payer = payer` specificeert het `payer` account als betaler voor het
  aanmaken van het nieuwe counter account.

  **`space = 8 + Counter::INIT_SPACE`**

  `space = 8 + Counter::INIT_SPACE` reserveert bytes voor Anchor's account
  discriminator plus de `Counter` velden uit `state.rs`. De discriminator
  helpt Anchor bevestigen dat het account het verwachte type opslaat voordat het
  wordt gelezen.

  **`seeds = [COUNTER_SEED]`**

  `seeds = [COUNTER_SEED]` bepaalt dat het adres van het counter account de
  PDA moet zijn die is afgeleid van deze seed en het programma-ID. Met één vaste
  seed is er één counter PDA voor dit programma. Om afzonderlijke tellers aan te
  maken in een echt programma, zou je gewoonlijk een andere seed toevoegen, zoals
  het adres van een gebruiker.

  **`bump`**

  `bump` vertelt Anchor om de PDA bump te vinden en te valideren. Dit is de
  extra byte die het afgeleide adres geldig maakt als PDA.

  **`Account<'info, Counter>`**

  `Account<'info, Counter>` vertelt Anchor om de accountgegevens te behandelen
  als het `Counter` type uit `state.rs`. Anchor controleert ook of het account
  eigendom is van dit programma.

  **`Program<'info, System>`**

  `Program<'info, System>` vereist dat de aanroeper het System Program
  aanlevert. Anchor gebruikt dit voor de `init` account aanmaakbeperking. De
  transfer CPI van de handler roept ook het System Program aan.

  **`handle_initialize`**

  De handler wordt uitgevoerd nadat Anchor de accounts heeft gevalideerd en het
  counter account heeft aangemaakt, zodat de initiële gegevens van het account
  veilig kunnen worden geschreven.

  **`counter.count = 0`**

  Stelt het `count` veld in het counter account in op `0`.

  **`counter.authority = ctx.accounts.payer.key()`**

  Stelt het `authority` veld in het counter account in op het adres van de
  betaler.

  **`system_program::Transfer`**

  Dit zijn de accounts die worden doorgegeven aan de System Program
  transfer-instructie. Deze transfer CPI is alleen opgenomen om te demonstreren
  hoe een CPI accounts doorgeeft aan een ander programma.

  **`CpiContext::new`**

  `CpiContext` verpakt het doelprogramma en de vereiste accounts voor een
  Cross Program Invocation. Het aanmaken van de context bereidt de CPI voor door
  het programma dat je wilt aanroepen te koppelen aan de accounts die dat
  programma verwacht.

  **`system_program::transfer`**

  Deze CPI roept de transfer-instructie van het System Program aan en verplaatst
  `HELLO_WORLD_LAMPORTS` van de betaler naar het telleraccount.

  **`msg!`**

  `msg!` schrijft een bericht naar de programmalogboeken wanneer het programma
  wordt aangeroepen.
</Note>

<Steps>
  <Step title="Account Context">
    De `Initialize`-struct definieert de accounts die moeten worden meegestuurd
    wanneer een gebruiker de `initialize`-instructie aanroept. Anchor
    controleert deze accounts voordat de handler wordt uitgevoerd.

    ```rust initialize.rs focus={1-2}
    #[derive(Accounts)]
    pub struct Initialize<'info> {
        #[account(mut)]
        pub payer: Signer<'info>,
        #[account(
            init,
            payer = payer,
            space = 8 + Counter::INIT_SPACE,
            seeds = [COUNTER_SEED],
            bump
        )]
        pub counter: Account<'info, Counter>,
        pub system_program: Program<'info, System>,
    }
    ```
  </Step>

  <Step title="Payer Account">
    Het `payer`-account betaalt voor het aanmaken van het tegenaccount. Het
    `Signer<'info>`-type betekent dat de betaler de transactie moet

### increment.rs

`increment.rs` definieert de accounts die vereist zijn om een bestaand
telleraccount bij te werken. De handler controleert of de ondertekenaar de
opgeslagen autoriteit is, controleert of het aantal de opgegeven `MAX_COUNT`
niet heeft bereikt, en verhoogt vervolgens de teller.

```rust programs/my-program/src/instructions/increment.rs wrap
use anchor_lang::prelude::*;

use crate::{constants::*, error::ErrorCode, state::Counter};

#[derive(Accounts)]
pub struct Increment<'info> {
    #[account(
        mut,
        seeds = [COUNTER_SEED],
        bump
    )]
    pub counter: Account<'info, Counter>,
    pub authority: Signer<'info>,
}

pub fn handle_increment(ctx: Context<Increment>) -> Result<()> {
    require_keys_eq!(
        ctx.accounts.counter.authority,
        ctx.accounts.authority.key(),
        ErrorCode::Unauthorized,
    );
    require!(
        ctx.accounts.counter.count < MAX_COUNT,
        ErrorCode::CounterOverflow,
    );

    ctx.accounts.counter.count += 1;
    msg!("Hello, world! Counter is now {}", ctx.accounts.counter.count);
    Ok(())
}
```

<Note>
  **`derive(Accounts)`**

  `Increment` is de accountcontext voor de `increment` instructie. Anchor
  gebruikt het om het muteerbare telleraccount en de vereiste ondertekenaar te
  valideren.

  **`mut`**

  `mut` vertelt Anchor dat het teller-account schrijfbaar moet zijn omdat de
  handler de opgeslagen `count`-waarde bijwerkt.

  **`seeds = [COUNTER_SEED]`**

  `seeds = [COUNTER_SEED]` verifieert dat het opgegeven teller-account de PDA
  is die is afgeleid van deze seed en het programma-ID.

  **`bump`**

  `bump` vertelt Anchor om de PDA-bump voor het teller-account te vinden en te
  valideren.

  **`Account<'info, Counter>`**

  `Account<'info, Counter>` vertelt Anchor om de accountgegevens te
  deserialiseren als het type `Counter` van `state.rs`. Anchor controleert ook
  of het account eigendom is van dit programma.

  **`Signer`**

  `Signer` vereist de handtekening van de autoriteit. De handler vergelijkt
  vervolgens het adres van deze ondertekenaar met de autoriteit die is opgeslagen
  in het teller-account.

  **`handle_increment`**

  De handler wordt uitgevoerd nadat Anchor de accountlijst heeft gevalideerd, het
  eigendom heeft gecontroleerd en het teller-account heeft gedeserialiseerd.

  **`require_keys_eq!`**

  `require_keys_eq!` vergelijkt twee publieke sleutels en stopt de instructie
  tenzij het adres van de ondertekenaar overeenkomt met de autoriteit die is
  opgeslagen in het teller-account. Dit is de autorisatieregel op applicatieniveau
  van de template.

  **`require!`**

  `require!` controleert een booleaanse regel en stopt de instructie met
  `CounterOverflow` als de teller al `MAX_COUNT` heeft bereikt. Deze
  templateregel demonstreert aangepaste fouten en het mislukken vóór mutatie.

  **`count += 1`**

  Pas nadat beide controles zijn geslaagd, werkt de handler de
  teller-accountgegevens bij. Als een van de controles mislukt, mislukt de
  transactie en wordt het account niet gewijzigd.

  **`msg!`**

  `msg!` schrijft een bericht naar de programmalogboeken wanneer het programma
  wordt aangeroepen.
</Note>

```rust programs/my-program/tests/test_initialize.rs wrap
use {
    anchor_lang::{
        prelude::Pubkey,
        solana_program::{instruction::Instruction, system_program},
        AccountDeserialize, InstructionData, ToAccountMetas,
    },
    litesvm::LiteSVM,
    solana_keypair::Keypair,
    solana_message::{Message, VersionedMessage},
    solana_signer::Signer,
    solana_transaction::versioned::VersionedTransaction,
};

#[test]
fn test_initialize() {
    let program_id = my_program::id();
    let payer = Keypair::new();
    let counter = Pubkey::find_program_address(
        &[my_program::constants::COUNTER_SEED],
        &program_id,
    )
    .0;
    let mut svm = LiteSVM::new();
    let bytes = include_bytes!(concat!(
        env!("CARGO_TARGET_TMPDIR"),
        "/../deploy/my_program.so"
    ));
    svm.add_program(program_id, bytes).unwrap();
    svm.airdrop(&payer.pubkey(), 1_000_000_000).unwrap();

    let instruction = Instruction::new_with_bytes(
        program_id,
        &my_program::instruction::Initialize {}.data(),
        my_program::accounts::Initialize {
            payer: payer.pubkey(),
            counter,
            system_program: system_program::ID,
        }
        .to_account_metas(None),
    );

    let blockhash = svm.latest_blockhash();
    let msg = Message::new_with_blockhash(&[instruction], Some(&payer.pubkey()), &blockhash);
    let tx = VersionedTransaction::try_new(VersionedMessage::Legacy(msg), &[&payer]).unwrap();

    let res = svm.send_transaction(tx);
    assert!(res.is_ok());

    let counter_account = svm.get_account(&counter).unwrap();
    let mut data: &[u8] = &counter_account.data;
    let counter_state = my_program::state::Counter::try_deserialize(&mut data).unwrap();
    assert_eq!(counter_state.count, 0);
    assert_eq!(counter_state.authority, payer.pubkey());

    let instruction = Instruction::new_with_bytes(
        program_id,
        &my_program::instruction::Increment {}.data(),
        my_program::accounts::Increment {
            counter,
            authority: payer.pubkey(),
        }
        .to_account_metas(None),
    );

    let blockhash = svm.latest_blockhash();
    let msg = Message::new_with_blockhash(&[instruction], Some(&payer.pubkey()), &blockhash);
    let tx = VersionedTransaction::try_new(VersionedMessage::Legacy(msg), &[&payer]).unwrap();

    let res = svm.send_transaction(tx);
    assert!(res.is_ok());

    let counter_account = svm.get_account(&counter).unwrap();
    let mut data: &[u8] = &counter_account.data;
    let counter_state = my_program::state::Counter::try_deserialize(&mut data).unwrap();
    assert_eq!(counter_state.count, 1);
    assert_eq!(counter_state.authority, payer.pubkey());
}
```

<Note>
  **`litesvm::LiteSVM`**

  `LiteSVM` is een in-process Solana VM voor tests. Het stelt de test in staat
  het gecompileerde programma te registreren, accounts aan te maken, transacties
  te verzenden en de accountstatus te inspecteren zonder een validator-proces te
  starten.

  **`let program_id`**

  De test haalt het programmaadres op uit de `declare_id!` waarde via
  `my_program::id()` en maakt een nieuw payer keypair aan voor de
  testtransactie.

  **`Pubkey::find_program_address`**

  Het counteradres wordt afgeleid van dezelfde `COUNTER_SEED` die door het
  programma wordt gebruikt. Dit zorgt ervoor dat de test de PDA target die
  `initialize.rs` verwacht.

  **`include_bytes!`**

  `include_bytes!` leest het gecompileerde `my_program.so`-bestand dat door de
  build is gegenereerd. Die bytes zijn de uitvoerbare programmacode die LiteSVM in
  de test zal uitvoeren.

  **`svm.add_program`**

  `svm.add_program` registreert de gecompileerde programmabytes op het
  programmaadres in LiteSVM. De airdrop geeft de betaler genoeg lokale SOL om de
  transactie en het aanmaken van het account te betalen.

  **`let instruction`**

  `Instruction::new_with_bytes` maakt een instructie aan om het programma aan
  te roepen. Het bevat de programma-ID, instruction data en instructieaccounts.

  **`svm.latest_blockhash`**

  Elke Solana-transactie heeft een recente blockhash nodig. In deze test levert
  LiteSVM een blockhash voor gebruik bij de transactie.

  **`Message::new_with_blockhash`**

  Het bericht bevat de instructie, de vergoedingsbetaler en de blockhash. Dit is
  de transactiedata die ondertekend zal worden.

  **`VersionedTransaction::try_new`**

  `VersionedTransaction::try_new` ondertekent het bericht met de payer
  keypair. De betaler ondertekent omdat hij de transactievergoeding betaalt en het
  nieuwe counter-account financiert.

  **`svm.send_transaction`**

  `svm.send_transaction` voert de transactie uit in LiteSVM.

  **`svm.get_account`**

  Nadat de transactie is uitgevoerd, leest de test het counteraccount rechtstreeks
  uit LiteSVM om de accountdata te inspecteren.

  **`Counter::try_deserialize`**

  Het counteraccount slaat geserialiseerde data op. `Counter::try_deserialize`
  controleert de accountdiscriminator van Anchor en zet de accountdata terug om
  naar het `Counter`-type uit `state.rs`.

  **`assert_eq!(counter_state.count, 0)`**

  Nadat `initialize` is geslaagd, deserialiseert de test het counteraccount en
  controleert of de begintoestand overeenkomt met wat `handle_initialize`
  heeft geschreven.

  **`assert_eq!(counter_state.count, 1)`**

  Nadat `increment` is geslaagd, moet hetzelfde counteraccount `count`
  hebben ingesteld op `1` terwijl de authority hetzelfde blijft.
</Note>

<Note>
  **`skip_local_validator`**

  `skip_local_validator = true` vertelt Anchor om geen validator te starten voor
  `anchor test`. De Rust-test gebruikt in plaats daarvan LiteSVM.

  **`programs.localnet`**

  `[programs.localnet]` koppelt de naam van de Rust-crate aan het programmaadres
  dat wordt gebruikt voor lokale builds en tests.

  **`provider`**

  `[provider]` stelt het standaardcluster en de standaardwallet in voor opdrachten
  zoals `anchor deploy`.

  **`scripts`**

  `[scripts]` bepaalt wat `anchor test` uitvoert. In dit sjabloon voert
  `anchor test` `cargo test` uit.
</Note>
